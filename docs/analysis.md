# AI 分析 · 数据处理 · 可视化

> 本文是采析绘文档的一部分，返回总览见 [README.md](../README.md)。

AI 分析（双提供方 / 情感 / 倾向 / NER / 关键词等）、通用数据处理算子与事件研究套件、以及可视化图表与 LaTeX 出图的完整说明。

## AI 分析
- **双 AI 提供方**：本地 Ollama 或 OpenRouter API（免费模型列表一键拉取、连接测试），
  模型选择、批量保存行数、截断长度均可在 AI 面板配置；OpenRouter Key 仅存浏览器 localStorage，不落服务器
- **逐节点模型**：AI 面板选的是整轮运行的默认模型；每个用本地 Ollama 的分析节点（清洗 / 情感 / 倾向 / NER）
  还可在自己的面板单独挑一个模型，不必与其他节点一致。默认「跟随全局」即沿用运行级模型；OpenRouter 运行不提供此下拉
- **为什么默认主推微调 BERT（而非通用大模型）**：见 [`docs/why_finetuned_bert.md`](why_finetuned_bert.md)——质量、速度、成本、确定性四维对比，含本机实测的 accuracy/F1
- **情感分析（三模式）**：LLM 逐行深度分析、传统 ML（sklearn TF-IDF + 逻辑回归）批量推理，或**微调 BERT**；
  情绪标签集现按 **SMP2020-EWECT 六类**（`Anger`/`Fear`/`Joy`/`Neutral`/`Sadness`/`Surprise`，此前是少了 `Surprise` 的五类）。
  - ML 通路现统一走 jieba 词 + **那份停用词表去噪** + `class_weight=balanced` 逻辑回归（子线性 TF）；`build_tfidf_pipeline(char_features=True)` 可再并入字 n-gram（字+词 FeatureUnion）。
    这把「文本统计统一走一份停用词表」的同一份表也接进了 ML 特征侧（此前 ML 管线 `stop_words=None`，是一个真实的准确率缺口）。`/api/analysis/train` 的自训与 `ml_train/` 的重训共用这一管线。
  - `bert`（**默认**；未点名模型时自动取注册表里 emotion op 的默认模型）：填一个本机 HuggingFace 目录路径即可整列**分批推理**（有显卡自动走显卡，
    `batch_size`、截断长度 `max_length`（默认 512，长文可调大以免截掉尾部）均可调）；`pipeline('text-classification')` 直接读模型的 `id2label`，**换任何一套六类情绪模型都不用改分析器**。
    缺 `torch`/`transformers` 或无注册模型可解析时，执行器**自动降级到 `ml` 并打印本次实际用的模式**（绝不静默把 ml 结论冒充成 bert）；分析器被直接当 bert 调用仍按名拒绝；读不出的行留空，不臆造 `Neutral`。
    产出模型用 `ml_train/scripts/train_emotion_bert.py` 在 `ml_train/datasets/ewect_smp2020/train/usual_train.txt`（通用微博 27,766 条）上微调 `hfl/chinese-roberta-wwm-ext`，
    写到 `ml_train/models/emotion_ewect_six/`、在节点「已注册模型」下拉按名选（或填相对路径 `ml_train/models/emotion_ewect_six`）即可。**本机实测（2026-10-06）**：三 epoch、留出切片 **accuracy=0.811 / macro-F1=0.792**；
    官方未见过的验证集（2000 条）**accuracy=0.792 / macro-F1=0.758**（六类不均衡，`Surprise`/`Fear` 最稀，故 macro-F1 低于二分类的情感极性）。
- **情感极性（四模式）**：输出 `sentiment`（`positive`/`negative`/`neutral`）与 `score`（0–1 正极性概率）两列。
  它是**独立的一个操作**而不是「情感分析」的第三个开关：SnowNLP 与中文情感 BERT 回答的是"这段话偏正面吗"，
  给不出 Anger/Fear/Joy/Neutral/Sadness/Surprise 六分类、也给不出倾向性的六类传播标签，硬塞进去只能靠猜。
  - `snownlp`（bert 跑不动时的默认回退，无需模型、无需 GPU、不掏任何 API）：随包附带的朴素贝叶斯极性模型；
    另有「判定为正面的下限 / 判定为负面的上限」两个可调档位，落在两者之间记为中性。
    **实测要说清**：SnowNLP 是在购物评论上训出来的，对客观陈述明显偏负（"会议定于周三举行"实测 0.24），
    所以阈值是节点参数而不是写死的 0.5，`score` 列始终保留原始概率，判错方向时重划档位即可。
  - `ml`：与情感/倾向同一条「训练模型」通路，从表里已标注的行拟合 `data/models/sentiment.pkl`
  - `llm`：逐行走大模型，与情感/倾向共用批量、缓存与断点检查点
  - `bert`：**默认**（未点名模型时自动取注册表 sentiment op 的默认模型）。本机跑不动 bert（缺 `torch`/`transformers`，或无注册模型可解析）时，
    节点执行器**自动降级到 `snownlp`，并在控制台打印本次实际用了哪种**——绝不静默把 SnowNLP 的结论冒充成 bert。
    分析器**本身**被直接当 bert 调用仍按名拒绝（纵深防御）；勾 ≥2 模型的多模型对比不降级、维持按名拒绝。
    **注**：这一条通路在本仓库**从未真跑过**（开发机没有对应模型），不要把它当作已验证功能
- **倾向性分析（三模式）**：LLM 逐行、传统 ML（sklearn TF-IDF + 逻辑回归）批量，或**微调 BERT**（六类传播立场标签，与情感/情绪共用同一条 `bert` 后端与分批推理）
  - `bert`（**默认**；未点名模型时自动取注册表里 tendency op 的默认模型，缺栈/无模型时执行器降级到 `ml` 并打印）：倾向**没有公开语料**，所以模型来自 **LLM 蒸馏**——`ml_train/scripts/distill_tendency_labels.py` 用节点自己的 `llm` 通路（qwen3.5:4b 在 `ml_train/datasets/weibo_clean_265k.csv` 的 26 万条真实微博上逐条打标签，只保留干净解析出的六类、按类封顶去偏），产出 `ml_train/datasets/tendency_distilled.csv`（两轮蒸馏累计约 7,720 条）；再由 `ml_train/scripts/train_tendency_bert_v1.py` 微调 `hfl/chinese-roberta-wwm-ext` 到 `ml_train/models/tendency_stance_v1/`。`pipeline('text-classification')` 直接读 `id2label`（六类标签含空格/斜杠，原样匹配），**换任何六类立场模型都不用改分析器**。缺 `torch`/`transformers` 或模型名留空 / 无法解析时，执行器**自动降级到 `ml` 并打印实际模式**（分析器被直接当 bert 调用仍按名拒绝；多模型对比不降级），模型回了不认识的标签时该行留空、**不臆造 `Objective Statement`**。
    **本机实测（2026-10-06）**：在约 7,720 条上微调、三 epoch、5% 留出 **accuracy=0.731 / macro-F1=0.681**（较首轮 3,935 条的 0.572 明显提升，主要靠稀有类样本变多：`Controversy/Reflection` 106→364、`Criticism`/`Advocacy` 各约 1,300）。仍如实说：`Controversy` 是最稀的一类（真实微博少有人作多视角讨论），它与讽刺(`Satire`)仍是最弱两格——端到端里「呵呵，某些人倒是挺会演戏的」被误判为 `Praise`（置信仅 0.46）。曾试把各类下采样到最少类（`--balance`，每类 364）以求均衡，macro-F1 反降到 0.561（丢掉约 5,500 条有效数据），故保留全量训练。要更高可加大 `--n` 续蒸馏（脚本自动跳过已标注文本）。
- **微调模型注册表（显示名）**：`bert` 模式的「模型名」不再只能手敲路径。运维在 `data/model_registry.json` 里
  登记 `{name, path, desc}`（路径用**相对仓库根**的 `ml_train/models/…`，换机/换检出目录不失效，便于上传云盘共享），
  后端 `GET /api/models` 送出，情绪/倾向/情感节点的 `bert` 面板就列出**已注册模型复选框**，按**显示名**（如
  **「网暴模型」**——基于网络暴力事件真实语料微调的倾向六分类，产出在 `ml_train/models/tendency_stance_v2_cyberbully/`）勾选，
  勾选写入 `bert_models`（逗号分隔的**路径**，运行按路径加载，名字只给人读），下面仍保留原始路径框填未注册模型；二者只 `bert_models` 优先。
  文件缺失或损坏时复选框整组消失、路径框仍在——**注册表是可选加速器，不是运行前提**。
- **多模型对比**：`bert` 模式勾选 **≥2 个模型**（`bert_models`）时，该分析节点对同一文本列**逐模型各跑一遍**，输出一张**长表**：
  原表每行 × 每模型一行，新增 **`模型`**（显示名）与 **`原行`**（跨模型对齐同一条文本）两列，标签/置信列沿用各操作现名
  （emotion/tendency/sentiment + confidence/tendency_confidence/score）。**只勾 1 个模型时保持原样**（就地加两列、不拉长表），老画布不受影响。
  选择按去重排序存，点选顺序不改变节点指纹；`bert_models` 是选数据的输入，进指纹、不进 `_VOLATILE_PARAMS`。
  对比可视化：**模型×标签分布**用现成 **热力图**（`x_field=模型`、`y_field=标签列`）即可；**模型间一致率**新增图表 **`model_agreement`**，
  按 `模型`/`原行`/标签列算两两模型判定相同的百分比、画 model×model 方阵热力图（仅 echarts，无 LaTeX 版本）。缺列按名拒绝，不足 2 模型也拒绝而非画 1×1 空图。
- **语义数据清洗**：自动过滤广告、无关内容与低质量数据（LLM 判定）
- **关键词提取**：TF-IDF / TextRank（依赖 jieba）
- **文本聚类**：K-Means / DBSCAN 自动发现文本分组
- **命名实体识别（双模式）**：正则规则（人名/机构/地名/日期，零依赖），或改用大模型抽取；可只保留四类中的某几类
- **异常检测**：Isolation Forest 自动标记数值异常行（少于 5 行、或没有可用数值列时**明确报错**，
  不会给每行填 0 分冒充"已检查、无异常"）
- **相关性分析**：Pearson / Spearman / Kendall 相关系数矩阵（点名的列全是文本时报错并点名该列；
  混选时只算可用列并在控制台说明跳过了哪些）
- **显著性检验（跨组比较）**：拿**一个类别列当分组、一个数值列当取值**，检验各组之间这个数值有没有
  统计意义上的差异。四种方法两两配对（参数 / 非参数）：
  - `ttest` → **Welch's t**（`equal_var=False`），**恰好两组**；面板与统计标签都写 Welch，不冒充 Student's t——
    情感分按阶段分组时两组方差往往不等，Welch 才是站得住的那个。
  - `anova` → 单因素方差分析，**≥2 组**（统计量 F）。
  - `mannwhitney` → Mann-Whitney U，两组，t 的秩检验替身（情感分非正态时更稳）。
  - `kruskal` → Kruskal-Wallis H，≥2 组，ANOVA 的秩检验替身。
  - p 值一律取 **scipy 的真实分布 CDF**（t / F / 秩检验），不用 numpy 近似；scipy 因此从「随 scikit-learn
    传递引入」升为**直接声明依赖**（`requirements.txt`）。
  - 输出**一行**整洁结果，列名固定为下游图/预览的输入合同：`method, group_column, value_column,
    statistic, p_value, n_groups, group_sizes, significant_005`（后者按**固定 α=0.05** 判；要别的阈值就拿
    `p_value` 自己比，这一版不开 alpha 参数以免扩面）。`group_sizes` 说明各组实际用了多少行——**先丢掉**
    空分组标签与转不成数值的行，报的是「测了多少」，不是原始行数。
  - **能算才算**：缺列、列名不在表里、数值列整列不可转数、方法要的组数不对（如给 ttest 却三组，句里点名
    「试 ANOVA/Kruskal-Wallis」）、方差为零等退化情形一律**按名报错、绝不回一张空表**让节点绿着往下走。
- **模型训练**：从已有 LLM 标注数据一键训练传统 ML 模型，后续推理无需 Ollama

## 数据处理
- **通用数据分析节点**：去空值、去重、条件筛选、重命名列、类型转换、排序、采样、分组聚合、
  表关联、列计算、数值分箱等确定性清洗，可独立于爬虫直接处理任意表格数据；
  这些算子的细节参数现在都能从面板设置：**去空值**可选「任一列为空即删」或「全部列为空才删」，
  **填空值**可选用给定值填充或前向/后向填充（ffill/bfill），
  **数值分箱**可填等宽箱数（如 `4`）或直接给边界（如 `0, 60, 80, 100`）并配箱标签；
  算子被拒（写了不存在的算子、给文本列求和、比较条件填非数字）时**节点判失败并写明原因**，
  不再回一张空表让运行看起来成功、导出只剩表头的文件
  ——此前这三处参数在面板与后端之间被丢弃，选了也不生效
- **分词节点**：jieba 对任意文本列分词，输出词频对，供导出或词云使用
- **中文社交文本处理**（针对微博这类短文本、水军刷屏的语料）：
  - **清洗节点有两种模式**。`regex` 不用模型：剥掉转发链（`你的评论//@某人:原文` 只留你自己的那段）、
    `@提及`、`#话题#` 标记、链接与 `O网页链接`/`展开c` 占位符、`[表情]` 代码，整行只剩这些东西的判为
    「删除」。它**不判断主题相关性**——那是 `llm` 模式的职责，若把它当成了主题过滤会得出错误结论。
    源文本列原样保留，清洗结果写在 `cleaned_text` 旁边。留空=默认走 `llm`，与加这个选择器之前完全一致
  - **情感极性节点支持 BERT**：填一个本机模型名即可整列**分批推理**（有显卡自动走显卡，`batch_size` 可调，
    默认 32），比逐行调用快一到两个数量级；模型给出的正/负标签按概率签名后套用同一组正负阈值。
    加载用 `pipeline('sentiment-analysis', model=路径)`、`_signed_polarity` 只认 `positive`/`negative` 子串，故
    **换任何 HF 情感模型都不用改分析器**。要"非常高"的准确率：用 `ml_train/scripts/train_sentiment_bert.py` 在 `ml_train/datasets/weibo_senti_100k`
    （正/负；`--with-clean` 可再并入 `ml_train/datasets/weibo_clean_265k` 的 喜悦→正、愤怒/厌恶/低落→负）上微调一个中文 base BERT
    （默认 `hfl/chinese-roberta-wwm-ext`，fp16 + batch 16 在 8GB 显存即可），产出本地 HF 目录 `ml_train/models/sentiment_weibosenti_bin/`、
    在节点「已注册模型」下拉按名选（或填相对路径 `ml_train/models/sentiment_weibosenti_bin`）即可。
    **本机实测（2026-10-06）**：在 `ml_train/datasets/weibo_senti_100k` 上微调 3 epoch、5% 留出集，**accuracy = macro-F1 = 0.9785**
    （三个 epoch 分别 0.9782 / 0.9783 / 0.9785，取最优），RTX 4060 8GB、fp16+batch16 全程约 26 分钟、峰值显存 3.8GB；
    作为对照，词袋 `ml` 档同一留出集约 **0.78**。`sentiment.py` 的 bert 通路本身经真实节点路径验证：有显卡时 `bert_device`
    返回 `0` 自动走 GPU。
  - **中性从哪来（用 bert 模式前必读）**：这条通路的模型是**正 / 负二分类**头，`_signed_polarity` 把正类概率签成一个 0–1
    的极性分写进 `score`；模型**从不直接产出 `neutral`**（训练源 `ml_train/datasets/weibo_senti_100k` 与 `ml_train/datasets/weibo_clean_265k` 都只有正/负标注，
    也不要臆造 neutral 行去训练）。第三列 `sentiment` 的 `neutral` 完全由 `label_for_score` 用**正负阈值**卡出来：
    默认「判定为正面的下限」0.6、「判定为负面的上限」0.4，`score ≥ 0.6` 判正面、`≤ 0.4` 判负面、之间记中性（边界含等号）。
    所以一段温吞文本算不算中性取决于这两个阈值、而非模型「看懂了中性」——实测「这剧情也就一般吧，谈不上喜欢也不讨厌」
    被给出 0.86 正极性，即二分类头对模糊文本本就偏向一边。想**扩大中性区间**就调高正面下限、调低负面上限（反之收窄）。
    `torch`/`transformers` 在 `requirements-optional`；bert 模式缺依赖或模型跑不动时，节点执行器**降级到 `snownlp`
    并打印实际用的模式**（绝不静默把 A 模型结论写进 B 模型声称的列；分析器被直接当 bert 调用仍按名拒绝、多模型对比不降级）；
    `pipeline` 推理不需要 `accelerate`，它只被 gitignore 的训练脚本 `train_bert.py` 用到。
  - **关键词节点**新增「基于自己语料的 TF-IDF」：jieba 内置 IDF 来自新闻语料，微博口语词会因此排错位；
    这一档直接用你自己的表拟合 IDF。另可填**词性过滤**（如 `n,vn,v,a`），去关键词表里的「转发/哈哈/回复」
  - **网暴言论识别**（算法处理节点的新操作 `aggression`）：论文的研究对象是**暴力言论**而不是负面情绪，
    此前项目里没有任何东西量过它——"有多冷"被当成"有多骂"，而这两件事恰恰是论文治理章节要区分的。
    四类特征：谩骂、人身攻击、隐私披露（手机号/身份证/住址/人肉开盒）、造谣转述，输出三列
    `aggression`(none/mild/severe)、`aggression_score`、`aggression_hits`（命中了哪个家族的哪些词，
    让结论可核对而不是信一个数）。默认走**词库模式**：无需模型、不花钱、同一张表两次跑出同一张表；
    它明说自己是**召回器不是判定器**——换个说法的攻击看不见，而这一点在这里无法度量，所以词表就放在
    代码里让它的不足可见。两点刻意的取值：隐私披露权重高于谩骂（那是把线上辱骂变成现实伤害的一步）；
    「造谣/辟谣」这类辟谣用词**故意不算**暴力（它们更多出现在指责别人造谣的评论里，算进去就把一条纠错
    放进了论文的谣言曲线）。要覆盖委婉语与谐音变体就切 `llm` 模式，它复用逐行 Runner 的全套机制
    （批量、缓存、取消、`未处理`），本轮无模型，只由注入的 stub 客户端验证。
  - **事件研究套件**（复刻"舆情生命周期 + 主题演化 + 情感演化图谱"这类研究，如《基于情感演化图谱的
    网络暴力事件防范与治理研究》的表 1）：
    **提取时间维度**从时间列派生 `日期`/小时/星期等（解析不了的相对时间标签留空，不猜年份）；
    **按时间划分阶段**用「边界+阶段名」把行打上生命周期标签（边界左闭右开，按自然日比较）；
    它还能多写一列**阶段序号**（数字，首阶段=1）——这不是冗余：阶段列是有序 categorical，而每过一个节点
    表格都会被 `pd.DataFrame(records)` 重建回普通字符串，中文阶段名按码点排序会把「二次爆发期」排到
    「发酵期」前面，于是一张按阶段分组的表就把生命周期读反了却看着完整。**只有数字能跨过那道边界**；
    情感演化曲线与分组聚合都接受「按哪一列排行」，留空=按组名排（日期这种写法本来就自序），填了序号列
    就按生命周期排，某个阶段一行序号都没有则点名拒绝而不是补到最后；分组聚合还可加**附加聚合**
    （`列:函数`，逗号分隔的 `agg_metrics`）——主聚合列名保持不变（老图表读的列不受影响），每个附加项
    各出一列 `列_函数`；附加列缺列名同样点名拒绝；
    **按发文量建议阶段边界**读每日发帖曲线的峰谷，打印出可直接粘进上一步的 `edges`/`labels`——
    它只是建议，不改任何一行，官方通报那类日期得你自己补。一个「峰」是**连续若干天都 ≥ 比率×日常中位数**的一段，
    两段之间只要平滑后的曲线没回落到日常水平就并成一个峰（相邻两个高峰日因此不会被当成两段，
    也不会像早前那样把「一个肩上的日子」判成峰、结果整座山消失——刘学州 76 天的曲线就是这么被读成「只有一段」的）；
    短于「最短窗口」的窗口并入行数更多的邻居并**警告说明**（冲上来一天的不算一个阶段，留空=3 天）；
    **主题模型**（以及下面的距离图 / 显著词 / 分阶段）**默认 `method`=`auto`**：装了 sentence-transformers
    等可选包就用句向量 + KMeans（默认 `BAAI/bge-small-zh-v1.5`，本机实测主题相干性优于 LDA），没装就自动走
    LDA——两者都会在控制台**写明实际用了哪种**，绝不把 auto 出的 LDA 结果冒充成 embedding。想强制一种就显式选
    `method`=`embedding`（没编码器时**按名拒绝、绝不静默替换**）或 `lda`。可选依赖见 `requirements-optional.txt`；
    LDA 用 scikit-learn、不额外装依赖，困惑度与每个主题的词照常打进控制台。此前靠「不写方法=LDA」的**已保存画布
    已显式钉成 `topic_method`=`lda`**，所以改默认不动它们的老结果。实测对比脚本见 `ml_train/scripts/topic_bakeoff.py`。
    **同一套 `method` 选项（`auto` / `embedding` / `lda`）现在覆盖全部主题步骤**——`主题模型`、`分阶段 LDA`、`主题距离图数据`、
    `各主题显著词数据` 都接受它，且**输出列名逐字不变**（表还是同一张，图的 `pc1/pc2/prevalence_pct` 与
    `term/overall_freq/within_freq` 契约照旧），所以可在同一张画布就地做 LDA↔embedding 的 A/B，下游一行不用改；
    embedding 复用**同一份 CountVectorizer 词矩阵**，只把「文档→主题」的指派从 LDA 后验换成 KMeans 簇。注意**困惑度是
    LDA 的量**，走 embedding 时该字段如实留空（nan），不伪造一个看似可与 LDA 比大小的数。
    **分阶段 LDA 主题模型**先按阶段列切分语料、逐阶段建模，输出「每(阶段,主题)一行」的宽表：
    `阶段 / 主题编号(TopicⅠ-1…) / 特征词 / 权重 / 该主题帖子数 / 困惑度 / 代表文本`。整库跑一次模型出不来这张表——
    混合模型会把主题让给文本最多的阶段。每阶段主题数可统一填一个数，也可逐阶段列举（`5,6,4,4,4`）；特征词默认取
    该主题文本的 TF-IDF（论文的说法），也可切回 LDA 主题-词权重（单字词只有后者留得住）；阶段先后要么来自同一
    条流水线里的阶段列，要么由你指定一个时间列，两者都没有就拒绝而不是按中文字典序猜；
    **主题概括（模型）**对每个主题问一次模型，把「不超过 15 字」的概括写进 `主题概括` 列。默认任一主题失败就让
    节点失败（可切「留空继续」），没配模型则一开始就拒绝——不会静默交出一列空的概括；答案**存进 runs.db 的 llm_cache**，
    缓存键就是那条提示词，所以同一张表重跑不再重复付费（日志说「新问 {asked} 次、重放 {replayed} 次」），而换了模型、
    换了界面语言或改了特征词/样本帖列都会自己重问——能跨过提问本身存活的答案就是错的；
    **情感演化曲线**按任意分组列算出积极/中性/消极的数量与占比、情感指数 `(积极−消极)/总数 ∈ [-1,1]`，
    再加**热度** `volume_pct`（该期占全文量比例）与可选的**情感强度** `intensity = |score−0.5|×2` 的均值
    （分数列来自极性节点，没打分的时段留空并点名说明，不写成中性）。
    **主题距离图（数据）**与**各主题显著词（数据）**是 pyLDAvis 那张图的「数据面」，不装 pyLDAvis 也不装 gensim：
    前者一行一主题，给 `topic / pc1 / pc2 / prevalence_pct / doc_n / feature_words`——坐标是主题两两词分布的
    **Jensen-Shannon 散度**经**经典 MDS**（特征分解，非迭代）降到二维，符号固定所以同一张表永远画出同一张图；
    占比取模型自己的文档质量 `doc_topic.sum(axis=0)`，与「分阶段 LDA」里 argmax 计数的 `doc_n` 是两种读法，
    两者都留着并排放，免得把「模型的决定」和「模型的犹豫」混为一谈。后者一行一(主题,词)，同时给
    `overall_freq`（全库频次，蓝条）与 `within_freq`（该主题自身应产生的频次，红条），排序按 Sievert & Shirley
    的相关性 `λ·log p(w|t) + (1−λ)·log(p(w|t)/p(w))`：**λ=1** 按主题内概率（常见词容易上位）、**λ=0** 按相对全库的
    溢出（罕见但专属的词浮上来），论文图上的滑块就是这个 λ，本次用的值会随表一起打进控制台。
    两张表接 **主题距离图**（气泡面积=占比、带 PC1/PC2 参考线）与 **显著词图**（同轴双条横向柱状，rank 1 在顶端）
    两个可视化节点即可成图；显著词图先用筛选节点留一个主题。
    **主题生命周期（次生舆情）**读上一步的宽表：分阶段建模每阶段都重新编号，所以一个「主题」只能靠特征词的重合度
    （Jaccard，阈值可填，默认 0.5）跨阶段追下去，输出一行一个主题：`首现阶段 / 峰值阶段 / 末现阶段 / 覆盖阶段数 /
    阶段路径 / 规模合计 / is_secondary`。`is_secondary` 用的是论文的两条判据——不是开场那个主题，**且**峰值出现在
    首现之后；只在晚期冒头一次的话题算"晚生主题"而不算次生舆情，两列并排留着供你自己判断。
    **主题流向**把相邻阶段的主题两两按**词分布**（读 `weights` 那一格）算 JS 散度，换成相似度 `1/(1+d)`，
    超过阈值才出一条边，输出 `source / target / similarity / from_stage / to_stage / 两端特征词`——
    这三列正好是**桑基图**节点的 x / y / 数值。一条边都达不到阈值时它拒绝并告诉你实测最相似的一对是多少，
    因为交一张空流向表会被读成"没有承接"，而那并不是这次检查得到的结论。
    **主题数扫描**回答论文没交代的"设定主题个数怎么定"：对 `min…max` 逐个拟合，一行一个数，给困惑度与
    **一致性**。这里的一致性是按文档统计的 NPMI（一个主题的头部词两两"同现于同一篇文本"的程度），
    它只是发表口径 C_v 的一部分——没有滑动窗口切分、也没有主题两两的参考余弦那一步，所以不要拿它去对论文里的数字。
    语料大时默认只抽 2000 篇（抽样按表固定，同一张表两次跑出同一组数），日志会说明抽了多少。
    **共词网络**是论文"知识图谱"那一半：候选词取本表 TF-IDF 表（与关键词节点同一套分词、同一份停用词表），
    数同一篇文本（或 `window` 个词以内）里两两同现的次数，输出 `source / target / value`，接**关系图**或桑基图。
    候选词上限 120，超了会拒绝而不是悄悄截断：图对候选词是全覆盖的，留下哪 120 个词是在替你决定图上有哪些边。
    **回复传播边**（`reply_graph`）用评论自带的 `楼层`/`父楼层`（楼中楼指向被回答的那一层）把每条回复对回其顶层评论的作者，
    输出 `src_author / dst_author / weight`，接同一张**关系图**（源/目标/值）。一条回复都关联不上时按名拒绝，绝不画一张空图。
    **跨平台对比**（`compare_platform`）按 `platform` 列每个平台出一行：条数 `n` 加对一个可选数值列的聚合（均值/求和）。
    这个 `platform` 列由**输出(保存)节点合并多个上游爬虫时**统一盖下（每个父表按其节点平台写值、上传等非爬虫父留空），
    只加一列、不增删行也不改合并顺序，所以 SimHash「行数只对产生它的合并顺序成立」这条不变式照旧成立；表里没有该列时按名拒绝。
    **聚类摘要**（`cluster_label`）是「主题概括」的另一种读法：它读聚类(process 的 `cluster`)给每行贴的标签列与该行的**原始文本**，
    每簇问一次模型、用簇内真实文本写一段摘要，产出一张一簇一行的可读表（同样有模型缺失即拒、Stop 标未处理、答案缓存、簇数上限）。
    **簇综述·研究前沿**（`cluster_review`）是它的**文献计量版**：喂给模型的不是文本，而是该簇**已有的度量**——LLR 标签、节点数、
    按频次排序的代表节点、年份跨度（全部取自表格，缺哪列就少哪一行，不写"未知"诱使模型编造），请它写 3–5 句"这个簇构成什么研究前沿、往哪走"。
    默认列名对齐 `biblio` 节点写出的 `聚类 / 聚类标签 / 节点 / 频次 / 首年 / 末年`，输出 `聚类 / 节点数 / 代表节点 / 年份跨度 / 聚类标签 / 簇综述`。
    付费纪律与上面两步完全一致（无模型先拒、Stop 把没问到的簇标为未处理→节点结算为 PARTIAL、按 prompt 缓存所以续跑不重付、簇数上限）。
    `on_fail=fallback` 生成的句子会在**格子里**写明"未经模型"——表格是会被带进论文的，只在控制台说一声不够。
    **水军可能性**（`bot`，算法处理节点的新操作）按**作者**读整表：某作者与他人高度雷同（复用去重同款 SimHash，跨账号才算）的文本占比，
    加上相对全库中位的发帖突发，写 `bot_score/bot_level/bot_evidence` 三列回每行。它是**召回线索不是判决**——换措辞换时间的协同账号一律漏检且漏检率不可测，
    日志会打印这一句；缺 `评论者`/`评论时间`/`正文` 任一列都按名拒绝，绝不当成"没有作者"。
    **情感走向外推**（`forecast`）接情感演化曲线，把这条**曲线的形状**往后推若干期——不是预测事件，模型不知道会不会有
    通报，这一点写在算子里也写在面板上。四种方法都在这里手算，不引 statsmodels：`moving_average` 把最后 `window` 期的
    均值持平外推、置信带**不等宽**（它没有趋势，把带子画宽是演戏）；`holt` 是水平+趋势的双指数平滑，带子按 √步数 变宽，
    宽度用的是它自己一步预测误差的标准差。输出把历史与未来放在同一张表里：历史行带 `actual` 与"当时本可预测出的下一步"
    （`horizon=0`），未来行只有 `predicted/lower/upper` 且 `actual` 留空（没发生的事不留数字）。时段列必须能解析成**日期**
    （"发酵期"这类阶段名没法外推，直接拒绝），同一天出现两行会被拒（那会被当成趋势的两步），间隔不齐时按众数间隔标未来
    的日期并说明有多少步不齐。
    **二次爆发预警**（`alert`）把论文的"提前干预"落成一条可读的规则：`转向`=连续 N 期每期指数变化都超过幅度阈值且
    同向（一次大跳动是对事件的反应，一连串同向才是人群在移动）；`升温`=强度在这 N 期里平均每步上升超过阈值（指数可以
    停在 0 附近而两边同时变响，这正是论文说的二次爆发期形状，只看有符号曲线会漏掉）。两者都要**热度还在**（不低于前 N
    期均量的设定倍率）才算触发——只剩少数人在发帖时的剧烈摆动不是爆发；被热度压掉的候选**仍出一行**并写明是被压掉的，
    因为"没触发"与"触发了但人群已散"是两个不同的结论，只有一个值得动手。一条都没触发时也出一行 `未触发` 并带上实测
    到的最大幅度：空表会被读成"没检查过"，而在监控节点里，那正是"平静"与"失明"的区别。
    这几个算子的产出可直接接折线图、**双轴折线**（左轴热度、右轴强度，一条曲线说不清的"热度与强度反向"）、
    **占比堆叠图**（情感演化曲线每阶段一行、含 `positive_pct/neutral_pct/negative_pct`：接一个 `stack_pct` 节点，
    横轴填阶段列、堆叠字段填 `positive_pct,neutral_pct,negative_pct`，即每阶段一根归一到 100% 的柱、并排看清各期情感构成——
    倾向/情绪等任何按阶段分布的列同理）与导出。
    **事件标注**给柱状/折线/双轴折线：填 `2024-05-19=公安通报; 2024-04-23=遗体打捞`，在横轴那个类别上画竖直虚线，
    让官方节点落在它解释的那段曲线上方。标签必须与轴上的取值一字不差，对不上就拒绝并把可选标签列出来——
    一张悄悄丢了日期的图比没有图更糟；选 Matplotlib 时会明确拒绝，因为那个渲染器没有标注层。
    **阶段先后怎么跨过节点边界**：`按时间划分阶段` 写的是**有序 categorical**，而每过一个节点表格都会被
    `pd.DataFrame(records)` 重建回普通字符串——码点顺序会把「二次爆发期」排到「发酵期」前面。所以
    `分阶段 LDA` 除了阶段列还会写一列 `stage_order`（数字序号），`主题生命周期` 与 `主题流向` 都读它来定先后；
    两个都没有（既没有有序列、也没有可解析的时间或序号列）就拒绝，绝不按名字猜。
  - **去重分三层**：`去重`算子有两种判重依据——`exact`（逐字相同）与 `normalized`（忽略链接/@/话题/表情
    的归一化后相同，能识别水军改写）；**近重复去重（SimHash）** 则按语义指纹的距离分组，抓「改一个词的转发」。
    归一化只用于比较，落库的仍是原文。距离默认 **8** 位，是实测出来的不是拍的：微博评论里「改一个词」大约
    差 5–18 位，两条互不相关的评论差 26–28 位，所以 8 只合并明确相同的改写；往上调（上限 15）提召回、降精确率，
    建议按自己那张表的实际行数逐次调整。分桶数会随你填的距离自动加宽，所以 15 位也是**证明过**的结果，
    不是全量两两比对
- **文件持久化**：上传/粘贴的文件注册为数据集（内容哈希寻址、zlib 压缩存库），
  保存的工作流随时可重新加载自己的输入文件；无引用且长期未用的文件自动清理。
  「数据集管理」面板支持逐个改名/删除（被已存工作流引用的**当场拒**），面板头的**清空**
  则连被引用的也一并删——这一点差别写在确认框里，因为逐条删除会护住的那些文件正是这里唯一
  会被删掉的，而引用它们的 Upload 节点不会报错，只会下次读出一张空表
- **通用导出节点**：一个节点支持导出 CSV / JSON / Excel / TXT / HTML / Markdown / Parquet 七种格式
  （Parquet 需要列式引擎 pyarrow，属 `requirements-optional.txt` 里的可选依赖、CI 不装；缺引擎时该格式**按名拒绝**并提示
  `pip install pyarrow`，其余格式照常）
- **一键运行报告**：工具栏「生成报告」把本次运行（或运行记录里任选一条历史运行）的每张表格与服务端
  渲染的图表拼成**一个自包含 HTML**——样式与图片全部内联，离线能看、能打印、能发给别人；配色沿用画布的
  ZENVIZ 设计令牌（纸白底、墨色字、发丝分隔线、赭石强调色）。报告内容**可自定义**：弹窗里勾选要不要
  图表 / 数据表 / 运行信息、每张表最多几行、以及把「图表工坊（ZENVIZ）」存进导出目录的成图一并内联进去。
  可选「附 AI 结论」，只根据统计数字让模型写一段话，结论失败仅少一段文字而不影响报告本身；还能选「生成并导出
  PDF」——用用户自己的无头 Chrome 把已写好的 HTML 打印成 PDF（不引入新依赖，找不到 Chrome 或打印失败只少一个
  PDF，报告照常出）。文件仍落在导出目录，由「导出产物」面板统一查看与删除。因为内容来自互联网抓取的文本，
  报告页只经 `/api/report/view` 提供，并带禁止脚本的 CSP 策略

## 文献计量

CiteSpace 风格的知识图谱能力以 **Bibliometrics 节点**接入工作流。它是普通表格节点：上游可以是 Upload（CSV/Excel/JSON/CNKI/CSSCI），也可以是爬虫节点；列映射把任意表接成网络，CNKI/CSSCI 只是默认列名。实现为净室重写（Kleinberg 突现、PFNET、谱聚类、LLR 等公开算法），不包含 CiteSpace 代码或其 JCR 基线数据。

- **导入**：格式注册表识别 **CNKI RefWorks、CSSCI、WoS 纯文本、Scopus CSV、PubMed XML/NBIB、Dimensions CSV、Lens CSV、RIS、BibTeX、EndNote tagged**。规范化列为 `记录ID/题名/作者/作者单位/来源期刊/年份/卷/期/页码/关键词/摘要/参考文献/DOI/格式`，并按实际数据追加 `国家/学科/引用次数/使用次数/使用次数2013/基金/文献类型/语言/引文`。`引文` 是结构化 JSON；普通文本与不满足文献签名的 CSV/Excel 仍保持原导入行为。
- **实体**：关键词 / 作者 / 机构 / 国家 / 学科 / 主题词 / 基金共现；文献、作者、期刊共被引；文献耦合；来源期刊耦合。CiteSpace 的 `Source`、`Grant`、`Article` 分别作为 `source`、`grant`、`article` 节点类型接入，并与本项目的 `journal`、`funder`、`document_cocitation` 保持同一算法语义。共现类只需要实体列与年份列；引文/耦合类需要参考文献列。CNKI RefWorks 通常没有参考文献，引文模式会按名拒绝并提示改用 CSSCI/WoS/Scopus 等含引文的导出。
- **网络**：按年份切片（`slice_years`），每片按 TopN / Top% / g-index / 阈值三元组选择后合并；支持 look-back years、最低 TC/usage 过滤、citation expansion（0–2 阶，只沿数据集中已有文献的 DOI/题名展开，上限 500 条/文献并播报）、cosine / Dice / Jaccard / association、**整次/分数计数**（`counting`：`fractional` 把每篇文档的 1 份信用均摊给它承载的连边对，于是引用 150 条的文章不再压过引用 12 条的文章；表里的「次数」仍是真实相遇次数，只有连边强度被重新归一；耦合类网络没有可拆的第三方文档，选了会按名拒绝）、每节点最大连边 + LRF、cc/ccv 边过滤、最大连通分量；剪枝 none / MST / Pathfinder，作用域可选 `slices`（逐片剪完再合并，默认）或 `merged`（对合并网络剪一次）。Pathfinder 的三个参数：**`pathfinder_r`**（Mantel 的 r 范数：`1` = 路径上各段距离求和、`2` = 欧氏范数、`inf` = 取最长的一段，即瓶颈路径，默认）、**`pathfinder_lmax`**（参与比较的间接路径最长几跳，`0` = 不限）、**`pathfinder_dmax`**（在通过判定的连边里按强度降序保留的比例，`1` = 全留）。判据是：一条连边只有在**自身距离不比两端之间最好的间接路径更长**时才保留。`r=∞` 且不限跳数时 PFNET 与最大生成森林是同一张图，此时走生成森林快路（结果相同、代价 O(m log n) 而非 O(n³)）；一般情形按跳数做稠密 DP，规模超过预算时**按名拒绝**并写出它测到的节点数、层数与运算量，建议改用 MST 或调小 TopN/`pathfinder_lmax`，绝不静默降级。实际剪枝前后边数、作用域与用到的参数都写入控制台。
- **指标**：度、中介中心性（距离 = 1/权重，节点多时按 500 源点采样并播报）、特征向量中心性（按连通分量计算）、PageRank、Sigma = `(中介中心性+1)^突现强度`；输入含 `引用次数` 时追加 `总被引/H指数`，含 `使用次数` 时追加 `使用次数合计`。
- **聚类**：归一化 Laplacian 谱聚类，聚类数留空时按特征值间隙自动选择；模块度 Q、逐节点/逐簇轮廓值写入运行摘要；标签支持 LLR / LSI / MI / TF-IDF。标签词的来源由 `label_source` 选择：`all`（默认，历史混合：图谱自身的实体/关键词值 + 题名 + 摘要；**作者名不会隐式混入**）、`title`、`abstract`、`keywords`、`author`。显式选择的来源列在输入表里不存在时**运行前按名拒绝**；`all` 保持宽松（没有摘要的爬取表仍用关键词打标签）。来源没有可用的词时回退 `members` 并在摘要/控制台标明。
- **突现**：两状态 Kleinberg Viterbi，按逐年文档数计算；每个节点保留最强突现区间，突现词表另写 CSV。耦合类节点是施引单元本身，禁止突现。
- **结构变异（structural variation）**：开关 `variation`，度量**相邻两个切片之间**一个节点连接模式的移动量——取该节点两期连边强度分布之间的 **Jensen–Shannon 散度（比特）**：0 = 模式没变，1 = 两期的邻居毫不相干。选 JSD 而不是裸 KL，是因为"某邻居出现/消失"会让 KL 变成无穷大，而无穷大的分数没法排进表里。`variation_min`（默认 0.05 bit）是上报阈值：0 会把"只是多了一个邻居"的节点也列出来。**只有两期都有连边的节点才计分**——"原来有模式、后来什么都没有"是消失，不是结构改变，替它编一个分数会把消失排在真正的重组之上。切片不连续（中间有年份没有任何文献）时**不跨缺口比较**，否则报出来的是两年缺数据。`output_shape=variation` 输出该表（`节点 / 起始年 / 结束年 / 结构变化 / 前邻居 / 后邻居 / 新增邻居 / 消失邻居`），并按 `<名>_variation.csv` 写产物、进 JSON 快照。少于两个切片、或耦合类网络（耦合连边属于两篇施引文献、不属于某一年）都会**按名拒绝**，不替你造一条时间轴。
- **情感 / 话题叠加**：`sentiment_column` / `topic_column` 填**上游已经写出的标签列**——情感/情绪/倾向步骤的 `sentiment` / `emotion` / `tendency`，或逐文档的话题归属（文本聚类写出的 `cluster` 可以当话题代理）。每个节点追加两列：`情感倾向` + `情感分布`（或 `主导话题` + `话题分布`）。分布是「**提及该节点的文档里各标签的篇数**」的规范 JSON；主导标签取篇数最多者，**并列按标签文字定序**，与行序无关——同一语料换一种排列得到同一个答案。分母只含**有标签的文档**：空白是「没有判断」，不是「中性」，部分记录没标签会在控制台报出条数。填了表中不存在的列、或整列没有任何标签，都在**运行前按名拒绝**，不会带着两列空白继续。两列各配一张图：`sentiment_overlay`（每个节点一条 100% 堆叠横条；三个极性标签按 负面→中性→正面 的语义顺序与固定颜色，其它标签集按频次排序；行按正面占比从高到低）与 `topic_overlay`（节点 × 话题热力图，格子是**占比**而不是原始篇数，否则一个高频节点会把别的行都压成空白色）。两张图都只画前 20 个节点 / 12 个话题并在标题下写明省略数，完整分布仍在节点表的 JSON 列与 CSV 里。
- **人工校正**：`aliases` 每行 `规范名=别名1|别名2`，`exclude_values` 每行一个排除标签；两者在建图前合并/移除节点，并计入节点指纹，因此续跑不会复用未校正的图。`cluster_labels` 每行 `#簇号 = 标签`，在 LLR/LSI/MI/TF-IDF 之后覆盖簇名（同样计入指纹）；指到本次运行不存在的簇会在控制台点名该行未生效，摘要里的标签方法会加写 `+manual`，只按**真正落地的条数**计数。填了人工簇标签却没开聚类 → 运行前按名拒绝。
- **输出**：默认 `output_shape=nodes`，一行一节点，固定列 `节点/类型/频次/首年/末年/年份序列/度/中介中心性/特征向量中心性/PageRank/Sigma/x/y/连接`；开启聚类追加 `聚类/聚类标签/轮廓值`，开启突现追加 `突现强度/突现起始/突现结束`。`连接` 与 `年份序列` 是规范 JSON 文本，图谱图直接读取；每个节点的 `连接` 存完整局部邻接，图构建时按端点对去重。`output_shape` 还可输出 `edges`/`clusters`/`bursts` 普通表，供下游继续处理；`dual_map` 输出 `map/source/target/weight/label/x/y` 的叠加表（`map` 取 `journal`/`category`/`overlay`，端点为空的行是该侧的一个节点），需要 `basemap_dataset_id` 指向一份自备的「期刊—学科」两列表，缺基线按名拒绝。
- **图**：`knowledge_graph`（固定布局知识图谱）、`circular`（环形图谱）、`cluster_timeline`（聚类时间线）、`landscape`（景观图）、`burst`（突现词图）、`timezone`（时区图）、`biblio_heatmap`（聚类—年份热力图）、`graph3d`（三维图谱，ECharts GL）、`variation`（结构变异：x 为相邻切片对、y 为节点，标记的**面积与深浅**都随散度增大——面积按平方根映射，所以等量的变化画出等大的面；空格子不是 0，而是该节点在那一对切片里没有可比连接）、`dual_map`（双图叠加：左期刊列、右学科列、中间叠加引用弧）、`geo_map`（国家/地区地理图：世界底图着色，读 `country` 图谱的节点表）、`sentiment_overlay`（情感叠加：每节点一条 100% 堆叠横条，图例随标签集而定）、`topic_overlay`（话题叠加：节点 × 话题热力图，格子为占比），均仅 ECharts。缺列/无连边/未开聚类、突现或结构变异、没有叠加列时按名拒绝。十三类图均有 TikZ/pgfplots LaTeX 图源与 booktabs 三线表，并附余弦、Dice、Jaccard、中介中心性、PageRank、Sigma 公式（结构变异图另附 Jensen–Shannon 散度公式，地理图附地区合计/占比/色阶归一公式，情感/话题叠加图附各自的占比公式与「图和表是节选」的说明）；`emit_latex` / `emit_latex_table` 在节点上默认开启，画出来的图与论文里的图是同一份行的两个投影。前端 `labelLayout` 按实际渲染矩形避让中文标签，并且只在 series 自己声明的 `left/top/right/bottom` 预留带内落位（带上沿是标题与聚类图例），放不下的标签隐藏并保留 hover。y 轴分类标签**永不旋转**：竖排中文名有多长就有多高，13 行以上就会互相压字（`_print_style` 的密轴规则因此只对 x 轴生效）。
- **按年份回放**：图谱与环形图的每个节点都带自己的 `yearSeries`（就是节点表的 `年份序列`，随选项一起发到浏览器），
  所以预览窗口与全屏窗口下方多一条回放条：播放/暂停、逐年拖动、看完整图。节点按**到这一年为止累计的频次**长大，
  连边在**两端都已出现**的那一年才出现——选项里没有逐年的连边，所以不替它声称一条它没有的边（这条规则写在按钮旁边，不藏在文档里）。
  最后一帧与完整图**逐字节相同**（每格按该节点自己的总量归一，不是按当帧最大值），所以"播完"就是"回到那张图"；
  回放只改浏览器里的一次 `setOption`，**已存的 PNG/SVG/LaTeX 仍是完整网络**——动画不能印在纸上。
  只有 ECharts 画的图型有这条；Matplotlib 出的是位图、只有一年的表、或没有 `年份序列` 列的手作表，都**不出现回放条**。
- **跨 run 监测（领域监测）**：`biblio` 节点填了 `watch_project` 之后，每次运行都会把自己这张网络**存成该项目的一个快照**，
  并与**上一次捕获**对比（`watch_baseline` 可指定更早的那一次，用来回答「比上个月变了什么」而不是「比昨天变了什么」）：
  新增/消失的节点与连边、逐列变化的节点属性、新簇/消失的簇/簇改名/簇规模、**新突现/结束的突现**、以及**哪几项参数被改过**，
  全部逐条打印到运行控制台，并另存一份 `<画布>-<节点>-watch.csv`（`类别 / 名称 / 前值 / 后值`）登记到运行产物，可在文献计量工作区下载。
  项目不存在时**自动新建**并说明；首次捕获没有可比对象，就照实说「无更早的快照可比」而不是报一片「消失」。
  两条按名拒绝：输出形态不是实体表（`variation`/`clusters`/`bursts` 的行不是一行一实体，存进去会让下次对比把行数差当成领域变化）、
  本次图谱空（空捕获会把历史上所有实体报成消失）。`watch_*` 三项**不进节点指纹**（它们不改变任何一行输出，改个捕获名不该重算已付费的图），
  也**不写进快照的参数**（否则每次捕获都与基准差在自己的名字上，「参数变了」就不再说明任何东西）。
  配合顶栏**定时任务**按周期跑同一张画布即是监测流水线：时钟走的是同一条 `_begin_run` 路径，服务器忙就排队，错过的时刻只记账不补跑。
- **国家/地区地理图（`geo_map`）与它的世界底图**：底图是 **Natural Earth 1:110m Admin 0 — Countries（public domain）**，
  由 `tools/build_world_geojson.py` 生成并**随仓库分发**（`backend/static/geo/world.json`，239 个区域、约 200 KB）：
  只留 `name / zh / iso / alt` 四个属性、坐标取两位小数、110m 缺的 65 个小国（新加坡、巴林、毛里求斯、斐济……）从 1:50m 补进来——
  否则地图上画不出一个国家，读起来就像"那个国家没发文"。文件随仓库走而不是运行时抓第三方 CDN，因为这是台离线也要能出图的科研工具。
  **一处明确的制图主张**：Natural Earth 把台湾记为独立区域（`NAME_ZH: 中华民国`），构建脚本把台湾、香港、澳门的几何并入中国
  （MultiPolygon 允许不相交的分片，所以是坐标拼接而不是重画），与本应用中国底图（DataV/高德）的画法一致；格陵兰、北塞浦路斯等
  仍按 Natural Earth 原样分开，因为 WoS 的地址字段就是这么给的。**并入是有代价的，所以图上点名**：
  标题下的副文本写出「底图无此区域 N 个：…」与「并入其他区域 N 处：England→英国；Peoples R China→中华人民共和国」。
  名称解析走 `services/biblio_geo.py`：底图自身的 `name/zh/iso/alt` 先匹配，再借导入器已有的国别别名表
  （`biblio_formats/countries`，不另起一份拼写表），最后才是一张刻意保持短的桥表；
  `tests/unit/test_biblio_geo.py` 拿**导入器能吐出的全部国名**逐个比对底图，一个都不许解析不出来。
  同一地区的多种写法**按地区求和**（`biblio_geo.aggregate` 由图与 LaTeX 共用），纸质版按发文量排序画条形图（世界几何不进 LaTeX），全部数值见三线表。
- **产物**：默认写 `<节点>_graph.graphml`、`_graph.gml`、`_graph.net`（Pajek：顶点按名字排序、边带权重）、`_graph.json`、`_nodes.csv`、`_edges.csv`，开启聚类/突现时另写 `_clusters.csv`/`_bursts.csv`，登记到本次运行，可在导出目录下载；`export_files` 可关闭。`dual_map` 形态没有单一网络图，只写表。
- **边界**：CNKI 无被引次数与 CR，因此无共被引/耦合/引用突现；双图叠加的期刊—学科基线由用户导入（`samples/biblio_basemap_demo.csv` 是合成样例），不内置任何商业 JCR 数据，缺文件按名拒绝而不是画空图。

演示：`data/workflows/文献计量演示：CNKI 与 CSSCI 知识图谱.json`（CNKI 关键词/作者 + CSSCI 文献共被引/来源期刊耦合/作者共被引，共 14 张图；双图叠加那条链默认**关闭**，因为基线要用户自备——先在数据集管理里上传 `samples/biblio_basemap_demo.csv`，在「双图叠加」节点选它作 basemap，再启用这两个节点）。**情感/话题叠加链也默认关闭**：它跑得起来（CNKI 摘要 → SnowNLP 情感 → 文本聚类 → 带两列标签的图谱 → 两张叠加图），但本机实测 SnowNLP 把这 36 条摘要涉及的 108 次关键词—文献共现**全判为正面**——一张全绿的横条图不是发现，也不该被当成演示结果。真实的用法是在爬取的短文本上跑情感步骤（或换用你训练/标注的标签列），再在 biblio 节点填入列名；启用这条链之前先在数据集里上传 CNKI 样例并在「上传 CNKI 样例」节点重新选择。工作流按数据集 id 引用本机已注册的两份样例；换一台机器时先上传 `samples/biblio_cnki_demo.txt` 与 `samples/biblio_cssci_demo.txt`，再在两个 Upload 节点里重新选择即可。

## 跨源融合
- **`fuse` 节点**：把任意多张上游表折叠成一份规范记录表（`题名/作者/作者单位/来源期刊/年份/关键词/摘要/参考文献/记录ID/来源`）。
  每个角色是**候选列列表**，按顺序尝试：文献的 `关键词` 与帖子的 `话题` 折叠后进同一个词表，下游 `biblio` 节点用默认列映射即可。
  年份从 `2022-03-04 11:02` 这类时间戳里取四位年份，取不到就是空（`keep_undated` 决定这类行留不留）。
- **来源是数据，不是猜的**：表内自带 `平台`/`来源` 列就逐行取（一张表混几个平台时每行保留自己那个）；否则用
  `source_labels` 里为该父节点写的一行（`node-1 = 文献`）；再否则按父节点 id 登记。**不会**替一个没说过自己来历的表
  写「文献」。父节点没有可用实体列、或该列一个实体都没提出 → 按名拒绝并列出试过的候选。
- **图的来源列**：输入表带 `来源` 时，`biblio` 节点的输出多出 `来源`（该实体出现在哪些语料，`;` 连接）与 `跨源`
  （是否多于一个）两列，`output_columns` 同步声明；普通文献运行不会长出这两列（空的可信度列等于假的声明）。
- **为什么不用现成的 fan-in 合并**：引擎的多入线合并保留各表原有列名并把行拼起来，`关键词` 与 `话题` 于是永远在两个
  列里，而且没有任何一行还知道自己来自哪张表——融合图要回答的正是「哪些词文献和社媒都在谈」。`fuse` 因此读
  `upstream`（每个父节点及其行）而不是 `current_input`，并为此**不**打印「第一条线是主输入」那条通用提示：
  多入线对这个节点就是功能本身。
- **导出**：`export_files` 打开时把折叠后的记录表写成 CSV 并登记进运行产物台账（`fuse_records`）——这是唯一能事后核对
  「某个词到底来自哪份语料」的中间文件。

## 可视化
- **图表是论文样式，不是仪表盘样式**：一套印刷安全的配色（首个色是深板岩蓝，不再是荧光蓝）、衬线字体
  （Times New Roman + 宋体）、**折线不平滑、不填充渐变面积**（平滑会在两个实测日之间编出形状，面积会让人以为
  那片阴影是个量）、坐标轴细而可见、网格线浅虚线。分类轴**保留表格自己的行序**——早前 `_aggregate` 末尾一个
  `sort_index()` 把 表2 的阶段按字典序重排，于是 图3 的第一根柱子是「一次爆发期」，图看着完整而生命周期被读反了。
  密集分类轴（>12 个取值）会**旋转到 45° 并强制显示每一格**（`interval: 0`）：ECharts 默认为了避让会**丢标签**，
  而一张日期被吞掉一半的图正是 图2 的问题；网格同时留足下边距与右边距（`containLabel`），轴名 PC1/PC2 不再被裁。
  力导向的关系图**先算定再画**（`force.animate: false` + 圆形初值 + `layoutAnimation: false`），
  不再像早前那样在屏幕上晃几十秒才平衡——一张每次打开位置都不一样的图没法进论文。
- **关系图可「以某个节点为中心」渲染（`center_node`，可选）**：整张共词网络候选词一多就糊成一团，而某个词的邻居只在鼠标悬停时才亮起来、鼠标一动就没了——悬停高亮抓不进导出的 PNG。填入图中已有的某个词，就只画它的**邻域图（ego-network）**：该词 + 与它直接共现的词 + 这些词之间的边，中心词按共现权重自然成为最大的一团。这是一个真参数（进节点指纹、改变出图），预览与「导出为图片」、报告里的图都按它渲染；留空则画全部候选词（与从前逐字节一致）。填了图里没有的词会**按名拒绝**，不会画成空图。
- **所有渲染文字跟随界面语言（中文界面即全中文）**：图例、series 名、坐标轴名、tooltip，以及从数据里读出的分类值
  （`positive/negative/neutral`→正面/负面/中性、`Topic-1`→主题-1、`PC1/PC2`→第一/第二主坐标、`total`→发帖量、
  `sentiment_index`→情感指数、`overall_freq/within_freq`→总体词频/主题内词频 等）都在**显示层**统一翻译
  （`visualizer.py` 的 `_localize_label`，走 i18n，中英各一套，随运行语言切换）。库里与算子输出的**列名、标签值一律不改**
  （那是节点之间的输入契约），只改图上那几个字；不在受控词表里的值——日期、数字、已经是中文的阶段名、你自己起的列名——
  原样透出，绝不猜。事件标注的竖线走同一张翻译表，所以汉化后的轴标签与标注值仍对得上、不错位。
- **所有数词的步骤共用一份停用词表**（`backend/analyzers/stopwords.py`）：LDA 特征词、显著词、共词网络、
  关键词节点、词云以前各用各的过滤（LDA 那几处只要求"含字母或数字"），所以 表1 的头部特征词里会出现
  自己 / 一直 / 成为 / 一个 / 这个，共词网络的强边也连在这些词上——那不是噪声大的测量，是量到了语法。
  表本身保守收录：语法词进表，域内实词（网暴 / 警方 / 律师 / 生父 / 校园 / 私信 / 微博 / 网友 / 问题）一律保留，
  用例把这两个方向都钉住了；觉得某个词被误杀或漏杀，改那一处列表即可（与 `aggression` 的词表同理：不完整是可以审的）。
- **通用可视化节点**：柱状图 / 折线图 / **双轴折线**（左轴热度、右轴强度，两根独立刻度的曲线共用一条时间轴）/
    **主题距离图**（气泡位置=主题间 JS 散度的 MDS、面积=主题占比、标签=主题概括——刘学州画布里每张距离图的
    `topic_map` 数据节点后各挂一个「主题概括」LLM 节点，把 `主题1` 换成读得懂的中文概括；未接概括时回落 `主题N`）/
    **显著词图**（同轴双条横向柱状：全库频次与主题内频次并排，rank 1 在顶端）/
    饼图 / 散点图 / 直方图 / 箱线图 / 热力图 / **模型一致率**（`model_agreement`，多模型对比表专用：读 `模型`/标签/`原行` 三列，
    画两两模型判定相同的百分比方阵热力图，需上游是勾选了 ≥2 个模型的分析节点）/ 桑基图 / **关系图**（力导向：共词网络与主题流向都吃这张表，
    节点面积与边宽都按 √值 走，起点固定为环形布局，所以同一张表两次跑出同一个形状，不会看着像另一个结论）/
  词云（支持中文分词）/ 中国地图，支持 ECharts（前端渲染）与 Matplotlib（服务端渲染）两种引擎
  （双轴折线、主题距离图、显著词图、模型一致率与关系图只有 ECharts 支持，选 Matplotlib 会明确拒绝而不是画成别的东西）。
  柱状/折线/双轴折线还能填**事件标注**（`日期=名称; 日期=名称`），在横轴对应类别上画一条竖直虚线并标出事件名
- **占比堆叠图（stack_pct）**：把任意「独立分布」画成每根柱归一到 100% 的堆叠对比图——横轴是分类（如阶段/时期），
  「堆叠字段」填逗号分隔的若干列，每列是柱内一段（如 `积极占比,中性占比,消极占比`）。每个分类都会被**归一到 100%**，
  所以传入某一步写出的占比列、或任何构成同一分布的原始计数列都可以（计数会自动换算成占比）。一张图并排展示各期的构成占比，
  正是「对比性分布」（情感/倾向/情绪等）最清楚的呈现方式；横轴按数据表自身顺序保留阶段次序，不会被字母序打乱。
  列名（`positive_pct`→`积极占比` 等）随界面语言本地化显示，两种引擎都支持。
- **图表统一为文科论文印刷风格**：所有图表（两种引擎）都去掉网格线、只保留读者度量所依的左/下两条坐标轴并以墨色绘制、
  文字用衬线（Times New Roman / 宋体）；折线不再平滑、也不填色阶（两点之间没有测量过的数据，画出来等于编造），
  柱条直角、力导向图一次算定不再在屏上漂移——导出到论文里的每张图读起来是一幅「图」而非一块仪表盘。
- **可视化节点另出 LaTeX（`emit_latex`，默认开）**：每个可视化节点除出图外，还生成一份 **可被 MiKTeX 编译的
  LaTeX 图源码**，写为 `data/exports/<节点标题>.txt`（standalone 文档，`xelatex` 直接编译成矢量 PDF，也可把其中
  figure 体复制进论文）。用 pgfplots + TikZ（ctex 中文、booktabs），**对齐手工精修论文的观感**：全文 **仿宋 FangSong**
  （`\setCJKmainfont`）、与论文实调一致的 muted 配色、淡点网格、坐标轴与柱顶数值 **千分位**（`1000 sep`、禁科学计数）、
  柱条顶标注数值、折线圆角描点；**主题距离图 / 共词关系图 / 桑基流向图**的标签一律走**白底圆角框 + 引线**（长中文不再压叠数据点），
  桑基缎带按来源着色、节点为实色条；热力图改用与配色同系的蓝色渐变。分类过多时 X 轴自动倾斜并等距抽稀（数据点全留、可按点数还原标签）；
  **覆盖项目全部图型**——中国地图用省会质心气泡图、词云用按词频字号与深浅的词块（无外部地理/排版数据下的近似，且全部数值另附三线表以保证「内容完整」）。
  预览面板提供「复制 LaTeX / 下载 .txt」。另有默认开的 **`emit_latex_table` 复选框**，可再输出一份符合论文规范的
  **booktabs 三线表** `.txt`（`\footnotesize`、行距 1.25、表头加粗）。LaTeX 生成失败只记一条具名日志，不影响该节点照常出图。
- **MiKTeX 编译节点 + 图表直出 PDF**：新增 **编译（`compile`）节点**，上游只能接**可视化节点**，把它产出的
  LaTeX（图和/或三线表）用本机 **MiKTeX `xelatex`** 合成**一份** standalone 文档、编译成**一个 PDF**（图与表在同一份文件里）。
  再接一个**输出节点**即把 PDF 落成用户命名的文件；**可视化节点直连输出节点**也能出 PDF（输出节点自行编译）。
  为此**输出节点的格式按上游锁定**：上游是可视化/编译节点时**只有 PDF 可选**，其它上游则**不出现 PDF**；前端 `validateWorkflow`
  与后端 `engine.validate` 同时把关——接可视化节点但两个 LaTeX 复选框都没开、或 PDF 输出混了表格上游，运行前就按名拒绝。
  `xelatex` 路径在**设置 → MiKTeX 编译程序路径**里指定（留空则自动探测 PATH 与常见安装位置）；找不到编译器只让该节点具名失败，不崩整轮。
- **论文成稿（一键把这次运行排成一份 .tex/PDF）**：报告面板的运行下拉里多一个「**论文成稿（LaTeX）**」按钮，
  打 `POST /api/report/latex`，**请求只带 `run_id` 与标题**——图与三线表一律从这次运行**已登记的 LaTeX 源文件**读回来，
  所以论文里的图与预览里的图不可能各画一份，浏览器也没有把 LaTeX 交给编译器的路（那等于让它读任意文件）。
  合成的是 `article` + `ctex`（导言区**复用图表自己的 preamble**，否则第一处 `\draw[cA]` 就死在 `Undefined color`）：
  **方法**段逐节点给出分析单元与参数（参数只从**已保存画布**读、并与运行记下的指纹核对，核对不上就明说哪几个节点没核上），
  随后是**图 1 / 表 1 / 图 2 / 表 2……**，标题用节点标题，末尾点名工作流、运行编号、时间窗与图表数。
  **先写 `.tex` 再编译**：编译器拒绝时留下的正是那份可继续排查的源文件，且绝不留半份 PDF。
  跑过却**没登记 LaTeX 源**的可视化节点不会留下空图位，也不会被悄悄省略——文末点名「另有 N 个可视化节点没有登记 LaTeX 源…」。
  - **每一项都是 `[H]` 浮动体**（float 宏包）：普通 `figure`/`table` 会把图挪到下一段之后，第一次编译就排出了
    一整页只有「1 图表」标题的空白页；`[H]` 既钉住阅读顺序，又保留 TeX 的整项换页能力。
  - **贴进来的正文按页宽缩放**（`\cixifit`：只在超出 `\textwidth` 时缩，绝不放大）：本项目图表自带的 minipage 是 17.5 cm，
    而 A4 配 2.2 cm 页边距只剩 16.6 cm 文本宽，于是页面右侧被切掉。
  - **网络图按版面反过来定自己的尺寸**：环形/图谱的布局半径随节点数增长（`0.46 × 节点数`）而 tikz 单位一直是 1 cm，
    49 个节点就画出 46 cm 宽的图；现在按 `GRAPH_BOX_CM`（15.0 × 10.5 cm）求出坐标缩放系数 `x=…cm,y=…cm`
    （**只缩不放**，小图保持原样），标签宽度用 `_label_cm` **偏宽地估**（估窄了才会溢出页面）。
  - **会互相遮盖的标签被丢掉并且当场说明丢了几条**（`_fit_labels` 矩形避让，东/西/南/北四个方向一起判，
    图上印「已省略 N 个会互相遮盖的节点标签；完整节点见三线表」）——只按每侧纵向扫描会漏掉「东侧标签压住北侧标签」。
  - **超过一页的三线表被切成整页的块**（`TABLE_ROWS_PER_BLOCK=26`）：`tabular` 不能跨页，50 行的表比版心高出 2.6 cm；
    切块后每块重复表头，**只有第一块编号**，续块用 `\caption*{…（续）}`（一张表两个编号就没法引用），**一行不丢**。
    形状不是本服务写出来的表（例如导出目录里手工改过的 `.txt`）原样贴入，绝不动刀。
- **采集深度可调**：微信正文长度上限由 `Config.WECHAT_BODY_MAX_CHARS` 决定（默认 0，完整保留；
  填正数才设上限，被截断时行尾带 `…` 标记，免得"半篇"看起来像"写完的短文"）；
  小红书数据源节点新增**每篇评论预览数**，填 `0` 真的跳过评论面板（以前即便只要 0 条，
  每篇仍会等满 10 秒，最快的设置反而是最慢的）
- **Chart Studio 图表工作台**：画布内嵌 ZENVIZ 工作台，可对任意节点/数据集的完整表格做自由图表创作，
  支持多数据源合并，成品 PNG 可保存回导出目录

  随界面语言切换；库里仍按原始 key 存，未知 key 回落原值不显示空白）。**导出的文件（CSV/Excel/JSON/txt…）同样写本地化平台名**——

- **评论采集前的一次性提示**：画布含评论节点时，运行前提示「部分平台/视频的评论区不发布 IP 属地，『评论地区』列可能为空」，
  避免把空列误当程序出错（纯搜索画布不打扰）

  只要该画布有最近一次运行，看板会按持久化的上游行把每张图重新渲染出来（图是数据行的投影，不额外写进运行库），
  没有最近结果时格子显示一条**友好提示「尚无运行数据，请先运行一次工作流」**（灰字备注、非红色报错），

- **图表另存为图片**：图表预览面板与看板每个格子都有「存为图片」，落到 `data/exports/` 里（与导出表同处），
  文件名就是那张图的节点标题（第二张预览会把名字带走，否则「chart-preview.png」无法对应回 图23）。
  两种引擎都管：ECharts 现取 `pixelRatio=2` 的白底 PNG（透明图贴进白纸等于没图），Matplotlib 直接存节点
  已经拿到的那张图。**还没有画出来的图不发请求**，而是说明「先点预览或把节点跑完」——点了没反应会被当成按钮坏了。

- **图表全屏**：看板每个格子和预览面板都有「全屏」，弹出一个**可拖动、可改大小**的浮层窗口看单张图（复用与预览面板同一套
  `makeDraggable`/`makeResizable`）。它**优先复用在屏上已经画好的那张**（看板格子的 option / 预览的 option / 已存的 Matplotlib 图），
