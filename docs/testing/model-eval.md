# 本地模型的工具路由评测（2026-11-24 实测）

> 工具选择是小模型在这套工作区里最常做、也最容易做错的一件事：37 个工具、一句话描述、只许挑一个。
> 这个评测问的就这一件事，所以它同时是**描述质量**的度量：模型的错，多半是描述的错。

## 方法

`tools/eval_tool_routing.py`：

1. 从 `ai.tools.TOOLS` 生成工具清单（名字 + 描述第一句），加上四个控制工具；
2. 依次问 26 条真实用户原话（中文，带数据/运行/工作流/模型/源码/装环境等场景），要求**只回答工具名**；
3. 取回答里第一个已知工具名计分；`temperature=0.1`，`max_tokens=64`；
4. 有两条任务接受两个正确答案（例如“先看看长什么样”可以 `dataset_peek` 或 `dataset_profile`），
   把一条合法答案判错会测出评测的毛病，而不是模型的。

复现（需要 `ollama serve` 与已拉取的模型，不消耗任何账号）：

```bash
python tools/eval_tool_routing.py --model qwen3.5:4b
python tools/eval_tool_routing.py --model qwen3.5:4b --model qwen3.5:9b --model qwen3.5:2b --json docs/testing/model-eval.json
```

## 结果（本机，26 条）

| 模型 | 命中 | 说明 |
|---|---|---|
| `qwen3.5:9b` | **26/26** | 全中 |
| `qwen3.5:4b` | **26/26** | 全中——严格模式默认的 12 工具预算就是给这一档定的 |
| `qwen3.5:2b` | **24/26** | 两处：见下 |

`qwen3.5:2b` 的两处错误：

| 任务 | 期望 | 实际 | 读法 |
|---|---|---|---|
| `peek-first`（“先给我几行看看”） | `dataset_peek` / `dataset_profile` | `dataset_page` | 描述里 `dataset_page` 也说了“peek 不够时”，2b 把“看一眼”读成了“翻页”；`dataset_peek` 的第一句可以更硬（“最便宜的一眼，默认 5 行”） |
| `rerank`（“把三条候选按相关性排序”） | `model_rerank` | `ask_user_question` | 直接跑偏到控制工具：2b 对“排序”这种介词短语缺少锚点，属于模型能力问题而非描述问题 |

## 这组数字怎么用

- **严格模式（`tools.strict_local`）的 12 工具预算**：目标“≥80% 有据”，4b/9b 在本组上 100%，2b 92%，
  所以这条目标按本组任务成立；任务集偏“工具边界清晰”，不能外推成“任何说法都能选对”。
- **改描述前先跑一遍**：一处描述改动可能让 2b 从 `dataset_peek` 滑到 `dataset_page`，数字会告诉你。
- **不作为通过/失败门禁**：它需要模型、跑得慢、且是本机读数；进 CI 只会变成一条被跳过的测试。

## 已知局限

- 26 条是**人工挑的清晰场景**，没有覆盖“一句话里两个动作”“用户说错列名”“工具不可用（云端没有源码工具）”
  这类更难的分布；扩展它比改算法更值得先做。
- 只测“选哪个工具”，不测参数是否正确；参数正确性由各工具自己的单测与拒绝路径覆盖。
- **它测的是“工具全在列表里时模型选得对不对”，不是严格模式的裁剪**。裁剪是另一层，2026-11-24 量出它
  当时是坏的（27 个工具、0 个技能工具），已修：技能自有工具现在是预算的地板，通用动词在中文提问下
  只能按名字排（词法无信号）。细节见 `docs/architecture/w7-incremental.md` 第 4 节。
