# 为什么这三类分析用「微调 BERT」而不是通用大模型

本项目的情感 / 倾向 / 情绪三个分析节点，`bert`（**微调中文 BERT**，本机 `hfl/chinese-roberta-wwm-ext` 系）
是**默认且主推**的档位（`llm` 逐行走 Ollama/OpenRouter 大模型、`ml` 走 sklearn TF-IDF + 逻辑回归是另两档；
情感极性还多一档 `snownlp`，见下）。这份文档专门回答：**放着大模型不用，为什么偏要自己微调一个小 BERT？**
与 `docs/analysis.md`（各模式的功能说明）、`docs/tendency_model_comparison.md`（倾向编码器实测选型）互补——
那两份讲"是什么/怎么调"，这份讲"为什么"。

## 一句话结论

- 对**封闭标签集的逐行分类**（情感二/多类、情绪六类、立场六类），微调 BERT 在**质量、速度、成本、确定性**
  四个维度同时占优：一个 ~400MB 的模型在本地一次前向就出一整批标签，比每行让 9B 大模型自回归"说"一个词
  快若干个数量级，且在固定标签集上并不比通用大模型差——因为我们的标注本就来自大模型蒸馏。
- 需要**深度判断**（主题相关性、语义清洗、跨行结论段落、指代/讽刺的语境推理）时，`llm` 模式仍是正确的选择。
  BERT 不取代它，二者分工。

## 这三类任务的形状

| 维度 | 事实 | 后果 |
|---|---|---|
| 标签集 | 封闭、固定（如情绪 6 类、立场 6 类、情感 正/负） | 是**分类**，不是生成；输出是标签之一，不是自由文本 |
| 数据量 | 单事件常见数千到数十万条评论 | 逐行方法只要每行成本非零就会放大成小时级 |
| 确定性 | 同一行每次必须给同一个标签（续跑/指纹/缓存的前提） | 采样式的自由文本输出是负担，不是特性 |
| 可离线 | 单机、单用户工具，不应强依赖联网 API | 本地推理优先 |

这四条正好是微调 BERT 的甜点区，也是通用大模型的短板区。

## 与「通用大模型」的对比——为什么"通用的比不过专用的"

| | 微调 BERT（分类） | 通用大模型（qwen3.5:9b / Jev 类等自回归 LLM） |
|---|---|---|
| 质量来源 | 学的是"大模型在这一固定标签集上的判断分布"——窄任务专门拟合，**追平**老师且远比老师便宜 | 通用开放对话更强，但这里没有开放对话：六选一、答案空间极小 |
| 每行计算 | **一次前向**，序列 ≤512 token，输出=各类概率，与输出长度无关 | **自回归生成**：逐 token 解码，成本随输出 token 数线性涨 |
| 输出可控 | `pipeline('text-classification')` 直读 `id2label`——结构化类别概率，不解析自由文本 | 每行正则出标签，模型偶尔"发挥"就多一个 token、导致下游解析错位 |
| 批处理 | 原生 batch，GPU 上吞吐极高 | 逐行 prompt+解码往返；批量仍受解码瓶颈 |
| 常驻开销 | ~400MB 权重，fp16 + batch 16 在 8GB 显存即跑（`docs/analysis.md` 情感节） | 9B 级权重要常驻 daemon（Ollama），GB 级显存/内存 |
| 每行网络 | 无（进程内调用 transformers） | 每次走本机 HTTP 到 daemon（`llm_client`），逐行往返 |
| 断点/缓存 | 不需要——快到直接整列重算也不心疼 | 才需要昂贵的 LLM 答案缓存 + 逐行检查点来摊薄成本 |

三点关键：**(1) 质量**——本项目的倾向/情绪标签**本来就是大模型蒸馏来的**（`docs/analysis.md`：qwen3.5:4b 在
26 万条真实微博上逐条打六类标签，产出 `tendency_distilled.csv` 再微调），所以 BERT 在窄任务上逼近老师、且便宜；
**(2) 可控**——BERT 天然按名读 `id2label`，不存在自由文本漂移；**(3) 新 ≠ 好**——参数量大不等于窄标签集上更好，
却几乎一定等于更慢（`docs/tendency_model_comparison.md` 已实测：换更新的 `gte-base-zh` 骨干**反而退步**，英文
ModernBERT 的 tokenizer **中文直接失效**）。一句话：分类只要"看一眼、报个类"，一次前向就够；大模型是
"一个字一个字把答案说出来"，同任务天然慢若干个数量级——尤其当数据是几万条评论时。

## 实测质量数据（本机，可复现，全部来自仓库内记录）

> 以下数字均**实测**，非估算；每行标了它读自哪个语料/划分——同一个模型在 5% 留出与编码器对比 dev 上是两个数。

| 任务·模型 | 训练语料 / 划分 | 指标 | 出处 |
|---|---|---|---|
| 情绪 `emotion_ewect_six` | EWECT `usual_train` 通用微博 27,766 条，3 epoch，5% 留出 | **accuracy 0.811 / macro-F1 0.792** | `docs/analysis.md` 情绪节 · `ml_train/README.md`（2026-10-06） |
| 情感 `sentiment_weibosenti_bin` | `weibo_senti_100k`，3 epoch，5% 留出 | **accuracy = macro-F1 = 0.9785** | `docs/analysis.md` 情感节（2026-10-06） |
| 立场 `tendency_stance_v1`（蒸馏基线，对照） | `tendency_distilled.csv` 两轮蒸馏约 7,720 条，3 epoch，5% 留出 | **accuracy 0.731 / macro-F1 0.681** | `docs/analysis.md` 倾向节 · `ml_train/README.md`（2026-10-06） |
| 立场 `tendency_stance_v2_cyberbully`（推荐，wwmext+类权重） | 编码器对比 dev（seed 42，5%） | macro-F1 0.668 / Controversy F1 0.452 | `docs/tendency_model_comparison.md` §2 |
| 同上，并入 batch1 真实数据后 | 8,208 条重训，同一 dev | macro-F1 **0.681** / Controversy F1 **0.537** | `docs/tendency_model_comparison.md` §7.3 |

诚实边界（同见 `tendency_model_comparison.md` §6）：稀有类（`Controversy`）与反讽（`Satire`）仍是最弱两格；
蒸馏受限于老师的判断，不是无条件优于大模型——但在**这个固定标签集 + 这个速度/成本约束**下，它"完全满足需求"。

## 实测吞吐（本机 GPU，可复现）

一次**本机 GPU 实测**（测量探针 `backend/test_bert_throughput.py` 是一次性脚本、已删除；下列数字保留为带日期的
实测记录，结果形状由仓库内测试钉住）。**驱动的是生产代码路径**——`TendencyAnalyzer` / `EmotionAnalyzer` /
`SentimentAnalyzer` 在 `mode='bert'` 下、生产批量 `BERT_BATCH=32`、`truncation=True, max_length=512`，
对一份**真实微博文本**整列跑，所以这个数就是分析节点实际付的价，不是手调的最佳情形。模型加载的一次性耗时
**单列**，不混进吞吐。

**测试条件（缺任一项这个数就不可审计）：**

| 项 | 值 |
|---|---|
| 设备 | NVIDIA GeForce RTX 4060 Laptop GPU（8.6GB） |
| torch / transformers | 2.14.1+cu126 / 5.13.0 |
| dtype | fp32（生产 `pipeline` 默认，未显式半精度） |
| batch / max_len | 32 / 512 |
| 数据 | `ml_train/datasets/tendency_distilled.csv` 的 `text` 列，**8,208 行真实微博** |

**结果（warm 整列批推）：**

| 模型 | 整列 8,208 行耗时 | 吞吐 | 冷加载+热身(256行) |
|---|---|---|---|
| 立场 `tendency_stance_v2_cyberbully` | 34.79 s | ≈ 236 rows/s | 7.34 s |
| 情绪 `emotion_ewect_six` | 34.22 s | ≈ 240 rows/s | 1.77 s |
| 情感 `sentiment_weibosenti_bin` | 34.71 s | ≈ 237 rows/s | 1.77 s |

即本机约 **230–240 条/秒**（≈4 ms/行有效，三模型均值 ≈237 rows/s），三个模型几乎一致（同骨干、同 8,208 行同文本，
互相印证不是噪声）。**换算**：2 万条评论约 1.5 分钟、10 万条约 7 分钟跑完整列——对续跑/成本敏感的工作流完全够用。
换更快的桌面卡或 fp16/更大 batch 还会更高，换 CPU 则低一个量级。此数绑定上表环境，别当普适承诺。

**对照大模型侧（qwen3.5:9b 等，同一 `LLMClient`、同一 GPU、串行逐行；Ollama 节点本就 `workers=1`，
串行即生产形状）**：取同一份真实微博文本前 25 行，提示约束成"只回一个类别词、不解释"，逐行调用计时（冷加载一次已剔除）：

| 后端 | 吞吐 | 同一 8,208 行整列墙钟 |
|---|---|---|
| 微调 BERT（三模型均值） | ≈4 ms/行（≈230–240 条/秒，见上） | **≈ 35 s** |
| qwen3.5:9b（串行逐行） | ≈ 0.29 rows/s（≈3.4 s/行） | ≈ 8 小时 |
| qwen3.5:4b（串行逐行） | ≈ 0.31 rows/s | ≈ 7 小时 |

约 **800 倍（~2.9 个数量级）** 的差距，正解释了本项目为何走"LLM 蒸馏 → 微调 BERT"：让 9B 给几万条评论逐行打标签要
**小时到整天**，微调 BERT 几**十秒**扫完——所以蒸馏只在离线做一次，线上跑 BERT。诚实标注：这是**串行、单条、
输出约束极短**的 N=25 样本（大模型开思考链/更长输出会更慢，能批处理/并发则略快，绝对值随配置浮动），
但一到两个数量级的差距由计算形状决定、稳。qwen3.5:4b 与 9b 实测几乎同速，说明瓶颈是自回归解码/daemon 往返本身，
而非参数量。"Jev 类模型"具体所指未确证，未替它测/编数。

## 什么时候仍应该用 `llm` 模式（不越俎代庖）

- **主题相关性判断 / 语义清洗**：BERT 分类器只做它被训的标签，判断"这条离题吗""这是广告吗"是 LLM 的职责
  （`docs/analysis.md` 清洗节：留空默认走 `llm`）。
- **跨行结论、摘要、报告段落**：需要生成，不是分类。
- **一次性、探索性的深度逐行分析**：量小、要模型"想一想"给细致判断时，`llm` 更合适；量大到需要续跑/成本可控时切 `bert`。

`ml`（sklearn）档是"连 BERT 都不想加载"时的极轻量批推（纯 CPU、无 torch），质量低于微调 BERT，作为兜底。

## 诚实边界

- 微调 BERT 的上限受蒸馏老师约束；稀有类/反讽仍弱，见上。
- **默认就是 `bert`**（`emotion`/`tendency`/`sentiment` 三个节点的 `mode` 默认均为 `bert`，见
  `services/analysis/process.py` 的 `PROCESS_ENUMS`）。当 `bert` 真的跑不动时（缺 `torch`/`transformers`
  或无注册模型可解析），**节点执行器会挑一个免依赖的回退档并打印本次实际用了哪种**：`emotion`/`tendency`
  降到 `ml`，`sentiment` 降到 `snownlp`——绝不静默把 A 模型的结论写进 B 模型声称的列。而**分析器被直接当
  `bert` 调用**（不经执行器降级）时缺依赖仍**按名拒绝**；勾 ≥2 模型的多模型对比**不降级**、维持按名拒绝。
  这符合 AGENTS「被批准的降级必须打印实际方法」的规矩，与"绝不静默冒充"是一件事的两面。
- **吞吐**：BERT 侧与大模型侧**均已本机实测**（RTX 4060 Laptop，见上表与上文的倍数换算；数绑定该环境，别当普适承诺）。
