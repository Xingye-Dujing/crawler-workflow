# 为什么这三类分析用「微调 BERT」而不是通用大模型

本项目的情感 / 倾向 / 情绪三个分析节点都有三档后端：`llm`（逐行走 Ollama/OpenRouter 大模型）、`ml`（sklearn TF-IDF + 逻辑回归）、`bert`（**微调中文 BERT**，本机 `hfl/chinese-roberta-wwm-ext` 系）。`bert` 是本项目**实际主推**的档位。这份文档专门回答：**放着大模型不用，为什么偏要自己微调一个小 BERT？** 与 `docs/analysis.md`（三模式的功能说明）、`docs/tendency_model_comparison.md`（倾向编码器实测选型）互补——那两份讲"是什么/怎么调"，这份讲"为什么"。

## 一句话结论

- 对**封闭标签集的逐行分类**（情感二/多类、情绪六类、立场六类），微调 BERT 在**质量、速度、成本、确定性**四个维度同时占优：一个 ~400MB 的模型在本地一次前向就出一整批标签，比每行让 9B 大模型自回归"说"一个词快若干个数量级，且在固定标签集上并不比通用大模型差——因为我们的标注本就来自大模型蒸馏。
- 需要**深度判断**（主题相关性、语义清洗、跨行结论段落、指代/讽刺的语境推理）时，`llm` 模式仍是正确的选择。BERT 不取代它，二者分工。

## 这三类任务的形状

| 维度 | 事实 | 后果 |
|---|---|---|
| 标签集 | 封闭、固定（如情绪 6 类、立场 6 类、情感 正/负） | 是**分类**，不是生成；输出是标签之一，不是自由文本 |
| 数据量 | 单事件常见数千到数十万条评论 | 逐行方法只要每行成本非零就会放大成小时级 |
| 确定性 | 同一行每次必须给同一个标签（续跑/指纹/缓存的前提） | 采样式的自由文本输出是负担，不是特性 |
| 可离线 | 单机、单用户工具，不应强依赖联网 API | 本地推理优先 |

这四条正好是微调 BERT 的甜点区，也是通用大模型的短板区。

## 与「通用大模型」的对比——为什么"通用的比不过专用的"

**1）质量：标签是老师给的，学生能逼近老师。** 本项目的倾向立场标签**本来就是大模型蒸馏来的**（`docs/analysis.md` 倾向节：用 qwen3.5:4b 在 26 万条真实微博上逐条打六类标签，产出 `tendency_distilled.csv`，再微调 `chinese-roberta-wwm-ext`）。也就是说，微调 BERT 学的是"大模型在这一固定标签集上的判断分布"——它在一个**窄任务**上专门拟合，往往在这个窄任务上**追平**通用模型、且**远比通用模型便宜**。在**通用开放对话**上大模型更强，但这里没有开放对话：问题是六选一，答案空间极小，专用小模型够用。质量数据见下一节（全部本机实测）。

**2）输出可控、无漂移。** `bert` 走 `pipeline('text-classification')` 直接读模型的 `id2label`——标签是**结构化的类别概率**，不是要解析的自由文本；不存在"多写一句解释/标点/换行导致下游解析错位"。而 `llm` 每行要正则出标签，模型偶尔"发挥"就多一个 token。分析器对不认识的标签一律**按名拒绝、绝不臆造**（`docs/analysis.md` 反复强调的"付过学费的 bug 形态"），BERT 后端天然满足这条。

**3）与"新出的大模型"（本项目 LLM 模式用的 qwen3.5:9b，以及近期新出现的 Jev 类等模型）相比——质量没有代差，速度有代差。** 参数量大 ≠ 在我们的窄标签集上更好；参数量大 = 每行要生成的 token 更多、显存占用更大。这一点直接体现在速度上。

## 与「大模型」的速度对比——为什么响应比 BERT 慢得多

这不是经验玄学，是两种模型的**计算形状**决定的：

| | 微调 BERT（分类） | 通用大模型（qwen3.5:9b / Jev 类等自回归 LLM） |
|---|---|---|
| 每行的计算 | **一次前向**，序列 ≤512 token，输出=各类概率，与输出长度无关 | **自回归生成**：逐 token 解码，要吐完"标签（+可能的解释）"才结束，成本随输出 token 数线性涨 |
| 批处理 | `pipeline` 原生 batch，一批一次前向，GPU 上吞吐极高 | 逐行 prompt+解码往返；批量也要排队生成，解码是瓶颈 |
| 常驻开销 | ~400MB 权重，fp16 + batch 16 在 8GB 显存即跑（`docs/analysis.md` 情感节） | 9B 级权重要常驻 daemon（Ollama），GB 级显存/内存 |
| 每行网络 | 无（进程内调用 transformers） | 每次走本机 HTTP 到 daemon（`llm_client`），逐行往返 |
| 断点/缓存 | 不需要——快到直接整列重算也不心疼 | 才需要昂贵的 LLM 答案缓存 + 逐行检查点来摊薄成本 |

一句话：分类只要"看一眼、报个类"，一次前向就够；大模型是"一个字一个字把答案说出来"。在同一任务上后者天然慢若干个数量级，尤其当数据是几万条评论时。

## 实测吞吐（**待补**）

**本节故意留空，绝不凭空填一个数字。** AGENTS 的硬规则：一个被引用的数必须报它**测了多少、在什么条件下测的**；编造的"每秒 N 条"比没有更糟。本机当前无法测量，原因是真实的、可核查的：

- **BERT 吞吐测不了**：`torch`/`transformers` 是**可选依赖**（列在 `requirements-optional.txt`，从不装进 `.venv`、也不进 CI——见 `AGENTS.md`/`docs/development.md`），本环境未安装，故此刻无法跑一次真实推理计时。
- **大模型延迟测不了**：本次 Ollama 未开启，`qwen3.5:9b` / Jev 类模型的每行耗时同样无法在此实测。

**在你的机器上如何测出这个数（得到可写入本节的实测）：**

1. 装可选依赖：`.venv/Scripts/pip.exe install -r requirements-optional.txt`（torch + transformers）。
2. 写一个一次性探针（仓库惯例：`backend/test_*.py` 是"一次性测量的合法归宿"，非 pytest），例如 `backend/test_bert_throughput.py`：加载注册表里某个模型（如 `ml_train/models/sentiment_weibosenti_bin`，见 `data/model_registry.json`），取一份现成 CSV 的一列文本，分批跑 `pipeline`，计时并打印 **rows/sec**。
3. **报告测了多少**：至少上千行、注明 `batch_size`、`max_seq_len`、是否 `fp16`、CPU 还是 GPU（型号）、行数与总耗时——缺任何一项这个数都不可审计（本项目有过"用真实时钟测一个小于 16ms 的量是掷硬币"的教训）。
4. 要对比大模型延迟，在同一机器上对同样 N 行走一遍 `llm` 模式（需 Ollama 运行），把 `llm` 的 rows/sec（或每行秒数）与 `bert` 并排记下。
5. 把两组实测填回本节，并在 `docs/development.md`/`AGENTS.md` 需要处保持一致。

预期量级（**不作为结论，仅供填数后核对是否离谱**）：BERT 在 GPU 上分类吞吐通常在**数百到数千条/秒**（取决于序列长度与显存），而 9B 级自回归 LLM 单卡逐行分类通常在**每秒几条到几十条 token 级**——两者相差常在一个数量级以上。真实数字以你测出的为准。

## 什么时候仍应该用 `llm` 模式（不越俎代庖）

- **主题相关性判断 / 语义清洗**：BERT 分类器只做它被训的标签，判断"这条离题吗""这是广告吗"是 LLM 的职责（`docs/analysis.md` 清洗节：留空默认走 `llm`）。
- **跨行结论、摘要、报告段落**：需要生成，不是分类。
- **一次性、探索性的深度逐行分析**：量小、要模型"想一想"给细致判断时，`llm` 更合适；量大到需要续跑/成本可控时切 `bert`。

`ml`（sklearn）档则是"连 BERT 都不想加载"时的极轻量批推（纯 CPU、无 torch），质量低于微调 BERT，作为兜底。

## 与"新 ≠ 好"的呼应

`docs/tendency_model_comparison.md` 已实测：换更新的 `gte-base-zh` 骨干**反而退步**（macro-F1 0.597 < 0.644），英文 ModernBERT 的 tokenizer **中文直接失效**。同一份谨慎适用于"最新大模型"——在我们的窄标签集上，新的更大的通用模型不自动等于更好，却几乎一定等于更慢。选型看的是**这个任务上的实测**，不是发布日或参数量。

## 诚实边界

- 微调 BERT 的上限受蒸馏老师约束；稀有类/反讽仍弱，见上。
- `bert` 是**可选**档：缺 `torch`/`transformers` 一律**按名拒绝**、绝不回退到 `llm`/`ml`（把 A 模型的结论写进 B 模型声称的列是本项目的 bug 形态）。默认后端仍是 `llm`，老画布不受影响。
- 本文件的**吞吐对比尚未实测**，理由如上；填入真实数字前，速度一节只讲**计算形状的结构性差异**，不报数。
