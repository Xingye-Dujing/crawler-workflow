# 工作流引擎 · 断点续跑 · 界面 · 节点类型

> 本文是采析绘文档的一部分，返回总览见 [README.md](../README.md)。

画布与工作流引擎、断点续跑与运行记录、界面行为的详细说明，以及全部节点类型参考表。

## 工作流引擎
- **工作流画布**：拖拽式节点编辑，可视化配置采集/清洗/分析/可视化全流程
- **画布历史（命名快照）**：底部「工作流文件」面板「画布历史」页签。保存当前画布时可取一个可选名字，存进
  `data/workflow_history.db`（`canvas_snapshots`），与工作流文件**互不影响**；列表按保存时间倒序。点「恢复」先取回快照并
  与当前画布做差异（列出会回来/消失的节点、连线增减与位置变化数），确认后才走
  `workflow.loadFromJSON(..., {history:'single'})`，**整次恢复只记一个撤销点**；快照名可事后**重命名**；删除一条快照会同时清掉
  指向它的布局基准。上限 100 份，存满时服务端**按名拒绝**；快照保存的是**文件形状**，可复用节点的折叠/展开状态会一起回来。
- **项目包迁移**：底部「工作流文件」面板顶部可**导出项目包**（当前或全部工作流）——zip 内是 `manifest.json` + 工作流 JSON +
  引用的数据集（列名与记录）+ 引用的可复用模板；不含 Cookie、API key、模型权重、运行日志。**导入**时数据集/模板重新分配 id
  并改写工作流里的引用，同名自动加 ` (2)`，绝不覆盖；zip 版本、校验和、路径、解压体积、结构都会先校验，任一项不对按名拒绝。
  缺失数据集在导出时拒绝；缺失模板只作警告（实例自带模板快照）。
- **自动排布的两个策略**：「自动排布」可选「算法排布」或「按历史基准恢复」。基准按**已保存工作流名**单独存（`layout_baselines`）；
  未保存草稿不能设基准（按名拒绝）。基准策略先跑一遍算法，再把基准快照里**同 id 节点**的位置覆盖上去（基准没见过的后加节点仍由
  算法摆放）；基准快照被删后显示「基准快照已不存在」并拒绝执行。基准只恢复**位置**，不改内容。
- **可复用节点（一个盒子里的子图）**：选中一组节点（允许 process/analysis/visualize/tokenize/biblio/fuse/output/compile，
  不允许 source/upload/comment/resume/name/可复用节点本身——这些要么自带会话/数据集，要么属于画布机制）后右键「创建可复用节点」：
  服务端验证后存成 `data/reusable_nodes/<id>.json`，画布把选中节点收成一个 `reusable` 节点并重接外部连线。模板可从「插入可复用
  节点」选回，实例把模板快照存在节点参数里，所以模板后来被删/改都不会悄悄改掉旧实例。
  - **多条输入**：组左端口可接多条上游线，按 `canvas.connections` 落线顺序对应模板 `inputs` 的第 1、2… 槽；输入槽数与接线数
    不一致时运行前**按名拒绝**（少接或多接都拒绝），不猜映射。
  - **折叠/展开**：折叠时只占一个普通节点，运行角标取内部所有节点汇总（running 优先，其次 failed/partial，全部 settled 才算
    done）；展开时内部节点按模板位置只读呈现，但组节点始终是**一个顶层模型节点**，内部节点不进 `canvas.nodes`。
  - **展开时自动排布**：默认开；展开后立即排布一次，避免变大的块遮住旁边节点。无论开关，自动排布都把展开组按**实际测量尺寸**
    当作一个块。
  - **运行展开**：`canvas.toWorkflowJSON()` 默认把组展开成 `<组id>__<内部id>` 真实节点；文件保存改用 `{expandReusable:false}`
    保留组本身。**定时任务从文件启动时服务端也会先展开**（`services/workflows/expand.py`），规则与浏览器一致。
  - **解包编辑**：组设置面板与右键都有「解包为普通节点」，整次解包是**一个撤销步骤**；模板文件不删除；外部连线多于输入槽按名拒绝。
  - **模板管理**：「工作流文件」面板「可复用节点」页签列出 `data/reusable_nodes/` 模板，可**预览/插入/重命名/删除**；重命名只改名，
    删除只删模板文件（已插入实例保留自己的快照）。模板行左侧拖到画布落点插入，与「插入」按钮共用 `insertTemplateAt`。
  - **当前边界**：内部节点默认只读（解包后可编辑）；模板重命名不改内部节点。
- **版面约束**：窗口与页面级**绝不出现水平滚动条**；面板内表格可横向滚动，但被截断的单元格必须带省略号（静默裁掉等于让用户读不到
  数据）；顶栏放不下时**靠左锚定并显式留出一条细滚动条**（居中加隐藏滚动条最坏：滚不到负方向溢出）；节点设置与 Cookie 面板加高度
  上限，超长表单自己滚动；下拉单选行也带省略号、完整文字挂在 title 上。中英文两种语言与 1920/1366/1024 三档宽度都在真 Chrome 里量过。
- **参数只有"读懂"和"点名拒绝"两种下场**：凡是选数据、选花费或起名字的参数——采集内容里的**榜单**与**分片格式**、清洗步骤的
  **列名/筛选条件/类型/填充方式**、AI 处理的 **method**（TF-IDF / TextRank）与 **mode**（大模型 / 本地模型）——只接受面板给出的
  那些写法。空着＝没选过，按面板默认值跑；写了列表外的名字，节点**失败并把原因与可选项一起送出来**，不再悄悄改做另一件事。
- **勾选框两种写法都认**：面板历史上把"没勾"写成文本 `'false'`，而 `bool('false')` 是 True，所以以前**取消勾选反而等于勾选**；
  现在按值读取（`core.refs.as_bool`），两种写法（`'false'` 与 `false`）含义一致，「升序」也不再被反转。
- **面板不再持有第二种意见**：节点里存着一个列表外的值时，下拉框过去会因为"没有一个 option 匹配"而显示**第 0 项**；现在把节点
  真正持有的那串原文作为一个"不是可选项"的条目显示出来（`selectOptionTags`/`boolParam`），改选即可。勾选框同理按值读取、写回统一布尔。
- **运行记录带「运行时长」**：每条运行按 `finished_at − started_at` 记一段耗时（`MM:SS`，一小时以上 `H:MM:SS`）。续跑从不刷新
  `started_at`，所以它是**整条工作从头到尾的总墙钟时间**；仍在运行的显示破折号而不是 0。详情卡片里每个节点也各自带一段。
- **界面等回答，也认回答落地时的那张表**：运行记录详情、续跑下拉、工作台网格都是"发请求 → 等回复 → 写进界面"，这期间面板会刷新，
  被抓住的行/容器可能已不在页面上。三处都改成**等回来之后再按 id 重新找一次**，找不到就什么都不写——以前答案写进一个脱离文档的子树，
  屏幕上什么都没有。
- **底部五面板互斥**：控制台、运行记录、导出产物、数据集管理、工作流文件共用同一个底部槽，打开任一个都会收起另外四个并清掉残留
  内联高度；五个面板都可拖高。
- **条目"锁"（导出产物 / 运行记录 / 工作流文件）**：每行一个 🔒/🔓 按钮。锁住的条目**在「清空」时被跳过、单独删除时被点名拒绝（409）**，
  直到用户先解锁。锁状态存 `data/locks.json`，界面只在启动时读一次、点锁时本地翻转；服务端是唯一裁判，绕过界面直接 POST 删除也删不掉被锁项。
- **导出产物·论文成稿（LaTeX PDF）**：报告对话框多一个按钮，请求体只有 `run_id` 与标题——**图与三线表由服务端从这次运行已登记的
  LaTeX 源文件里读回来**（浏览器不上传任何 LaTeX 源码，否则 xelatex 就成了一条读任意文件的路）。产出 `article`+`ctex` 一份文档：
  方法段（逐节点参数，只从**已保存画布**读并与运行指纹核对，核不上就点名说没核上）+ 图 1/表 1/图 2/表 2 ……（`[H]` 钉位）+ 运行编号
  与时间窗；**先写 `.tex` 再编译**，编译器拒绝时留下的正是那份可排查的源文件，且绝不留半份 PDF。产出的 `.tex` 与 `.pdf` 都记回台账。
- **导出产物·智能清除**：面板顶部除「清空」外多了两个**按来源**的批量清除：「按运行清除」删某次运行产生的**全部**文件，「清除分片」
  只删某次运行里某个数据源节点爬出的**分片文件、保留合并文件**。二者靠 `runs.db` 里的「运行→文件」台账（`run_files`）定位——文件名本身
  不可靠，只有登记过的才知道属于哪次运行。清除**跳过「固定」条目**、**有运行在跑时 409 拒绝**，删成功的名字同步从台账遗忘；
  「按运行清除」只清磁盘产物，不动运行记录与已存的行。
- **刷新页面不再丢掉控制台**：页面启动时问一次 `/api/workflow/status?tail=…`（`tail` 缺省 200 行，重连时按保留上限 5000 行索取），
  把这一轮已写过的行整段重放：运行还在跑就接管轮询、并行分栏一起重建；已跑完就只重放与落一句状态，**不重发结束 toast、不再开续跑横幅、
  不自动弹开控制台**。重放会把每个视图的游标推到服务端总数上，所以紧接着的轮询只补新行。轮询定时器只有一个所有者（`workflow._pollTimer` + `_stopPoll()`）。
  边界要说清楚：**实时控制台仍只在内存里**（`execution_state['logs']`，保留 5000 行，重启即空）；但**控制台文本另外按运行号持久化**进 `runs.db`
  的 `run_log` 表（每条物理行都存，随运行删除/purge 级联回收），事后都能在「查看运行日志」里翻回来（按级别/工作流标签过滤、搜索、加载更早、
  下载 .txt）；这条路只读持久表、绝不碰 `execution_state`。`logs/app.log` 是又一条通路（进程级、不带运行号）。
- **控制台的两条读法约定**：① **切换工作流标签页不再清空日志**——服务端只保留整次运行最后 200 行，所以每个标签页在浏览器里各自留一份
  已显示历史，切回来按自己历史重画，游标各自前进，最多各留 500 行。② **「工作流命名」「上传文件」节点不再播报执行信息**——被压掉的只有
  那两句套话，上传节点"已载入 xxx.csv：N 行"以及任何失败/跳过/复原的原因照旧送出。
- **中止运行不再喷出传输层红字**：按「停止」会杀掉 chromedriver，被杀那刻在途的 HTTP 命令由 selenium 的 urllib3 连接池重试死端口，
  冒出「Connection pool is full…」「Retrying (…)」几行——它们不描述任何真实失败。现在控制台按 logger 名把 `urllib3.*`（和 `werkzeug`）
  过滤掉（文件日志仍原样保留），真出错的运行仍由执行器那句「节点 X 执行失败」点名说明一次。
- **可选：每次运行前清空控制台**（默认关）：开启时新运行把控制台清成空白——连各工作流标签页连同各自保留的历史一并删除。
- **可选：慢速采集（降风控）**（默认关）：开启后所有采集**只是放慢节奏**——DOM 走查与评论面板逐屏之间停顿统一乘以 `GENTLE_PAUSE_FACTOR`
  （现取 4×），关掉完全是现网行为。它**不碰浏览器身份、不伪造指纹、不做反检测伪装**——降风控靠退避少给触发阈值的机会，不是伪装。
- **界面四处修正**：① Cookie 面板那行"哪个平台存了 Cookie"以前固定印 `zhihu: OK`（有文件 ≠ 会话还有效），现在逐平台用界面语言说
  「已存 Cookie / 未存」；② 凡是"要丢东西"的确认不再用浏览器原生 `confirm`，改回页面自己的对话框；③ 断点续跑横幅钉住显示时向下让开
  整条菜单高度；④「导出产物」的"共 N 个文件，合计 X"改成表格下方的居中总结行。所有"平台名"位置统一：`zhihu` 是矩阵与 Cookie 文件的
  **键**，不是给用户看的词——控制台 `{platform}` 由后端翻译，前端弹窗同一份词表，两处由 `TestPlatformLabelParity` 钉住相等。
- **工作流命名**：保存时可命名（画布 Name 节点即工作流名），历史与运行记录按名称归组；同一节点还带一个「排布顺序」数字，供「自动布局」
  决定这条工作流排在画布上方还是下方。
- **运行队列**：一次只跑一个运行是这套设计的前提，但"忙"不再等于"白按一次"——运行中再按「执行」，按钮变成「排队运行」，请求被服务端
  存下，当前运行结束后自动接着跑；排队列表显示在「运行记录」面板顶部，可逐条取消（最多 8 个，满了直接拒绝）。队列只在服务进程内存活。
- **多线程执行**：支持并行/串行执行模式，可随时停止；进程管理面板可强杀残留浏览器进程。「停止」之后要**等自己启动的节点线程真的退出**
  才交还运行槽（旧写法 `shutdown(wait=False)` 会让被停掉那次的最后一个节点往下次运行的控制台、计数与 results 里写）。
- **「停止」现在就地把运行记录翻成「正在停止」**：浏览器在后台并行收，但**记录的状态不跟着一起等**：停止请求自己写 `stopping`，worker
  到点再用真实结论覆盖它。抓取一侧每一行入库前都要问一次「可以停了吗」，被停掉的那次运行写成「被停止」而不是「失败」，已付过费的行照旧保留、
  照旧可续跑。
- **停止之后到底要等多久，是真机量出来的**（测量脚本 `backend/test_stop_real.py`、`backend/test_dead_driver.py` 已归档为结论，探针数据见
  `docs/crawler_notes.md`）：按「停止」后**记录不再说「运行中」用 0.005~0.009 秒**；worker 定档——卡在首屏导航约 5.3 秒、走查中途原为
  28.7~29.6 秒。**拖时间的是被杀后 selenium 连接池对无人监听的端口逐条重连**（吃 urllib3 默认 `Retry(total=3)`，约 16.3 秒/条）；
  现在强杀成功后 `crawler.driver` 会换成一个"死驱动"会话：**任何命令立刻抛 `CrawlerStopped`**（实测 0.00 秒），于是一次被停掉的抓取只花
  那一条在飞的命令。**修完重测**：走查中途那一次停止，worker 定档从 28.7~29.6 秒降到 **4.35 秒**。顺带修掉一个真 bug：本地 Ollama 的
  `timeout=300` 以前根本没接到连接上（`ollama.Client` 把 `None` 交给 httpx 含义是"永不做超时"），现在接上了，最坏从"永远"变成可算的 600 秒。
- **「页面没到」和「站点不给看」从此是两句话**：一页的**首屏内容**等 `Config.PAGE_WAIT_TIMEOUT` = 300 秒（`Crawler.wait_for_first_content`），
  而"滚动后有没有新行"的 14/12/3 秒不变——那是进度判据。等待本身**三件事都做**：每一拍问一次「可以停了吗」、看到墙或浏览器自己的错误页就立刻
  收尾、同一浏览器连着两次没拿到页面就**不再付第三次**。到点仍拿不到内容时，控制台同时给出 等了多久 + 哪个节点 + 本机网络的实测诊断
  （`services/ingest/net.py` 用两个对照主机把结果分成 区域不通/本机断网/站点侧连不上/单纯没渲染 四种；最后一种**不许**指出原因）。
  已入库的行全部保留，节点按有无行记 partial/failed。
- **判定一页的第四种说法**：`crawlers/engine/wall.classify` 现在答 `ok` / `login` / `blocked` / **`unreachable`**。第四种是浏览器自己拒掉的
  导航——实测文档写着 `chrome-error://chromewebdata` 带 `ERR_NAME_NOT_RESOLVED` 之类机器码，而 `driver.current_url` 仍显示被请求的地址，
  所以这一层专门读 `document.documentURI`。它既不是登录墙也不是风控，因此**不写** `login_wall`/`risk_blocked`、不让你去重存 Cookie。
- **停止之后，「抓取自己回来了」也算被停止**：共享走查 honor 停止的方式是**返回**已采到的行而非抛异常，所以现在抓取返回后还要再问一次
  「可以停了吗」，结局统一走 被停止。**评论引擎也改成握着 crawler 而不是当时的 driver 对象**——被强杀时换死驱动桩的是 crawler 身上的名字。
- **面板会自己修好没人收尾的记录**：本进程开过、执行线程已不在的运行行，在刷新时被判定为「已中断」并写明原因；范围严格限制在**自己开过的行**。
- **撤销/重做**：Ctrl+Z / Ctrl+Y 支持 50 步历史回退。历史快照必须**深拷贝节点参数**（`getState()` 深拷），相同的画面不入栈，打开一份草稿只算
  **一个**撤销点（`_pushState` 跳过与当前相同的状态，`restoreState` 用 `_historySaving` 括住自己）。
- **键盘复制 / 粘贴 / 微移**：选中节点后 `Ctrl`/`Cmd`+`C` 复制、`Ctrl`/`Cmd`+`V` 粘贴（副本落在右下方一格，`PASTE_CASCADE=24px`）。方向键平移
  所选节点（默认 10px、`Shift` 1px），每一下都是可撤销的一步。`_isTypingTarget` 在最前，故输入框里 `Ctrl+C/V` 仍是正常的文本复制粘贴、不劫持。
- **跨画布分享单个节点（JSON 复制 / 导入）**：右键一个节点「复制节点为 JSON」把 `{type,title,params}` 片段写进剪贴板（无剪贴板 API 的 http 场景
  退回手填对话框，此时**不**谎报「已复制」）；右键空白「从 JSON 导入节点」复用同一条 `pasteClipboardAt`，与同页复制粘贴**逐字节一致**。导入按名
  校验：非法 JSON、缺 `type`/`params`、`type` 不在已知节点类型表里，一律具名拒绝。
- **剪贴板抽屉（持久化 + 精细管控）**：顶栏「视图」组按钮（`toggleClipboardDrawer()`）开合一个右侧滑入抽屉，把**每一次复制**累积成一份清单
  （`node`/`nodes`/`text` 条目），存于独立的 `crawler_clipboard` 键（与草稿分开，刷新/重开仍在），上限 50 条、置顶（★）条目豁免淘汰。每条可
  粘贴/重命名/置顶/删除，头部可全部清空（二次确认）并搜索过滤。粘贴一律走画布**同一个 `canvas._pasteAt`**；`text` 条目若能解析为合法节点 JSON 则
  作为节点插入，否则**具名拒绝**。抽屉是**视图态**，其内容永不进入 `getState()`/撤销历史/工作流文件。
- **跨标签页同步**：抽屉持久到 `crawler_clipboard` 后，注册一个 `window` 的 `storage` 事件（仅当键是 `crawler_clipboard` 时触发），调
  `Clipboard.load(); Clipboard.render()` 把别的窗口刚写入的清单拉回本窗口；`storage` 事件只在"其它标签页"派发，无回声循环。
- **缩放控件与快捷键一览**：状态栏 `#status-zoom` 旁挂 `[−] 百分比 [+]`（点数字＝`resetView` 适应），绑 `+`/`-`/`0` 键（经 `_isTypingTarget` 守卫）。
  缩放是**视角态**，与平移一样只进草稿/`settings.view`，绝不进撤销。`?`/`F1` 开一个静态键表浮层，逐条列出实际绑定的快捷键。
- **对齐 / 分布（多选）**：`canvas.alignSelected(mode)` 提供左/右/上/下对齐、水平/垂直居中、水平/垂直等距分布；一次对齐是恰好一步撤销，少于两
  个选中是静默 no-op。对齐**不新增任何持久字段**。
- **连线环检测**：图是无环的才能被引擎自顶向下走，所以一条会成环的线必须在**唯一提交点**挡下。`connectNodes` 在自环/重复守卫之后判断"加上
  from→to 是否让 to 已能到达 from"，是则**具名拒绝**（toast `connCycle`）。环检测**不新增任何持久字段**。
- **视角与坐标都会留下来**：平移/缩放随本地草稿与工作流文件一起存，但**不进撤销栈**；节点坐标为 `0` 也算一个位置（旧写法 `x || 随机` 会把
  x/y 恰好为 0 的节点打散），只有真正没给坐标时才随机摆放。
- **打开的是哪份文件也会留下来**：当前打开的保存文件名随本地草稿记进浏览器（`crawler_open_file`），刷新或重启后重开的仍是刚才那份；只有点「新建」
  才清空。**本地草稿只是快照**，所以每次进入都会按记忆的文件名再向服务器拉取一次最新内容并加载；拉取失败或文件已不存在则保留草稿原样。
- **未保存改动看得见**：状态栏一个 `●` 标记，判据是 `getState()`（节点+连线模型），**不含视角**——平移/缩放不会点亮它。据此，从文件面板「打开」
  另一份工作流时，**只在确有未保存改动时**才弹二次确认。
- **节点重命名**：双击节点标题（或右键→重命名）即可命名节点；控制台与校验信息以「名称 #节点号」播报（`engine.workflow.node_label`），自定义名
  在保存/加载、撤销重做、切换语言后都保留，清空即恢复类型默认名。
- **一次按键说完所有问题**：toast 只有一个元素、文字是替换的，旧写法遍历校验错误等于只让你看见**最后**那一条。现在一条 toast 带计数与编号，读完为止。
- **节点 id 不是页面 id**：节点框的 DOM id 就是它的 id，所以按 id 去 `getElementById` 是在问"页面上有没有这个元素"——一个叫 `status-zoom` 的节点
  会让删除节点与撤销路径把底部状态条整个删掉。所有节点元素改由 `canvas._nodeEl(id)` 取，并用文本门禁止 canvas.js 里再出现"变量参数的 getElementById"。
- **切换语言到达每一张 JS 生成的表**：运行记录、导出产物、数据集管理、工作流文件、执行历史五张表的表头与状态词都是 JS 从词典拼出来的，`I18n.apply()`
  走不到它们——现在面板开着就当场重画（执行历史用上一次的返回结果重画，不再多问服务器一次）。
- **右键菜单不说假话**：没复制过任何东西时不再列出「粘贴节点」；折叠过的节点那一行改说「展开」；菜单位置按它自己实测的宽高钳位，不再用 200px 魔数。
- **节点折叠**：选中节点按 F 键或右键折叠，节省画布空间。
- **自动布局**：按 DAG 层级 BFS 自动排列所有节点；排布读**每个节点的真实宽高**，同链节点按**中心线**对齐，连线**能直则直**（只有分支、反向线
  和手工斜线才保留弧度）；排布后自动执行一次**「适应」**，所以「自动布局 = 重新排布 + 适应」。**上下堆叠顺序**按各「工作流命名」节点的**排布顺序**
  排（数字小的在上，留空沿用创建顺序且排在已编号项之后），所以从没填过这个值的旧画布排布结果与从前逐像素一致。
- **大纲侧栏（右侧）**：右侧常驻一个「大纲」面板列出画布上的**每一个**节点（按创建顺序：类型缩写 + 显示名）。点一行即把该节点居中**并放大到能
  看清它和邻居**（取景窗口是节点 3 倍，缩放允许超过 100%、钳制 50%–150%）。被禁用/断供的节点**仍在列表里但置灰**。列表由 `canvas.saveState()`
  重建；「新建」不走 saveState，故 `newFile()` 里**直接重建**侧栏并调 `canvas.resetView()`。面板可折叠，折叠态单独存本地、不进草稿、不构成撤销步。
- **连线跟随节点尺寸**：线端点是首绘时量下的**字面数字**，而节点连接点是 CSS（永远跟着当前盒子）；ResizeObserver 盯住每个节点盒，尺寸一变即按
  新值重画连线（只重画：不产生撤销步、不写草稿）。
- **连线分支：多连一（fan-in）与一连多（fan-out）的后果**：执行器按目标节点类型区别对待，其中一部分是**静默**的，所以连线当下即弹一个说明框
  （**不阻断**：线已写入，可点「撤销这条连线」退回；可勾选「本次会话不再提示」按类静音）。每种组合的确切后果与 `backend/engine/run.py` /
  `backend/engine/workflow.py` 同源，前端警告文案逐条对应：

  | 连线情形 | 目标 / 源节点 | 程序实际会做什么 | 结果 |
  |---|---|---|---|
  | 任意线连入 | 命名 `name` | 命名节点必须打头，不能有上游 | 运行前**具名拒绝** |
  | 第一条连入即提示 | 上传 / 评论 / 续跑 `upload`·`comment`·`resume` | 这三类**完全不读上游** | 连线**静默无效** |
  | 第二条及以后汇入 | 处理 / 分词 / 可视化 `process`·`tokenize`·`visualize` | **只取第一条**上游表，其余丢弃 | 弹窗提示"只用第一个" |
  | 第二条汇入 | 数据源 `source` | 被投喂时只读**第一个带表格的父**当链接源；若该采集内容不接受上游 | 前者只用第一个；后者**运行拒绝** |
  | 第二条汇入 | 分析 `analysis` | 表连接只用两表（第一＝左表、第二＝右表），**第三个及以后丢弃**；非连接步骤只读第一个 | 弹窗提示 join 上限 |
  | 第二条汇入 | 输出 / 保存 `output` | 把**每一条**上游表 `concat` 纵向合并成一个文件；两张表**列集不同则具名拒绝** | 合并成功或具名拒绝 |
  | 一个节点连多个下游 | 任意（fan-out） | 每个下游各拿到**同一份完整快照**，不分流、不互相覆盖 | **安全**，仅在首次分叉时提示一次 |

  要合并多批采集，请让多个**采集 / 上传**节点连到**同一个输出节点**（走纵向合并）。这些后果由 `tests/frontend/harness_canvas_ix.mjs` 的
  `connect_warnings`、`tests/api/test_fan_in_fan_out_results.py`、`tests/unit/exports/test_output_merge.py` 锁定。
- **适应 = 缩放到看得见**：「适应」不再把视角锁死在 100%。它按**可视区**（`#workspace` 自己的盒子，不是 `window.innerWidth`）求节点外接矩形的
  缩放比：**只缩不放**（上限 100%、下限 20%），顶部预留**菜单栏高度 + 边距**。
- **相机缓动（适应 / 大纲跳转）**：「适应」和大纲「点击行→跳到该节点」走一段 CSS 过渡（`VIEW_ANIM_MS`≈280ms）平滑推到位。关键分工：**最终
  pan/zoom 仍同步写入状态**，**只有渲染出来的 transform 去补间**。任何手动操作都会先 `_clearViewAnim()` 撤掉过渡；系统「减弱动态效果」或 `ms=0`
  时直接吸附。缩放按钮 +/− 保持即时。
- **节点库可折叠**：左侧节点库标题行右侧的「−/+」按钮把面板收成只剩标题行（永远有路可展开），`aria-expanded` 与提示随状态翻转。
- **节点颜色编码**：节点库按 工作流 / 数据输入 / 数据处理 / 结果输出 四组排列，各节点有独立颜色与标识——全部 14 个类型：
  **NAM / SRC / UPL / RSM / CMT / PRC / ANL / TKN / BIB / FSN / ACC / VIZ / CMP / OUT**（与 `backend/nodes/catalog.py` 的 `PLUGINS` 一一对应）。
- **平板 / 手机触控适配**：`@media (pointer: coarse)` 把节点按钮、菜单按钮、连线命中区放大到指腹尺寸（桌面细指针布局逐字节不变），画布容器加
  `touch-action: none`。面板与控制台的「拖动改高度 / 拖拽移动」已改用 **Pointer 事件**（鼠标/触控/笔共用同一套代码）。画布内：**单指在背景拖动=平移
  画布**、**单指拖节点标题=移动节点**、**从端口单指拖到另一节点=连线**、长按=弹出节点菜单。
- **双指手势（平板）**：画布背景上两指**同时同向移动=平移**、两指**张开/合拢=缩放**（以两指中点为锚）；先抬起一根手指时剩下那根仍可继续平移。
- **触控板 / 鼠标滚轮（三职分立）**：三个角色互不打架——**Ctrl/Cmd+滚轮=以光标为锚缩放**；**触控板双指滚动=平移画布**（跟手，delta 取反）；
  **鼠标滚轮=以光标为锚缩放**。难点是 Windows/Chrome 里"纯竖直、整数像素 delta"的单事件触控板与鼠标完全一样，逐事件无法区分——分流改为**读整段流
  （stream）而不是单事件**：一次滚动的 burst 里只要有任一个事件满足触控板证据（① `deltaX !== 0`；② 分数 delta；③ 同 burst 内 `deltaY` 相对上一
  事件变化）之一，整段 burst 升级成平移；纯竖直、整数且不变才认定为鼠标滚轮并按光标缩放。相机始终只写进 `serializeDraft` / `settings.view`，
  绝不进 `getState()`。`harness_canvas_ix` 用四个 `wheel` 场景把三职钉住。

## 断点续跑与运行记录
- **待运行队列重启不丢**：内存 `_RUN_QUEUE` 仍是运行时唯一真源，但每次入队/出队/取消/清空都会 `_mirror_queue()` 把当前队列**整表镜像**进
  `runs.db` 的 `run_queue`（≤`QUEUE_MAX` 条，全量替换；payload 存原始 POST 体）。开机时 `_load_pending_queue()` 仅在内存队列为空时按 `position`
  回填，**绝不覆盖**已有活队列。这没有动摇"一次只跑一个运行"的核心不变式。
- **单节点重跑（含下游）**：运行详情里每张已完成节点卡片给一个「从此节点重跑」，**复用现成的续跑机制**而非新造执行器：① 由 `connections` 走
  **有向下闭包** `{目标 ∪ 全部下游}`；② `run_store.invalidate_nodes(run_id, 子树)` 删掉这些节点的 `node_rows`+`node_runs`，上游未变节点的**保留行
  原样留着**；③ 以 `resume_run_id` 走普通 `begin_run`，reusable 谓词天然只重跑被删空的子树、绝不重采、绝不再付费。具名拒绝：节点不在当前画布 /
  上次没完成 / 没有可复用既往运行 / 画布指纹与所选运行不符。**另一个运行仍活着时也先拒绝**。
- **载入任意一次运行的结果（画布默认最近一次）**：每个节点每次运行的**表格输出**按运行号持久化在 `node_rows`，成败/行数/错误留在 `node_runs`。
  画布打开时询问 `POST /api/runs/for-workflow`（用与「继续」相同的结构指纹），默认载入**最新一次**并给每个节点画角标：**绿勾** = `done`/`restored`，
  **黄色转圈** = `running`（状态是一张 map），**红叉** = failed/partial/skipped/pending；没跑到的节点不画角标。载入后所有预览/图表/看板请求都带
  `run_id`，服务端按**那一次运行**取行；手动载入不执行任何节点，要复用历史结果继续算用「从此节点重跑」。
- **跨运行采集水位**：数据源节点的作者投稿模式（目前仅哔哩哔哩）可勾「停在上一次运行的边界」。一次成功完成后把最新 BV 号写进 `source_watermarks`
  （按节点指纹存档，改关键词/账号/模式即另起）；下一次运行遇到该 BV 就停止翻页、**不请求该 BV 及更旧的条目**。只有完整结束的运行才推进水位，
  墙/风控/停止/欠采都不写；水位与「重新采集」互斥。
- **运行级对比**：任一次运行可点「对比」并选另一次运行。`GET /api/runs/compare` 读两次运行的 `node_runs`/`node_rows`：先给每个共同节点的状态
  与行数变化，再对**默认节点**调用同一套 `DataAnalysisService.diff`，返回新增/消失/变化行、列增减与样本；两次运行的工作流名/结构不同会明确标注。
- **累积数据集（版本化谱系）**：「累积数据集」节点接一个上游表格，填累积集名称。每次运行把新增行追加到一个带版本的谱系并把**全量表格传给下游**；
  去重方式必须显式选择「整行完全相同」或「按指定列」，列变化按名拒绝。谱系存在 `datasets.db` 的 `dataset_lineages`/`dataset_lineage_versions`。
  **重置累积数据集**只清空谱系和版本指针，已存的数据集版本保留。项目包会携带当前版本的数据集和谱系名称。
- **数据集多源合并**：数据集面板每行可「加入合并」，选至少两份后「合并所选」并命名。服务端按列集合校验（按第一份的列序，多/缺列按名拒绝），
  默认插一列 `来源` 记录每行来自哪个数据集；总行数受 `DATASET_MAX_ROWS` 上限约束。
- **数据集行级对比**：`POST /api/data/diff`，两侧各是一个解析器载荷（`{dataset_id}` 或 `{node_id,workflow_name}` 或内联 `{data}`）。比对按**两份表
  共有列**做逐行规范化哈希的多重集差（`added`/`removed`），**增删列**单列出来；`changed` 只在调用方**显式点名**一个在两侧都唯一的键列时才判定——
  绝不自动挑一列当主键去"猜"行身份。
- **节点级检查点**：每步输出行持久化到 `data/runs.db`，工作流结构指纹 + 节点指纹决定哪些结果可复用、哪些因参数改动而失效重算。**标签不算参数**：
  改「工作流命名」的名字、给它填「排布顺序」、把上传文件名改得更好看都不会让已付过费的行作废；数据集/运行的 **id** 仍在指纹里，指向另一个文件就必须重算。
- **LLM 答案缓存**：按 操作+提供方+模型+列+截断+主机+主题+提示词版本 缓存回答，重跑或续跑不再为同一行付费；改了提示词模板或参数，旧答案自动失效。
- **采集去重指纹（增量采集）**：已抓到的条目指纹按节点入库，续跑/重跑自动跳过已采集内容并明示跳过数；采集节点可勾选「重新采集」清除账本全量重抓。
- **中断自动识别**：服务重启后遗留的"运行中"记录自动标记为"已中断"，画布顶部出现续跑横幅，一键「继续」或「重新开始」（前提是本机同时只跑一个服务）。
  判定时**按已落库的行回填「已存行数」**：进程被硬杀时收尾不会执行，行数其实安全存在 `node_rows` 里；同一套判定也挂在运行记录面板的读取上，
  **不必重启服务**。
- **续跑可以连着点**：上一次只做「复原」的节点（状态是 restored 而不是 done）在下一次仍然算已完成、仍然直接回读。
- **完成数只有一个口径**：运行记录里的 `n/N` 与控制台的「N 个节点完成」说同一个数——跳过、失败、部分完成的节点都不算完成，`restored` 算；
  结束行"几个失败"只数**这次画布上真跑过的**节点；被「停止」剪掉的节点单独计数为「n 个被停止」。
- **Cookie 中途过期可续跑**：长采集常跑到一半 Cookie 失效被挡回登录墙——已抓的行早已落库，节点判为"部分完成"、整条运行进入续跑横幅；换新 Cookie
  点「继续」即从断点接着抓、绝不重复已存条目。撞墙那一行只陈述被挡回登录页，不再替爬虫宣称"已停止本次抓取"——各家策略不同，说停了就是假话。
  **评论**节点同样只点名真正被撞回的那个平台（以前硬写四个平台名，爬 YouTube/X 被撞墙时报告里没有一个名字是对的）。
- **运行前 Cookie 预检（`cookie_preflight_before_run`，可关，默认开）**：含采集/评论节点的工作流运行前，`workflow.js` 的 `execute()` →
  `_cookieGateBeforeRun` 调 `cookie_preflight_before_run`，用**这一次运行真正会用的浏览器**逐 (平台, 账号) 探测该模式是否需要会话（`Mode.needs_session`；
  weibo 热搜匿名、wechat 无会话可要）：**登录墙直接拒绝启动**（刻意**不留**「我确定，照样跑」——从登录页开始的抓取一小时后只会带回一张空表）；
  **无法核对**（验证码、超时、profile 正被占用）**不拦**（没有答案不等于 Cookie 死了）。结论缓存几分钟（`COOKIE_PREFLIGHT_TTL`），保存/删除/扫码取回
  Cookie 都会立刻作废缓存。关掉这一项 = 什么都不问、什么都不拦，直接开始运行。**旧的「执行前 Cookie 确认」弹框（带「继续执行」逃逸）已删除。**
- **禁用节点 / 工作流 / 节点类型（禁用＝等同于不存在）**：每个节点头部有一个**电源键**单独启停；新增节点一律**默认启用**；右键任一节点可**禁用整类**。
  **被禁用的节点对运行完全等同于不存在**：它和与它相连的线一起从有效图里移除（`engine.workflow.effective_workflow`），校验/拓扑/分量/命名/续跑/记录
  都按"画布上没有它"处理。禁用会**向下游传染**（所以"禁用整条工作流"＝禁用它的头节点）；但**多入边的节点只要还有一条活着的上游就照常运行**。
  `enabled` 是控制态，绝不进数据指纹，因此**禁用↔启用仍可续跑**。
- **Resume 节点**：直接收养历史运行的节点输出作为数据源；它的「选择运行记录」下拉列出**所有仍有数据行的历史运行（含已完成的）**，按运行/节点挑一份
  来收养，**不要求画布结构跟那次运行一致**（加了 Resume 节点本身就改写了画布指纹）；结构匹配只留给顶部**续跑横幅**去找"这条画布自己那次没跑完的运行"。
- **导出产物面板**：`data/exports` 按时间倒序列出导出文件，支持逐个下载与删除；文件名一律按名解析，`../`、绝对路径、子目录一律 404；脚本/可执行一类
  扩展名可见但不下发。面板头**清空**逐个调用与单条删除同一个解析器，只删面板列出来的名字，**有运行在跑时整个请求被拒**。
- **文献计量工作区面板**：顶栏与状态栏两个门（加面板自身关闭共三处 `toggleBiblioPanel()`），与其他 dock 共用底部槽位。它读 `/api/biblio/runs` 与
  `/api/biblio/table`——**持久台账**而非画布当前态，所以重启、刷新、甚至把那张画布改过之后，那次跑出来的结果仍找得回来。面板给：运行下拉、该运行内 `biblio` 节点下拉、
  输出形态标（`nodes`/`edges`/`clusters`/`bursts`/`dual_map`，服务端从列名判读，判不出显示「输出形态未知」而不是猜）、200 行分页的表格与本页内筛选（行数以服务端 `total` 为准）、
  GraphML/GML/JSON/CSV/Pajek 产物下载（名字按服务端解析结果回传，浏览器不拼路径）、以及「在画布中定位」（节点已不在当前画布时**照实说**）。**表头是界面文字，不是存储列名**：
  每个表头取本语言的词、把磁盘上的列名留在 `title` 里，构建没有词的列照实显示自己名字。**面板自己的输入框与下拉**带 `data-biblio-keep`，重绘后交还焦点。**项目与快照**：
  项目 = 被命名的研究对象，快照 = 某个 `biblio` 节点的一次捕获；参数只从**已保存画布**取并用节点指纹核对，核对不上记 `params_verified=0`（面板写「未核对」）。**对比**：
  差异由服务端算（`compare_snapshots`）——节点/无向边（按规范化端点对）/簇/突现的增减与逐列变化、变了的参数名；超过 60 条的段落同时写出 total。
- **工作流文件面板**：底部面板列出 `data/workflows` 里每个已保存画布，支持逐个 打开、重命名、删除，正在编辑的打「当前」。重命名会**同时改掉文件里那份
  name 和引用它的数据集记录**；目标名已存在返回 409 并原样显示原因，绝不静默覆盖；损坏文件**仍列在表里**（打「已损坏」、只给删除按钮）。三个动作在运行中都直接拒绝。
- **导入外部工作流文件**：File 菜单「导入」从本地磁盘选一个 `.json`。文本先由 `parseWorkflowFileText` 判定是不是工作流，判定在**动画布之前**完成，
  所以一份陌生或写了一半的文件绝不会先清空再失败；非 JSON 报「无法把该文件读成 JSON」、是 JSON 但没节点列表报「这不是工作流」，两种都**不改动当前画布**。
  导入只填画布、**不写服务器**。
- **运行记录面板**：列出各工作流的运行历史、节点状态、行数统计，支持丢弃、删除、按保留策略清理，以及面板头的**清空**（三个"删除全部"按钮都要求显式送
  `confirm: true`，少一个字符就 400）。清空语义与逐条删除不同且有意为之：删一条记录保留其"已采集"认领；清空全部记录把认领一并交回。LLM 答案缓存则
  故意活着一清空。续跑后那次尝试会**改写记录的描述字段**（mode/无头或窗口/工作流名/结构指纹/语言），`started_at` 保持原样。
- **并行 = 一条记录，写全部工作流的名字**：画布上几个工作流同时开跑就是一次运行、一条记录——名字按画布顺序用 ` + ` 连起来。**标签说的是"这次实际怎么跑的"**：
  `并行 ×N` 只在 mode 为 parallel 时出现，再加 `无头` 或 `窗口`。#148 之后没有任何路径再把无头运行偷偷换成可见窗口，所以 `无头 / 窗口` 照实读请求的值
  （旧的 `无头→窗口` 混合标签与它读的 `forced_visible` 一起下线，列仍在、恒 0）。合名也是查回旧行的键。
- **串行 = 每个"轮到执行的工作流"一条记录**：串行一个一个轮着跑，每个**开始执行**的工作流写自己一行（`串行 ×1`、各自状态与行数、各自可续跑），
  **中止时还没轮到的那个一条记录都不留**。① 每行仍存**整张画布**的结构指纹；② HTTP 响应交回的 `run_id` 是**第一个工作流那一行**的 id；③ 再点「继续」时
  各工作流按名字找回自己那一行**累加**。
- **一条记录里含多个工作流时，展开按工作流分组**（并行的那一条，以及拆分之前的旧记录）：每个节点存下它属于第几个工作流、那个工作流叫什么（`node_runs`
  的 `component` 与 `component_name`）。分组标题的名字**与控制台用的是同一个函数**（`_wf_display_name`）。每组显示"几个节点完成 / 共几行"，其中
  `restored` 计入完成、`partial` 与 `failed` 不计。
- **并行记录的续跑是每条工作流各自的状态**：一条工作流失败不会让另一条重跑；改动了 A 的参数也只重算 A，绝不把热门榜的表贴到周排行榜名下。
- **执行历史与趋势对比**：自动记录情感/倾向性分布与各节点行数，可按工作流和指标画出时间序列；列表里**每一条运行都能单独删除**（只删那一次的指标）。
- **保留策略**：每工作流默认保留最近 20 次运行、30 天内的记录；干净完成的先清理，还没写下结论的最后清理；单节点行数与单文件行数均有硬上限。策略
  **自动生效**（服务启动时清一次，此后每次运行结束按时间闸再清）。**被自动裁剪掉的运行会同时交回它的"已采集"认领**；手动删除某条运行仍保留认领。
- **运行日志自动轮转**：`logs/app.log` 写满 5 MB 滚动为 `app.log.1 … app.log.5`（上限与份数在 `core/config.py` 可调）。

## 定时任务

到点自己跑一份已存画布——为**云服务器**准备的（没有浏览器可点，也没有人坐在前面）。入口三处：顶栏 Run 菜单「定时任务」、状态栏右下角同一按钮、
以及面板自己的关闭按钮；面板是底栏停靠的一块（同一条 dock 规则）。

- **时钟在应用进程里**，`python app.py` 起来就有一个常驻线程按 `SCHEDULER_TICK_SECONDS`（默认 20 秒）看一次清单；**只在 `__main__` 里启动**，且热重载
  时只在真正的服务进程里起，否则会有两个时钟。到点后一律走与手动 Run **同一条启动路径**（`engine.run_schedule.start_scheduled_run` → `begin_run`），
  所以服务正忙时它照样**排队**。
- **时间怎么写**：预设（每天/每周 `HH:MM`、每 N 分钟）与 **cron 五段表达式**都行，每个任务可指定 **IANA 时区**（留空=服务器本地时区）。cron 自己实现
  （`scheduling/cron.py`，只用 stdlib `zoneinfo`）：`*`、范围、列表、步进、月/周英文三字母名、`0` 与 `7` 都是周日、日与周按 POSIX 取「或」、`@daily` 之类
  宏；春季夏令时被跳过的钟点整段跳过，秋季重复的钟点只跑**第一遍**；永不触发的写法（如 `0 0 30 2 *`）在**保存时**就具名拒绝。
- **定时任务不碰模型**：画布里只要有需要模型的节点（清洗默认 LLM、情感/倾向/情绪的大模型模式、关键词 LLM 模式、主题命名……），这个画布在**选择时**就
  标成不能定时并写出原因，保存期与触发期再各查一次（`engine.run_schedule.scheduled_canvas`，服务器不替你决定提供方，也不用环境变量里的 key）。
- **错过的时刻不补跑**：服务器停机期间该响的点，只在任务自己的历史里记一条**「已错过」**并显示次数，绝不补跑；重新计时从「现在」往后排。
- **记账只在任务自己身上**：每个任务有「最近一次」与最多 20 条历史；被拒绝的原因、崩溃的堆栈各记各的。**控制台只在一趟真的启动时得到一行**归属消息
  ——排队的那趟由队列自己讲，拒绝的那趟不写控制台。
- **面板不自己算、也不自己编**：下次运行/最近一次的时间、任务句子措辞、画布能不能定时，全部由服务端按任务时区算好送来（`next_run_local`/`last_run_local`/
  `runnable`/`why_not`）；状态词只把服务端给的 token 换成当前语言的词，认不出的原样显示。`tests/unit/frontend/test_frontend_schedules.py` 驱动真实 `schedules.js`。
- **数据在 `data/schedules.json`**（gitignore）：坏文件被隔离成 `.corrupt` 而不是让整个面板打不开；同一份 `data/` 只应有一个服务进程。

## 节点类型

| Name（命名） | NAM | 工作流元数据，其标签作为工作流名供历史/运行记录归组 | 是（纯元数据） |
| Data Source（数据源） | SRC | 先选平台、再选**采集引擎**（Selenium / CatBus），功能列表随引擎变化；CatBus 独有平台（快手 / TikTok / 京东 / 淘宝 / 闲鱼）与独有功能（粉丝列表、热搜词、直播间……）完全读自适配器清单，不可运行的一对列着、置灰并写明原因。**关键词采集**只覆盖 知乎 / 微博 / 小红书 / 哔哩哔哩 / YouTube / X（推特） 六平台（**抖音与红果短剧没有关键词模式**，运行它们会按名拒绝）；**微信按粘贴的推文链接采集正文**（无关键词搜索）。**「某作者的作品」**在 知乎、微博、YouTube、X（推特）、哔哩哔哩、抖音 可选（知乎填主页链接或 /people/ 后的 id，微博填 weibo.com/u/<UID> 或数字 UID，YouTube 填 @handle/频道链接/UC… ID，X 填 @handle 或主页链接，哔哩哔哩填 space.bilibili.com/<UID> 或数字 UID，抖音填 douyin.com/user/… 链接或那串 sec_uid）。**热榜/热搜**：哔哩哔哩（热门榜分页 / 周排行榜一次回整张表）、微博 热搜（一次页内请求回整块榜，精确整数热度，且**无需登录态**——矩阵 `needs_session=False`，只挂热搜的画布不会被运行前 Cookie 预检拦下）、知乎 热榜（整块 30 条且站点无视翻页参数）、抖音 热榜（一次回答整块榜，实测 51 行，用只由公开字面量拼出的 URL 取数，不需签名，带精确热度与观看数）、红果短剧 热榜（四榜各 5 页、每页 20 条，一榜一节点，不需登录/Cookie）。**红果短剧** 另有热榜与评论两种模式（评论：填详情页链接或由上游热榜表喂入，带本地代理驱动第三方桌面播放器收割 App 协议评论页——不开 Selenium 窗口、播放器需已登录，详见 docs/collection.md）。「采集内容」切到**评论**即变为评论采集器。可选项完全由后端 `/api/capabilities` 的采集矩阵生成，新增平台或模式不必再改前端；**运行前的本地校验也读同一份矩阵**（以前它自己写着"评论要链接、微信要链接、别都要关键词"，于是 5 个「某作者的作品」模式与 B 站热榜在界面上根本跑不了） | 是，需平台+关键词/作者（或评论/推文链接；热榜只需选榜单） |
