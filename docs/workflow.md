## 画布与引擎
- **画布历史（命名快照）**：底部“工作流文件”面板的“画布历史”页签；保存画布时可选一个名字，存进 `data/workflow_history.db` 的 `canvas_snapshots`，与工作流文件互不影响。恢复前先与当前画布做差异（节点/连线增减、位置变化数），确认后走 `workflow.loadFromJSON(..., {history:'single'})`，整次恢复只记一个撤销点；快照可重命名，删除一条会同时清掉指向它的布局基准。上限 100 份，存满时服务端按名拒绝；保存的是文件形状，可复用节点的折叠态一并回来。
- **项目包迁移**：“工作流文件”面板顶部可导出当前或全部工作流。zip 内是 `manifest.json` + 工作流 JSON + 引用的数据集（列名与记录）+ 引用的可复用模板；不含 Cookie、API key、模型权重、运行日志。导入时数据集/模板重新分配 id 并改写引用，同名自动加 ` (2)`，绝不覆盖；zip 版本、校验和、路径、解压体积与结构先校验，任一不符按名拒绝。缺数据集在导出时拒绝，缺模板只警告（实例自带模板快照）。
- **自动排布**：“算法排布”或“按历史基准恢复”。基准按已保存工作流名单独存（`layout_baselines`），未保存草稿不能设基准（按名拒绝）；基准策略先跑算法，再用基准快照里同 id 节点的位置覆盖（后加节点仍由算法摆放），基准只恢复位置、不改内容；基准快照被删后显示“基准快照已不存在”并拒绝执行。
- **可复用节点（一个盒子里的子图）**：选中 process/analysis/visualize/tokenize/biblio/fuse/output/compile 后右键创建，服务端验证后存 `data/reusable_nodes/<id>.json`，画布把选中节点收成一个 `reusable` 节点并重接外部连线；实例把模板快照存在自己参数里，模板后来被删/改不影响旧实例。组左端口按 `canvas.connections` 落线顺序对应模板 `inputs` 的第 1、2… 槽，槽数与接线数不一致时运行前按名拒绝。折叠时占一个普通节点，角标汇总内部状态（running 优先，其次 failed/partial，全部 settled 才 done）；展开时内部节点按模板位置只读呈现，但始终是一个顶层模型节点，内部节点不进 `canvas.nodes`，展开后默认立即排布一次（把展开组按实测尺寸当一个块）。`canvas.toWorkflowJSON()` 默认展开成 `<组id>__<内部id>` 真实节点，文件保存用 `{expandReusable:false}` 保留组；定时任务从文件启动时服务端先展开（`services/workflows/expand.py`），规则一致。解包为普通节点是一个撤销步骤、不删模板，外部连线多于输入槽按名拒绝；“可复用节点”页签可预览/插入/重命名/删除（删除只删模板文件），模板行可拖到画布落点插入（与按钮共用 `insertTemplateAt`）。内部节点默认只读，解包后可编辑。
- **版面约束**：窗口与页面级绝不出现水平滚动条；面板内表格可横向滚动，被截断的单元格必须带省略号；顶栏放不下时靠左锚定并留一条细滚动条；节点设置与 Cookie 面板有高度上限、超长表单自己滚动；下拉单选行带省略号、完整文字挂 `title`。
- **参数与面板**：选数据、选花费或起名字的参数（榜单、分片格式、清洗的列名/筛选/类型/填充、AI 的 `method` 与 `mode`）只接受面板给出的写法；空着＝按默认值跑，列表外的名字让节点失败并送出原因与可选项。勾选框一律按值读（`core.refs.as_bool`），`'false'` 与 `false` 含义一致；节点里存着列表外的值时，下拉框把它作为“不是可选项”的条目显示（`selectOptionTags`/`boolParam`），不再显示第 0 项。**前端对一次采集不持有第二种意见**：`sourceNodeErrors()` 问 `Capabilities` 该模式需要哪些字段，未加载则拒绝，绝不猜。
- **撤销与复制**：撤销/重做（Ctrl+Z / Ctrl+Y）保留 50 步，`getState()` 深拷参数，相同画面不入栈，打开草稿只算一个撤销点（`restoreState` 用 `_historySaving` 括住）。选中后可 Ctrl/Cmd+C/V（副本落在右下方一格，`PASTE_CASCADE=24px`）与方向键微移（默认 10px、Shift 1px），每步可撤销；`_isTypingTarget()` 在最前，输入框内不劫持快捷键。右键“复制节点为 JSON”写 `{type,title,params}`，无剪贴板 API 时退回手填对话框、不谎报已复制；右键空白“从 JSON 导入节点”复用 `pasteClipboardAt`，非法 JSON、缺 `type`/`params`、未知类型一律具名拒绝。
- **剪贴板抽屉**：顶栏“视图”组 `toggleClipboardDrawer()` 开合右侧抽屉，累积每次复制（`node`/`nodes`/`text`），存独立 `crawler_clipboard` 键，上限 50、置顶（★）豁免淘汰；可粘贴/重命名/置顶/删除、清空（二次确认）与搜索，粘贴走 `canvas._pasteAt`，`text` 能解析为节点 JSON 才插入。抽屉是视图态，永不进 `getState()`/撤销/工作流文件；`storage` 事件（仅该键）把其它标签页的写入拉回。
- **视角与打开的文件**：状态栏 `#status-zoom` 旁有 `[−] 百分比 [+]`（点数字＝`resetView` 适应），绑 `+`/`-`/`0`；`?`/`F1` 打开静态键表浮层。`canvas.alignSelected(mode)` 提供四向对齐、水平/垂直居中与等距分布，一次对齐恰一步撤销，少于两个选中静默 no-op。`connectNodes` 在自环/重复守卫后判环，会成环则具名拒绝（toast `connCycle`）。平移/缩放只进本地草稿与 `settings.view`，绝不进撤销栈；坐标 `0` 也是位置，只有非有限坐标才随机摆放。当前打开的文件名记在 `crawler_open_file`，刷新后重开同一份，每次进入按该名字重拉服务器最新内容，失败则保留草稿；只有“新建”清空。状态栏 `●` 由 `getState()` 判定（不含视角），从文件面板打开另一份时仅在确有未保存改动时二次确认。
- **节点拾取与命名**：双击标题或右键重命名（控制台/校验以“名称 #节点号”播报，`engine.workflow.node_label`），保存/加载/撤销/切语言后保留，清空恢复类型默认名。节点框的 DOM id 就是节点 id，所有节点元素必须走 `canvas._nodeEl(id)`，不得用 `getElementById(<变量>)`。选中节点按 F 或右键折叠。右键菜单只在复制过东西后列“粘贴节点”，折叠节点说“展开”，位置按实测宽高钳位。toast 只有一个元素，一条带计数与编号，读完为止。
- **自动布局、适应与相机**：按 DAG 层级 BFS 排列，读每个节点真实宽高，同链按中心线对齐，连线能直则直（分支、反向线、手工斜线保留弧度），排完自动“适应”；上下堆叠按各“工作流命名”节点的排布顺序（小的在上，留空沿用创建顺序并排在已编号项之后）。“适应”按 `#workspace` 自己的盒子求缩放比，只缩不放（上限 100%、下限 20%），顶部预留菜单栏高度 + 边距；“适应”与大纲跳转走 `VIEW_ANIM_MS` 约 280ms 的过渡，最终 pan/zoom 同步写状态、只对渲染 transform 补间，手动操作先 `_clearViewAnim()`，系统减弱动效或 `ms=0` 时直接吸附，缩放按钮保持即时。ResizeObserver 盯住节点盒，尺寸变化时按新数字重画连线（不产生撤销步、不写草稿）。
- **大纲侧栏**：右侧常驻面板按创建顺序列出每个节点（类型缩写 + 显示名），点一行把节点居中并放大到能看清它和邻居（取景窗口为节点 3 倍，缩放 50%–150%）；禁用/断供节点仍列出但置灰。列表由 `canvas.saveState()` 重建，`newFile()` 直接重建并 `canvas.resetView()`；可折叠，折叠态只存本地，不进草稿、不构成撤销。
- **节点库与输入**：左侧节点库可收成只剩标题行（`aria-expanded` 随状态翻转），按工作流/数据输入/数据处理/结果输出四组排列、各带颜色与标识；现有 13 个入口（分词已并入“处理”的一个操作），旧画布的 `TKN` 仍可加载执行，类型声明在 `backend/nodes/catalog.py`。`@media (pointer: coarse)` 放大按钮、菜单与连线命中区（桌面布局不变），画布加 `touch-action: none`；面板高度拖动与移动改用 Pointer 事件。画布内单指拖背景=平移、拖节点标题=移动、从端口拖到另一节点=连线、长按=节点菜单；两指同向=平移、张合=缩放（以中点为锚）。Ctrl/Cmd+滚轮或鼠标滚轮=以光标为锚缩放，触控板双指滚动=平移；分流按整段 burst 判定（`deltaX !== 0`、分数 delta、`deltaY` 相对上一事件变化任一成立即视为触控板）。相机永不进 `getState()`；`harness_canvas_ix` 用四个 wheel 场景钉住三职。

### 连线分支（fan-in / fan-out）
连线当下弹说明框（不阻断：线已写入，可“撤销这条连线”，可勾选本次会话不再提示）。后果与 `backend/engine/run.py`、`backend/engine/workflow.py` 同源。上游节点本身没有输出（“工作流命名”这类 `rows='none'` 的元数据节点）时整段不弹框：那条线本来就带不动数据，用户在连的时候就知道，没有后果可解释。

| 连线情形 | 目标 / 源节点 | 程序行为 | 结果 |
|---|---|---|---|
| 任意线连入 | 命名 `name` | 命名节点必须打头 | 运行前**具名拒绝** |
| 任意线连出 | 命名 `name`（`rows='none'`） | 该节点不产出表 | **不弹框**，连线保留 |
| 任意线连入 | 上传 / 评论 / 续跑 `upload`·`comment`·`resume` | 这三类完全不读上游 | 连线**静默无效** |
| 第二条及以后汇入 | 处理 / 可视化 `process`·`visualize` | 只取第一条上游表 | 提示“只用第一个” |
| 第二条汇入 | 数据源 `source` | 只读第一个带表格的父作链接源；该采集内容不接受上游时 | 前者只用第一个，后者**运行拒绝** |
| 第二条汇入 | 分析 `analysis` | 表连接只用两表（左/右），第三个起丢弃；非连接步骤只读第一个 | 提示 join 上限 |
| 第二条汇入 | 输出 / 保存 `output` | 每条上游表 `concat`，列集不同则具名拒绝 | 合并成功或拒绝 |
| 一个节点连多个下游 | 任意（fan-out） | 每个下游拿同一份完整快照，不分流 | **安全** |

合并多批采集请让多个采集/上传节点连到同一个输出节点。锁定：`tests/frontend/harness_canvas_ix.mjs` 的 `connect_warnings`、`tests/api/test_fan_in_fan_out_results.py`、`tests/unit/exports/test_output_merge.py`。

## 断点续跑与运行记录
- **运行队列**：一次只跑一个运行；运行中“执行”变为“排队运行”，请求被服务端存下并在当前运行结束后接着跑，排队列表在“运行记录”面板顶部、可逐条取消（最多 8 个，满了直接拒绝）。内存 `_RUN_QUEUE` 是运行时真源，每次变更把整表镜像进 `runs.db` 的 `run_queue`（payload 存原始 POST 体）；开机时仅在内存队列为空时按 `position` 回填，绝不覆盖活队列。
- **单节点重跑（含下游）**：运行详情每张已完成节点卡片有“从此节点重跑”，复用续跑机制：由 `connections` 求向下闭包 `{目标 ∪ 全部下游}` → `run_store.invalidate_nodes` 删掉这些节点的 `node_rows`+`node_runs`（上游保留行原样留着）→ 以 `resume_run_id` 走普通 `begin_run`，reusable 谓词只重跑被删空的子树。具名拒绝：节点不在当前画布、上次没完成、没有可复用既往运行、画布指纹与所选运行不符、另一个运行仍活着。
- **载入任意一次运行**：每个节点的表格输出按运行号存 `node_rows`，成败/行数/错误在 `node_runs`。画布打开时 `POST /api/runs/for-workflow`（同一结构指纹）默认载入最新一次，角标：绿勾=`done`/`restored`，黄色转圈=`running`，红叉=failed/partial/skipped/pending，没跑到的不画。载入后预览/图表/看板都带 `run_id`，服务端按那一次取行；载入不执行任何节点，继续算用“从此节点重跑”。“对比”另选一次运行，`GET /api/runs/compare` 先给共同节点的状态与行数变化，再对默认节点调 `DataAnalysisService.diff`，返回新增/消失/变化行、列增减与样本；工作流名/结构不同会标注。
- **跨运行采集水位**：数据源节点的作者投稿模式（目前仅哔哩哔哩）可勾“停在上一次运行的边界”；一次成功完成后把最新 BV 号写进 `source_watermarks`（按节点指纹，改关键词/账号/模式即另起），下次遇到该 BV 停止翻页、不请求它及更旧条目。只有完整结束的运行推进水位，墙/风控/停止/欠采都不写；与“重新采集”互斥。
- **累积数据集**：“累积数据集”节点接一张上游表、填累积集名称，每次运行把新增行追加到带版本的谱系并把全量表格传给下游；去重方式必须显式选“整行完全相同”或“按指定列”（按列必须填列名，缺列按名拒绝）。谱系在 `datasets.db` 的 `dataset_lineages`/`dataset_lineage_versions`；重置只清空谱系与版本指针，已存版本保留；项目包携带当前版本与谱系名称。
- **数据集合并与行级对比**：面板每行“加入合并”，选至少两份后命名合并；服务端按列集合校验（按第一份列序，多/缺列按名拒绝），默认插 `来源` 列，总行数受 `DATASET_MAX_ROWS` 约束。`POST /api/data/diff` 的两侧各是解析器载荷（`{dataset_id}`、`{node_id,workflow_name}` 或内联 `{data}`），按共有列做逐行规范化哈希的多重集差（`added`/`removed`），增删列单列；`changed` 只在调用方显式点名一个两侧唯一的键列时判定，绝不自动挑主键。
- **节点级检查点**：每步输出行持久化到 `data/runs.db`，工作流结构指纹 + 节点指纹决定复用/失效。标签不算参数：改工作流名、填排布顺序、改上传文件名不会让已付费的行作废；数据集/运行的 id 在指纹里，换文件必重算。LLM 答案缓存按 操作+提供方+模型+列+截断+主机+主题+提示词版本 缓存，改模板或参数即失效。采集去重按节点存条目指纹，续跑/重跑跳过已采内容并明示跳过数；“重新采集”清账本全量重抓。
- **中断、续跑与完成数**：服务重启后遗留的“运行中”记录由 `promote_stale_runs()` 标为“已中断”并按已落库的行回填“已存行数”，画布顶部出现续跑横幅，可“继续”或“重新开始”（前提是本机同时只跑一个服务）；同一判定也挂在运行记录面板的读取上。只做“复原”的节点（`restored`）下次仍算完成、仍直接回读。完成数只有一个口径：`n/N` 与控制台“N 个节点完成”一致，跳过/失败/部分完成不算、`restored` 算；结束行“几个失败”只数这次真跑过的节点，被停止剪掉的节点单独计“n 个被停止”。
- **Cookie 中途过期可续跑**：长采集跑到一半被挡回登录墙时，已抓的行早已落库，节点判“部分完成”、整条运行进入续跑横幅；换新 Cookie 点“继续”即从断点接着抓、不重复已存条目。撞墙那行只陈述被挡回登录页，不替爬虫宣称“已停止本次抓取”；评论节点只点名真正被撞回的平台。
- **运行前 Cookie 预检**（`cookie_preflight_before_run`，可开，默认关）：`workflow.js execute()` → `_cookieGateBeforeRun` 用这次真正会用的浏览器逐 (平台, 账号) 探测该模式是否需要会话（`Mode.needs_session`；weibo 热搜匿名、wechat 无会话可要）。登录墙直接拒绝启动（不留“照样跑”）；无法核对（验证码、超时、profile 被占用）不拦。结论缓存 `COOKIE_PREFLIGHT_TTL`，保存/删除/取回 Cookie 立即作废；关掉则什么都不问。CatBus 节点不受这项控制：清单声明 `auth: required` 的 cell 每次执行前用短命 Node 进程问，未登录按名拦下并给出 `catbus <平台> auth login`。
- **禁用节点与 Resume 节点**：每个节点头部有电源键，新增节点默认启用，右键可禁用整类；被禁用节点对运行完全等同于不存在（连同连线从 `engine.workflow.effective_workflow` 移除），校验/拓扑/分量/命名/续跑/记录都按“画布上没有它”。禁用向下游传染，但多入边节点只要还有一条活上游就照常跑；浏览器侧 `workflow.validateDetailed` 问同一张图。`enabled` 是控制态、不进数据指纹，所以禁用↔启用仍可续跑。Resume 节点收养历史运行的节点输出作为数据源，“选择运行记录”列出所有仍有数据行的历史运行（含已完成），按运行/节点挑一份，不要求画布结构一致；结构匹配只留给顶部续跑横幅。
- **记录形态与运行记录面板**：并行 = 一条记录，名字按画布顺序用 ` + ` 连接（查回旧行的键），`并行 ×N` 只在 mode 为 parallel 时出现，再加 `无头` 或 `窗口`；串行 = 每个开始执行的工作流一条（`串行 ×1`，各自状态/行数/可续跑），中止时还没轮到的不留记录。每行存整张画布指纹，HTTP 响应的 `run_id` 是第一个工作流那行，继续时各工作流按名字找回自己那行累加；一条记录含多个工作流时按 `node_runs.component`/`component_name` 分组，组名用 `_wf_display_name`，并行续跑是各工作流各自的状态。面板列出运行历史、节点状态与行数，支持丢弃、删除、按保留策略清理与面板头“清空”（三个“删除全部”都要显式 `confirm: true`，否则 400）；删一条保留其“已采集”认领，清空全部把认领一并交回，LLM 答案缓存不随清空删除。续跑会改写描述字段（mode/无头或窗口/工作流名/结构指纹/语言），`started_at` 保持原样；每条显示 `finished_at − started_at` 的时长（`MM:SS`，超一小时 `H:MM:SS`，续跑不刷新 `started_at`），运行中显示破折号，详情里每个节点也各带一段。面板会把自己开过、执行线程已不在的行判为“已中断”并写明原因。
- **执行历史与保留**：执行历史只保留趋势指标（情感/倾向分布与各节点行数），运行列表只在运行记录里出现。保留策略每工作流默认最近 20 次、30 天内，干净完成的先清、未写结论的最后清，单节点与单文件行数有硬上限；启动时清一次、此后每次运行结束按时间闸再清。被自动裁剪的运行交回“已采集”认领，手动删除保留认领。`logs/app.log` 满 5 MB 滚动为 `app.log.1 … .5`。

## 控制台
- **重连**：页面启动问一次 `/api/workflow/status?tail=…`（缺省 200 行，重连按上限 5000 行），整段重放已写行：在跑就接管轮询、重建并行分栏；跑完只重放并落一句状态，不重发结束 toast、不开续跑横幅、不自动弹控制台。重放把各视图游标推到服务端总数，下一次轮询只补新行；轮询定时器只有一个所有者（`workflow._pollTimer` + `_stopPoll()`）。
- **两条存储与各视图历史**：实时控制台只在内存（`execution_state['logs']`，保留 5000 行，重启即空）；文本另按运行号持久化进 `runs.db` 的 `run_log`（每条物理行都存，随运行删除/purge 级联），事后在“查看运行日志”里按级别/工作流过滤、搜索、加载更早、下载 .txt，这条路只读持久表；`logs/app.log` 是第三条进程级通路。服务端只保留最后 200 行，所以 `consoleViews` 按视图（`'all'` + 各工作流 id）各存 `{seen, lines}`，每次轮询都喂每个视图，切标签页按自己历史重画、游标各自前进，各留 500 行；`_push_log` 每条物理行一条记录。
- **噪声与节奏**：`_QUIET_NODE_TYPES`（`name`、`upload`）不播“执行中/完成”套话，但计数器照算、失败/跳过/复原的原因照发；`urllib3.*` 与 `werkzeug` 的记录按 logger 名从控制台过滤（文件日志保留），真实失败仍由“节点 X 执行失败”点名一次。“每次运行前清空控制台”默认开（连各标签页历史一并清空）；“慢速采集（降风控）”默认关，只把 DOM 走查与评论面板逐屏停顿乘以 `GENTLE_PAUSE_FACTOR`（4×），不碰浏览器身份、不伪造指纹。
- **停止与页面判定**：停止请求立即把记录写成 `stopping`，worker 到点用真实结论覆盖；抓取每行入库前问一次“可以停了吗”，被停的运行写成“被停止”而非“失败”，已付费的行保留且可续跑。“停止”要等这次启动的节点线程真的退出才交还运行槽，进程管理面板可强杀残留浏览器进程；强杀后 `crawler.driver` 换成死驱动会话，任何命令立刻抛 `CrawlerStopped`，停止后“抓取自己回来了”也按被停止处理（共享走查以返回已采行表示 honor，评论引擎握 crawler 而非当时的 driver）。“页面没到”与“站点不给看”是两句话：首屏内容等 `Config.PAGE_WAIT_TIMEOUT`（`Crawler.wait_for_first_content`），滚动后有没有新行的 14/12/3 秒是进度判据；等待期间每拍问停止、见到墙或浏览器错误页立即收尾、同一浏览器连续两次拿不到就停止重试。到点仍无内容时控制台给出等了多久 + 哪个节点 + 本机网络诊断（`services/ingest/net.py` 分 区域不通/本机断网/站点侧连不上/单纯没渲染，最后一种不指出原因）。`crawlers/engine/wall.classify` 答 `ok`/`login`/`blocked`/`unreachable`，第四种读 `document.documentURI` 识别浏览器错误页，不写 `login_wall`/`risk_blocked`、不要求重存 Cookie。

## 界面
- **中英双语与主题**：前后端消息全套 i18n 目录，界面一键切换，日志按请求语言输出；每个新增文案进本域 `i18n_catalog` 与浏览器词典两边。亮色主题是设计系统化的浅色界面，网格背景画布，主题色与圆角可调。
- **平台名与确认框**：Cookie 面板逐平台用界面语言说“已存 Cookie/未存”；要丢东西的确认一律用页面自己的对话框；续跑横幅向下让开菜单高度；导出产物统计是表格下方居中总结行；平台名统一——`zhihu` 是矩阵与 Cookie 文件的键，`{platform}` 由后端翻译，前端弹窗共用同一份词表（`TestPlatformLabelParity` 钉住）。四张 JS 生成的表（运行记录/导出产物/数据集/工作流文件）在语言切换时当场重画；图表库缺失时写“图表库未加载”，不留空框，启动步骤各自经 `boot(name, fn)` 兜异常。
- **等回答也认落地时的那张表**：运行详情、续跑下拉、工作台网格都是“发请求→等回复→写界面”，期间面板会刷新；三处都在回包后按 id 重新找一次，找不到就不写，绝不把答案写进已脱离文档的子树。

## 底部面板
- **共用槽与锁**：控制台、运行记录、导出产物、数据集管理、工作流文件共用同一个底部槽，打开一个收起其余四个并清残留内联高度，五个都可拖高。条目“锁”（导出产物/运行记录/工作流文件）每行一个 🔒/🔓：锁住的条目在“清空”时跳过、单独删除 409，直到解锁；锁状态在 `data/locks.json`，界面启动读一次，服务端是唯一裁判。
- **工作流文件**：列出 `data/workflows` 的每个画布，可打开/复制/重命名/删除，正在编辑的标“当前”。“复制”不问名字也不打开副本：服务端取第一个空闲的 `名字 (2)`（与项目导入同一条尾巴，绝不覆盖已存在的画布）并把数据集引用一并绑到新名字，画布仍停在被复制的那份。重命名同时改文件里的 name 与引用它的数据集记录，目标已存在返回 409 并原样显示原因；损坏文件仍列出（标“已损坏”、只给删除）。打开/重命名/删除在运行中都拒绝，复制只读源文件所以照常可用。每一行的操作按钮在放不下时换行显示，不省略、不隐藏——看得见的才能点。File 菜单“导入”从磁盘选 `.json`，先 `parseWorkflowFileText` 判定再动画布，非 JSON/无节点列表都具名拒绝且不改当前画布；导入只填画布、不写服务器。
- **导出产物**：`data/exports` 按时间倒序列出，可逐个下载/删除；名字按名解析，`../`、绝对路径、子目录一律 404，脚本/可执行扩展名可见但不下发。面板头“清空”与单条删除共用解析器，只删列出的名字，有运行在跑时整个请求被拒。“按运行清除”删某次运行产生的全部文件，“清除分片”只删某次运行某个数据源爬出的分片、保留合并文件；二者靠 `run_files` 台账定位（文件名不可靠），跳过“固定”条目、有运行在跑时 409，成功的名字同步忘出台账，“按运行清除”只清磁盘产物、不动运行记录与已存行。
- **论文成稿（LaTeX PDF）**：报告对话框的按钮只发 `run_id` 与标题，图与三线表由服务端从这次运行已登记的 LaTeX 源读回（浏览器不上传 LaTeX，否则 xelatex 成了读任意文件的路）。产出 `article`+`ctex` 一份文档：方法段逐节点参数（只从已保存画布读，与运行指纹核对，核不上点名）+ 图 1/表 1…（`[H]` 钉位）+ 运行编号与时间窗；先写 `.tex` 再编译，失败留下可排查的源文件，绝不留半份 PDF；`.tex` 与 `.pdf` 都记回台账。
- **文献计量工作区**：顶栏、状态栏与面板关闭共三处 `toggleBiblioPanel()`，与其他 dock 共用底部槽。读 `/api/biblio/runs` 与 `/api/biblio/table`（持久台账，重启/刷新/改画布后仍找得回）：运行下拉、该运行的 `biblio` 节点下拉、输出形态标（`nodes`/`edges`/`clusters`/`bursts`/`dual_map`，判不出显示“输出形态未知”）、200 行分页与页内筛选（行数按服务端 `total`）、GraphML/GML/JSON/CSV/Pajek 下载（名字由服务端给）、以及在画布中定位（节点不在时照实说）。表头取本语言词、磁盘列名留 `title`；带 `data-biblio-keep` 的输入在重绘后交还焦点。项目=命名的研究对象，快照=某 `biblio` 节点的一次捕获（参数只从已保存画布取并核对指纹，核不上记 `params_verified=0`）；对比由 `compare_snapshots` 算节点/边/簇/突现的增减、逐列变化与变了的参数名。

## 定时任务
到点自己跑一份已存画布，为无人值守的服务器准备。入口：顶栏 Run 菜单、状态栏按钮、面板关闭按钮；面板是底栏停靠的一块。
- **时钟与路径**：`python app.py` 起来后按 `SCHEDULER_TICK_SECONDS`（默认 20 秒）看清单，只在 `__main__` 启动，热重载时只在真正的服务进程里起。到点一律走手动 Run 同一条路径（`engine.run_schedule.start_scheduled_run` → `begin_run`），忙时照样排队。
- **时间写法**：预设（每天/每周 `HH:MM`、每 N 分钟）与五段 cron，每任务可指定 IANA 时区（留空=服务器本地）。`scheduling/cron.py` 只用 stdlib `zoneinfo`：`*`、范围、列表、步进、月/周英文三字母、`0` 与 `7` 都是周日、日与周按 POSIX 取“或”、`@daily` 类宏；春季跳过的钟点整段跳过，秋季重复的只跑第一遍；永不触发的写法在保存时就具名拒绝。
- **不碰模型与错过的时刻**：画布里有需要模型的节点（清洗默认 LLM、情感/倾向/情绪的大模型模式、关键词 LLM、主题命名等）时，选择时即标不可定时并写原因，保存与触发各再查一次（`engine.run_schedule.scheduled_canvas`）；服务器不替你决定提供方，也不用环境变量里的 key。停机期间该响的点只在任务历史里记一条“已错过”并显示次数，绝不补跑，重新计时从现在往后排。
- **记账与面板**：每任务有“最近一次”与最多 20 条历史，拒绝原因、崩溃堆栈各记各的；控制台只在一趟真的启动时得到一行归属消息，排队那趟由队列讲，拒绝那趟不写控制台。下次/最近时间、触发句子、能否定时全由服务端按任务时区给出（`next_run_local`/`last_run_local`/`runnable`/`why_not`），状态词只把 token 换成当前语言，认不出的原样显示；`tests/unit/frontend/test_frontend_schedules.py` 驱动真实 `schedules.js`。数据在 `data/schedules.json`，坏文件隔离成 `.corrupt`，同一份 `data/` 只应有一个服务进程。

## 节点类型
全部 16 个注册类型（`backend/nodes/registry.py` 的 `registered_types()` 与 `backend/nodes/catalog.py` 的 `PLUGINS` 一一对应）。

| 节点 | 标识 | 说明 | 能否独立运行 |
|---|---|---|---|
| Name（命名） | NAM | 工作流元数据，标签作为工作流名供历史/运行记录归组；另带“排布顺序” | 是（纯元数据） |
| Data Source（数据源） | SRC | 先选平台、再选采集引擎（Selenium / CatBus），功能列表随引擎变化；CatBus 独有平台与功能全读适配器清单，不可运行的一对置灰并写原因。**关键词采集**覆盖 知乎/微博/小红书/哔哩哔哩/YouTube/X；抖音与红果短剧没有关键词模式（按名拒绝）；微信按粘贴的推文链接采正文。**某作者的作品**在 知乎/微博/YouTube/X/哔哩哔哩/抖音 可选，填主页链接或对应 id（知乎 `/people/` 后的 id、微博 `weibo.com/u/<UID>` 或数字 UID、YouTube `@handle`/频道链接/`UC…` ID、哔哩哔哩 `space.bilibili.com/<UID>` 或数字 UID、抖音 `douyin.com/user/…` 链接或 `sec_uid`）。**热榜/热搜**：哔哩哔哩、微博（无需登录态，`needs_session=False`）、知乎、抖音、红果短剧（四榜各 5 页、每页 20 条，不需登录/Cookie；另有评论模式，经本地代理驱动桌面播放器收割 App 协议评论页，**仅 Windows**，见 [collection.md](collection.md)）。采集内容切到“评论”即评论采集器；可选项与运行前本地校验都读 `/api/capabilities` | 是，需平台+关键词/作者（或链接/榜单） |

### 双表角色与重爬缺口
- **角色按连线顺序**：表关联、反向筛选与采集校验都读第 1 条数据线作第一张表、第 2 条作另一张（命名节点的线不算）。面板把两条上游标题连同角色列出（“被筛选的表/作为依据的表”“清单/结果”），卡片同样；“交换两张表”同时翻转面板与卡片角色，运行时控制台再打印一行具名角色。
- **反向筛选（`anti_join`）与重爬闭环**：保留第 1 张表里没有出现在第 2 张表对应列中的行（切成“出现在另一表的行”就是找重复）；匹配五种：原样/去空白（默认）/链接归一/文本归一/近似文本（SimHash，上限 15 位），多列逗号分隔、两侧列数必须相同，空白键永不参与匹配并会被计数写日志；输出是第 1 张表自己的列，行序不变。重爬走 `帖子采集（清单：链接+评论数）→ 评论采集（输入列=链接）→ 采集校验（清单=帖子表，结果=评论表）`，校验默认只输出没采全的行且保留清单列，用输出节点存文件、上传后接回“链接”，只重爬这些文章（同一画布内不能直接接回，那是环）；再跑一次校验，缺口应归零。
