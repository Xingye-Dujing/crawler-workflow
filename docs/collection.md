# 数据采集（各平台细节）

> 本文是采析绘文档的一部分，返回总览见 [README.md](../README.md)。

各平台采集的内容、字段、模式、选项与上限。逐平台选择器/翻页/字段来源等**真机实测证据**见 [crawler_notes.md](crawler_notes.md)，本文只讲面向使用者的「采什么、有哪些字段、能怎么填」。

## 数据采集
- **多平台爬虫**：支持知乎、微博、小红书、微信公众号、哔哩哔哩、抖音、红果短剧、YouTube、X（推特）共 **9 个平台**的数据采集
  （Instagram 已可保存 Cookie，采集实现待接入；快手 / TikTok / 京东 / 淘宝 / 闲鱼 仅经 CatBus 引擎提供，见「第二采集方式」一节）
- **采集量只由你填的目标数决定**：后端不再有任何翻页数/滚动轮数/时间窗宽度的硬编码上限（原有的「微博每窗 5 页、超过 720 小时拒绝、
  B 站 40 页、抖音 12 轮、YouTube 20 轮」等全部删除）。一直采到目标数满、或站点自己说了「到底」（它印的结束标记、它明说的空结果），或撞登录墙为止；
  目标数留空就是把这份列表采完。微博小时窗现照站点头部链接深度翻页，续跑语义是**被 停止 打断的那一窗会从头重走并翻到底**——游标只记位置、
  已付费的行靠台账去重，所以重走只花请求、不重复存行；「这一页没有新增」绝不再被当成「这一页没有内容」（后者才是收工的唯一信号）。
- **慢速采集开关（设置里，默认关）**：开启后只把采集节奏放慢——DOM 走查每轮礼貌停顿（`_polite_pause`）与抖音评论面板逐屏等待统一乘以
  `GENTLE_PAUSE_FACTOR`（约 1 秒变约 4 秒），**绝不改浏览器身份、不伪造指纹、不做任何伪装**。页面「等内容出现」的渲染预算**不**被缩放——那不是礼貌
  节流而是死等。唯一理由：撞风控后「慢下来退避」是比「更会伪装」既安全又真正有效的做法——伪装是与平台风控军备竞赛，输了直接封号。
- **欠采判定（U1/U2）：站点没自报到底的短表，不再被静默判成「完成」**。执行器与爬虫之间新增一份「这次为什么停短了」的具名契约：只有**站点给的事实**
  （它自己的结束标记、它发布的固定榜量、它明说的 200-空结果）才算合法收尾；**「我们自己的循环说它没长了」不算**（软限流会伪装成它）。落地是**逐平台
  opt-in**：有站点自证结束信号的平台（抖音作者、知乎搜索/热榜、微博热榜、YouTube 搜索续页、B 站热榜、**红果短剧四个榜**）已接上**许可**侧。
  **判欠采（convict）侧只有一个平台触发：红果短剧**——它的翻页地址是站点自己给的（`pagination.nextUrl`），「下一页指回当前页」与「连着两页没有新条目
  而站点仍给下一页」都有可归因的正向信号，报「采得不足」并保留已采行；其余平台仍**一格都不触发**（要等各平台真机测出一个"确实没采完"的正向信号后才接）。
  **风控**现在有了**自己那一句**：节点把某次短采标记为 `risk_blocked`（抖音「验证码中间页」只写在标题里、`classify` 读不到，故在撞它处专门置此标志）时，
  执行器报**「风控拦截，非登录态失效，勿立即重跑」**并保留已采行、置运行失败让「继续」可见——话术只让你**退避后再继续**（建议开慢速采集），从不叫你重存 Cookie。
- **视频平台字段**：哔哩哔哩每行给出 播放/点赞/投币/收藏/转发/弹幕/评论数、时长、分P数、合集、UP主、发布时间与视频简介（取自视频详情接口，非搜索卡的
  「140.5万」式近似标签）；抖音给出 点赞/评论/收藏/转发、作者、发布时间与完整文案（含话题标签）。**作者粉丝数与获赞数只在页面发布它们时才填**，读不到
  就留空**不填 0**（0 是一句「这个账号没人关注」的假话）。抖音逐条详情页作者取自 `[data-e2e="user-info"]` 里那条 `sec_uid` 链接的文字（页面自标为作者的
  那一块），「什么算一行」：**身份是文案或发布时间，作者不算**——只带别人名字的空行按具名跳过，不占 target 一格。抖音**刻意没有播放数列**（网页播放器不展示
  播放量，宁可不给也不写"列名看起来对、数字是错的"假数据）。
- **抖音作者模式走「站内遮罩」读取，不再逐条跳转 `/video/<id>`**（2026-09-30 实测，见 `docs/crawler_notes.md`）：点开网格卡片是在同一文档弹预览遮罩
  （URL 变 `?modal_id=<id>`、不发生整页导航），读完 ESC 关掉再点下一张——省掉了过去的 N 次 `/video` 整页加载（那阵导航风暴是把账号推进「验证码中间页」的诱因）。
  代价：遮罩里发布时间比旧详情页粗（只有日期、解析不到留空不造假）、作者取 `feed-video-nickname`、粉丝/获赞改从个人页读一次套用。**卡片点不开时该行本轮
  跳过、绝不回退去开 `/video` 页**；整轮采到 0 条而卡片明明存在，具名判为欠采（可断点续跑），不被「没有更多了」许可成完成。评论模式仍按粘贴链接打开视频页，
  会展开「展开N条回复」子回复、把每条子回复也收成独立行（须对真正的 `button.comment-reply-expand-btn` 做原生点击），为此评论表新增 **`父楼层`** 列、父评论
  **`子回复数`** 改记实际展开到的子回复行数。「评论已删除/前端不可见」的线程试一次即跳过、绝不重试。详见 `docs/crawler_notes.md` U50。
- **抖音评论：面板走到底、楼层一路编号**（2026-09-28 实测，见 `docs/crawler_notes.md` U43/U46/U47）：评论面板原来带 40 轮上限（一条站点自报 3388 条的视频
  停在 406 行还报 `ok`）；现在收工只看三件事（这一屏没有新行 / 滚动盒子不再长大 / 你按的 停止 或 你填的 评论条数），走完仍够不上站点自己那个数时报出差额
  （`declared / rows / 子回复 / gap`），并把这次怎么收的工一起报出。楼层现是整条 thread 的连续编号（以前每滚一屏从 1 重数）。一个不存在的视频链接会被站点换成
  另一条视频回答，旧读法写成「登录墙/风控」——现按**该链接失效**处理，你的登录态不再为一条死链接背锅。
- **抖音「关键词搜索」模式已移除**（2026-09-28 实测 + 用户判定）：它的搜索供给本身就浅——同一关键词两次复测分别只给出 26 条与 16 条，且都没到站点自己的
  「暂时没有更多了」收尾；不是账号被标记、也不是我们少读。既然「只能爬一点」，该模式连同底层 `search()`、可选排序菜单（`engine/menu.py`）与相应真站用例一并删除。
  **抖音仍保留 作者 / 热榜 / 评论 三种模式**，Cookie/登录不变。旧的抖音「关键词搜索」节点在移除后由执行器按名字拒绝（`engine.source_unknown_mode`：该节点没有这种
  采集内容，请在「采集内容」里改选），**不会**静默改爬作者。**因此抖音没有关键词采集模式**——Data Source 节点的关键词模式只覆盖 知乎/微博/小红书/哔哩哔哩/
  YouTube/X（推特） 六平台（`backend/capabilities/registry.py` 里带 `posts` 模式的平台；红果短剧同样无关键词，只有热榜与评论）。
- **抖音结果列表里的图文帖，本机读不到**（2026-09-28 实测）：卡的 `href` 全是 `/video/<id>`，但一部分打开后被重定向到 `/note/<id>`，那台设备访问 note 页
  只拿到「验证码中间页」。这不是解析坏了，视频页照常出数，所以这一类**逐行报名**「被站点挡在验证码中间页」而**不**把整轮判成 cookie 失效。
- **无头现在带桌面指纹，抖音/X 不再强制窗口**（2026-09-26 实测，#148）：一个裸 `--headless=new` 只露 `HeadlessChrome` UA 与 800×600 虚拟显示，抖音/X 拿
  这两样判它验证码/403。`base.py` 现给无头会话改写这两样（CDP 换 UA + 回填窗口度量），实测抖音与 X 在伪装无头下都交出真行，于是类上的 `never_headless` 删了、
  执行器不再把无头偷偷换成可见窗口。今天判墙要读抖音自己的 `_wait_for_page()`（`captcha`/`not_mounted`/`ok`），通用 `check_intercept()` 在这种标题下会说 `ok`。
- **登录/生成的浏览器删掉「页面上能读到的 chromedriver 痕迹」（每一台浏览器）**（2026-09-29，#18）：启动早把 `navigator.webdriver` 变假、去掉「受自动测试
  软件控制」横幅；现代风控（谷歌 BotGuard）还从页面里读 chromedriver 注入的 `window.cdc_…` 全局。`base.py` 现用一段 new-document 脚本把这些全局删掉（设备层
  `test_driver_surface.py` 真 Chrome 两侧验）。它刻意不改 `navigator.webdriver`、`navigator.languages`，也不伪造 `window.chrome.runtime`。**三道这遮不住的上限**：
  CDP 调试器附加、全新未受信任设备、以及站点另开的弹窗是另一个 CDP target（谷歌/苹果 SSO 正是弹窗）。所以这不保证 X 登录一定通过：顽固 SSO 仍走邮箱密码登录或导入 Cookie。
- **热榜/热搜：各平台的榜、各不同的答案**（逐条实测，详见 `docs/crawler_notes.md`）：微博热搜一次页内请求回 51~52 行、热度是**精确整数**、并且**不需要登录态**
  （匿名会话同样回答，所以只挂热搜的画布不会被运行前 Cookie 预检拦下——这是矩阵 `needs_session` 字段的由来）；知乎热榜**整块就是 30 条**、站点无视一切翻页参数，
  目标数填更大只会被告知「榜只有这么多」，无 Cookie 时首页直接跳登录；B 站热榜维持两张表（热门榜分页 + 周排行榜一次回整张表）；**小红书没有热榜**（`/hot`
  重定向回普通信息流，唯一 trending 接口是搜索提示词且页内重放返回 406）；**抖音热榜已上线**（实测两遍：在已加载 `/hot` 文档里用一个只由公开字面量拼出的 URL 问
  `aweme/v1/web/hot/search/list/`，回 51 行、每行带精确 `hot_value` 与 `view_count`，一次回答就是整块榜、不翻页也不逐条打开；本工具自己的抖音 profile 实测被答
  「验证码中间页」，所以会话必须是插了 Cookie 的一次性浏览器）。
- **红果短剧（hongguoduanju.com）四个榜已上线**（2026-10 实测，四榜 × 第 1/2/5 页各 20 条）：榜单模式里再选**榜单**——热播榜 / 真人剧热播榜 / AI剧热播榜 /
  漫剧热播榜（存储值 `hot_drama` / `hot_real_drama` / `hot_ai_drama` / `hot_comic_drama`，每榜 5 页、每页 20 条、排名跨页连续）。**一个榜 = 一张表**：不把四个榜混进
  一张带「榜单」列的宽表。榜单**不需要登录也不需要 Cookie**（与微信同类的匿名平台，Cookie 面板里没有它一行、节点上也没有账号可选）。页面自带完整榜单数据
  （`window._ROUTER_DATA` 里那一段 loader 载荷），因此**不点、不滚、不逐条开详情**：排名/作品名/评分/热度/收藏/点赞/分类/状态标签/集数/简介/作品ID/链接/播放链接/
  封面全来自这一个载荷——**集数**就是 `episodeVids` 的条数（与详情页实测一致，而 DOM 上播放窗只有 25 个链接，按屏上链接数会采错）。热度/收藏/点赞入库时把
  站点四舍五入的「万」标签展开成整数。翻页只走站点自己给的下一页地址；站点没有第 6 页（只有页脚布局、返回 0 条），续跑游标一旦落在第 6 页**具名报错**而不是交空表。
- **红果短剧的「评论」模式：不签名、只旁听**（2026-10-19 全链实测，机制与全部红线在 `docs/crawler_notes.md` 红果短剧）：红果评论只活在 App 协议里且签名覆盖请求体
  （原样重放也回 `110001`），所以这个模式**不开 Selenium 窗口**：它带本地代理启动第三方桌面播放器（hongguo-player，需已在播放器里登录），由播放器完成签名与请求，
  节点从 mitmproxy 明文响应里收割 `comment/list` / `reply/list`。链接字段收**详情页链接**（`hongguoduanju.com/detail?series_id=…`），**也可以直接收剧名**（每行一个，
  或喂上游热榜表的 `作品名` 列）——网页热榜与播放器排行榜是两套排序，剧名才是客户端答得出的输入；按剧名采时 `文章URL` 留空（没打开过网页就不编造链接）。
  输出列除共享的 `文章URL`（八平台评论表的 join 键）外还带 **剧名 / 集序号 / 分集ID**；每部剧按「采集集数」逐集走查，默认连子回复一起采（每集会点开屏幕上所有
  「展开…回复」，绝不点评论自带的 `回复` 按钮——它抢走翻页所需的键盘焦点）；弹幕引导行被丢弃并计数。某集/某剧没收满会在节点结束时**具名报错**，已采行照常保留入库；
  台账按 `平台 + 评论ID` 认一条评论（同一条换楼层仍是同一条），重走只花播放器时间、不再重复存行。发现播放器已开着（不带本代理）会**具名拒绝**而不是杀掉你的窗口。
  **每页属哪部剧只问播放器发出的请求**（`req_body.business_param.book_id`）；网页 `series_id` 与客户端 `book_id` 是两个 id 空间，参照物是走查第一页自己的 book，
  绝不互比。一旦发现流量切到别的剧，节点**具名报出那部剧的 book 并停止本剧余下集数**（`feedDrifted`）。走查还**先问屏幕再收行**（播放器界面印着 `@剧名` 头部），
  屏上稳定报出另一部剧则**按名停止不再往下采**（`screenMismatch`）。设置面板新增四项：红果播放器路径（必填）、mitmdump 路径（留空自动）、收割代理端口、自动安装抓包证书。
  依赖 `mitmproxy` / `uiautomation` 在 `requirements-optional.txt`（Windows 桌面功能，缺失时该节点具名拒绝，其余平台不受影响）。
- **评论跟不跟无头走，只看你这次选了什么**（2026-09-26 实测，#148 收口）：过去评论执行器会替滚动型面板（知乎、小红书、抖音）在无头运行里强开可见窗口；现在无头
  Chrome 带桌面指纹，实测知乎评论区伪装无头 5/5 == 可见窗口 5/5，这条强制彻底删了：无头运行一个窗都不开。矩阵里每个模式仍声明 `collects`（取数/读 DOM/滚动/逐行开页），
  但它如今**只喂面板提示**——不再是任何执行开关。随之删除 `forced_visible` 列（保留为历史列、恒 0）与运行记录上「无头→窗口」那个 chip。共享的两趟走法：先把列表读够、
  收齐视频 id，**再**逐条打开详情页（旧写法交错时每次只交第一屏的量且一句拒绝都没有）；等的是页面「有锚点」而不是「有节点」（站点会先挂骨架行、约 4~6 秒后才填真数据）。
- **抖音「某作者的作品」**：填作者主页链接（`douyin.com/user/…`）或链接里那串 `sec_uid`——抖音 web 只认这个不透明 token，填昵称会被直接拒收。**作品网格只认它
  自己的滚动容器**（按"屏上锚点数"判进度会在 57 条处收工而那一页自报 85 条；改成把网格可滚动祖先 `scrollTop = scrollHeight`，每轮稳定多出一批 18 条，实测 21→39→57→85
  等于页面自报作品数）。计数逐条打开视频页取，所以作者模式与评论模式行字段一致；页面自报 0 作品→合法空表；自报 N 条却一条都没渲染→报可执行错误并引用页面自己的话。
- **为什么默认不加载图片，却仍然加载视频**：图片对抓取没有任何用处，所以浏览器层面默认拦掉。**但"人眼要看的窗口"必须显式允许图片**：抓取写下的封锁会被 Chrome
  存进持久 profile 并跨会话存活，登录窗只"不写这个偏好"会继承封锁、二维码是 `<img>` 于是码扫不了；现在取 Cookie 与验证 Cookie 的两个窗都显式写"允许"。**视频拦了不省时间**——
  七个可爬平台逐一 A/B 实测持平或普遍略慢（视频在后台并行下载，掐掉它不会更早拿到一行数据），唯一真实收益是省流量（抖音每行约 0.6 MB，其余为 0），默认不开。详见 `docs/crawler_notes.md`。
- **评论采集**：数据源节点把「采集内容」切到**评论**，粘贴所选平台的文章链接（一行一个）即可批量抓评论；评论引擎按 `core.refs.comment_platforms()` 路由**八个平台**——

- **分批输出（不必等运行结束）**：采集节点可设「分批大小」，每满 N 行先落一个带编号的分片文件，运行中即可打开查看，节点结束时合并为单个文件；LLM 处理节点可勾选「实时导出」，

  时间范围」勾选，**只在该输出节点上游确实有一个采集节点同时声明了起止时间时才出现**；若旧画布仍存着这个标志，后端在**一条链上没有任何窗口、或有两个不同窗口**时忽略它、照常写文件并记一行说明。

- **输出文件名可自动带上本次运行时间**：输出节点勾选「文件名追加本次运行时间（不覆盖旧文件）」后，落盘名变成 `导出名-YYYYMMDD-HHMMSS.csv`。时间戳只在**写文件那一刻**决定，绝不写进
  节点参数（参数一动节点指纹就变）。一句实话：**续跑时输出节点若被判为「可复原」就不会再执行，也就不会有第二个文件**。
- **同平台采集有两种不同的秩序（设置里两个键，别混为一谈）**：
  - **真排队**（`same_platform_queue`，默认开）：同一平台一次只跑一条，后一条要等前一条整个跑完才开始（与持久 profile「一个目录只开一个浏览器」的承诺同一件事），所以开着它时并行
    同平台不再弹「用不用 Profile」确认框。不同平台照常并行。**排队不给平台加冷却**是量出来的（微博当天两次排队跑完不重叠、第二条仍被弹登录页看着像欠一次冷却，但随后同一账号 14 次采集
    全部正常，那堵墙是站点间歇风控，见 `docs/crawler_notes.md`）。撞墙真实处理只有一条：第 0 行就撞 → 等 `WALL_RETRY_BACKOFF` 重试。
  - **错峰**（关掉真排队）：同平台两条采集可同时跑，只把发车时刻按 `same_platform_stagger` 秒隔开（默认 12，可 0~600，填 0 完全不隔）。这保住了真并行，也避开「同一账号一秒内两次搜索」
    这一最狠形态，但管不了 profile 冲突，所以那一次的 Profile 确认框会回来。
  - **例外：微博永远排队，关掉真排队也不例外**（矩阵标 `serial_only`）：同一账号并行翻页必定被弹回登录页，这是实测的站点规矩、不是能被设置改掉的偏好。并行画布里有两条以上微博采集时，
    执行前会单独弹一个窗说明微博只能串行、继续即自动排队。
  - **微博也只认"同一个会话"，不接受它的副本**（2026-09-26 实测，代价是用户当天登录态被刷掉两次；详见 `docs/crawler_notes.md`）：站点认的是某个浏览器目录里一路滚下来的那份 jar，把 Cookie
    拷进另一个浏览器 = 第二台设备、同样被弹。推论：**同一时刻只跑一条微博，并且始终在同一条路径上跑**。间隔秒数交给用户，因为耐受度是账号的属性。第 0 行就被弹到登录页的采集会退避后重试一次；
    **已采到行之后**才撞墙是 Cookie 中途死亡，仍走「判失败 → 断点续跑」，绝不重试。
- **网络分区：海外平台需要外网（设置项「海外平台运行前问一句外网」，默认开）**。不挂 VPN 时 x.com / YouTube 打不开，而页面看不到这台机器走的是哪条网络——画布出现任何海外平台，
  按下执行时会先问一句「你的外网开了吗」：答"还没开"就不启动（免得交回一张空表被读成"什么都没搜到"），并且这一问排在 Cookie 预检之前。开关关掉就什么都不问。**只问这一个方向**：曾经这里写的
  "国内与海外不能一起爬、挂 VPN 时抖音回 502" 已被海外出口实测否掉（见 `docs/crawler_notes.md`）。判定来自采集矩阵每平台的 `region` 字段（`cn`/`overseas`），矩阵没说的平台不猜。
  同一套分区也切开了真机测试层：`live_cn`（关 VPN 跑）与 `live_os`（开 VPN 跑）。
- **每平台一个持久浏览器 Profile（默认开启）**：抓取与"取 Cookie"用同一个浏览器目录（`data/chrome_profile/<平台>`），所以对站点来说我们是同一台连续的设备——这直接针对实测到的两类失败
  （微博任何一次已登录页面加载后就会换票；小红书会在十几分钟内把我们"重放快照"的搜索会话踢回登录页）。规则是：**目录被用过之后就不再往里种 Cookie**（只有首次导入 `data/cookies/*.json`），
  抓取结束也绝不把浏览器当前 Cookie 回写文件（回写实测会把可用会话写坏）。「设置」面板能看到每平台 Profile 现状（未建立/首次将导入/已在使用）。**"用过之后不再种"曾留下一个洞**：粘贴进来的
  Cookie 只落在文件里、真正抓取用的 profile 永远不再读它。**现在保存即更新**：粘贴成功那一刻 `app.py` 就把这份 Cookie 种进该账号自己的 profile（`_plant_saved_cookie_into_profile`），不再需要
  第二个按钮（按钮与 `POST /api/cookies/refresh-profile` 已删除）。唯一当场做不到的是那个浏览器正被占用，此时保存仍成功、`sessions.profiles.needs_refresh` 会让下一次抓取自动带上它。种进去这个动作
  是 Chrome 唯一能写进 Cookie 库的途径（那个库被应用绑定加密，外部进程写不了）。**一条实测划出的边界**：Chrome 只把**带有效期**的 Cookie 写进 profile 库，会话 Cookie 关掉窗口就没了。详见 `docs/crawler_notes.md`。
- **同一平台多账号（限流的结构性解法）**：站点踢人踢的是**账号会话**，换个账号就是平行的第二条路。Cookie 面板多了一个**「账号」**输入框：每个登录都有名字，**默认那份也不例外**——它的名字就是
  `default`（输入框显示 `default` 而不是留空）。留空仍被接受（它是 `default` 的历史拼法，在 `CookieManager.key` 这唯一一处折成同一个账号）；新名字允许 `a-z0-9_-`（1–24 位）但统一按小写存储，
  所以 `Work` 和 `work` 是同一个会话。填一个新名字再点「浏览器生成」或「保存」，就得到 `data/cookies/<平台>@<账号>_cookies.json` 与独立设备目录 `chrome_profile/<平台>/<账号>`（默认那份一个字节都没动）——
  **锁按目录注册，所以两个账号就是两台并发浏览器，同一平台真并行不再必先排队**。**重命名一个登录**（`POST /api/cookies/rename`）把 Cookie 文件与它自己的浏览器目录一起搬或一样都不动；默认那份结构性拒绝
  重命名。**删除 Profile**（`POST /api/profiles/delete`）删命名账号自己的浏览器目录、不动 Cookie 文件；默认那份结构性拒绝；目录被采集占用时 409、本就没有目录时 404，都点名说清。采集/评论节点因此多了一个
  **「登录账号」**下拉：选项由后端在 `/api/capabilities` 按"此刻有哪些账号文件"实时生成，候选顺序与新节点默认值同源（都取 `CookieManager.accounts_in_order`，第一个就是新建节点要用的账号）。执行器把它交给
  `get_crawler(account=…)`——它选的是数据（哪个会话、哪个设备），故不进 `_VOLATILE_PARAMS`，但空值与缺席等价（旧画布升级后指纹不变）。**没有会话就按名字拒绝执行**（`cookie_preflight.has_session_to_test`：
  Cookie 文件**或**一个仍带着那份会话的 profile），绝不悄悄退回别的账号替谁登录；被拒的旧行为不是"报错"而是撞墙爬一张空表再报完成。运行前的 Cookie 预检也按 (平台, 账号) 逐对探测，缓存槽按 `path_segment` 折叠，
  `default` 与留空共用一份判定。
- **并行 + 同平台 = 运行前问你一次**：一份 profile 同时只能开一个浏览器（chromedriver 建会话前要预写该目录的偏好文件，实测两个线程同时建会话 8 次里死 2 次）。所以画布里有**两个以上互不相连的
  工作流采集同一平台**、且当前是并行模式时，执行前弹窗让你本次二选一：① **继续用 Profile**（这些采集一个跑完再跑下一个，这部分并行等于没有）；② **本次不用 Profile**（真的同时爬，代价是每个都是全新设备 +
  导入一份旧 Cookie 快照，正是那些站点会拒绝的形态）。答案只作用于这一次执行；取消即不开始。同平台但在同一个工作流里、或不同平台、或串行模式，都不会问你。
- **最大并发浏览器数不再写死**（设置面板两项）：并行运行时同时打开的浏览器数 = 同时跑的工作流数，以前固定为 4（`DEFAULT_MAX_WORKERS`）。现在按本次运行是**窗口**还是**无头**分别取「窗口运行最大并发浏览器」/
  「无头运行最大并发浏览器」两个用户设置（无头不出窗、可更宽），仍受 1~16 约束；改动即时生效。
- **采集建议弹窗**（设置面板「采集建议」按钮）：一屏总结哪些平台建议启用持久 Profile、哪些只能串行不能并行、哪些推荐并行采集、以及哪些平台自动化测试必须复用同一个真实 Profile 会话。内容**全部读自
  采集矩阵**（`profileRecommended`/`serialOnly`/`parallelRecommended` 三个平台级标记），界面不留第二份清单；矩阵没加载时**拒绝凭记忆作答**。"并行推荐"当前为知乎、哔哩哔哩（两会话实测可共存）。
- **Cookie 管理**：持久化登录状态（知乎/微博/小红书/哔哩哔哩/抖音 + X（推特）/Instagram/YouTube 共八个平台；微信**不在其中**——抓推文正文本来就不需要登录，唯一需后台登录的按关键词搜索因实测不可验证已移除）。
  其中 **Instagram 目前只能保存登录 Cookie，还不能作为数据源采集**：画布的数据源节点不会列出它，即便手写进工作流也会被按节点名明确拒绝，而不是回一张空表（YouTube、X 已实装，见上）。Instagram 卡在实测而非工时：
  带有效会话的可见窗口、无头、退出登录三种情况下，主页都只渲染头部信息与零个作品卡片，话题页直接跳 `/accounts/login/`；在没有观察到真实作品列表之前，照着一份不存在的 DOM 写抓取就是猜。扫码生成为后台单飞任务。
  面板按平台**说明用途与获取步骤**（`/api/cookies/flow`，中英双语），可粘贴「登录入口链接」——只接受该平台域名，越界链接明确告知改用平台登录页，绝不把别站的 Cookie 存进本平台文件（Google/Facebook 这类中转站 Cookie
  一律不收，`evilyoutube.com` 这种伪后缀同样拒）。另有**「验证 Cookie」**：带已存 Cookie 实地访问一次，结论是**三种**——被弹回登录页 = 失效；页面正常 = 可用；回验证码/风控 = **没能验证**（既不算可用也不算失效）。
- **运行前自动验证 Cookie（设置里可关，即 `cookie_preflight_before_run`）**：按下执行时先用这一次运行真正会用的浏览器逐平台加载首页，问它还不认这份 Cookie。回登录页的平台就地被拦下——弹窗点名平台、
  引用后台原话、带你到该平台 Cookie 面板；**刻意不留**「我确定，照样跑」（从登录页开始的抓取只会带回一张空表）。核不上的平台（验证码、超时、profile 被占用）只说明「无法核对」，**不拦**（没有答案不等于 Cookie 死了）。
  结论缓存几分钟（`COOKIE_PREFLIGHT_TTL`），保存/删除/扫码取回 Cookie 都立刻作废缓存。关掉这一项 = 什么都不问、什么都不拦，直接开始运行（旧的「执行前确认 Cookie」弹框已删除）。
- **「删除已存 Cookie」**：Cookie 面板可按平台删那份 JSON 快照。删除框与回话都会说清：抓取若跑在该平台自己的 profile 里，登录态存在 profile 里，**删文件不会把那个 profile 登出**（profile 只在第一次使用时导入快照，之后
  不再被覆盖），它清掉的只是"一次性浏览器"要种的那份快照。要真正换设备得重置 profile 目录。
- **「删除已存 Profile」**：与「删除已存 Cookie」并排，也出现在底部「已保存登录」表格每一行，删的是那台**设备本身**（`POST /api/profiles/delete` 移除命名账号自己的浏览器目录、把它登出，而不动 Cookie 文件）。
  它复用同一个 `deleteCookieProfile()`：面板按钮**不带参数**调用它（代表当前平台下拉 + 账号框那份选择），表格行则带自己那行的平台/账号。默认账号按结构拒绝；被采集占用 409、没有可删 404，都点名说清。
- **账号候选下拉**：账号框**聚焦/点击/输入**时弹出此刻真存了登录的账号（按创建顺序）。程序生成的名字按语言写成**默认账号 / 默认账号2**，用户自己起的名字原样显示；一个都没存时什么都不显示。它不是 `<datalist>`
  （datalist 只印 value，而默认账号 value 恰恰是空串）。下拉挂在 `<body>` 上并带上 `_csSource`，所以"点外面关掉面板"那条守卫不会把它误认成离开对话框。账号框每敲一个字下面那行状态就重画一次，不再多问一次服务器。
- **「已保存的登录」= 底部停靠面板**（状态栏按钮，与其他 dock 同一个底部槽位、互斥）。一个 (平台, 账号) 一张卡片，可就地「打开」或「删除」——卡片删的是它自己那一行，不是账号框里恰好写着的那个。「打开」把平台与账号
  两半一起落过去。清单**只有元数据**（条数与日期），**Cookie 值永不进前端**——那就是登录本身，而这个界面在云端部署时可能正站在一个陌生人面前。两件已被删掉的话（「其中 N 条关窗口即失效」「它的浏览器里就是这份 Cookie」——账号、
  Cookie 文件与 profile 目录现在一一对应、保存即种入、所有抓取都在带桌面指纹的无头浏览器里跑，这两句说的都是程序自己的事）；唯一还留给用户看的是真例外：保存时该账号浏览器正被运行占用。
- **微信的特殊处理（实测后确定）**：微信只采集**文章正文相关字段**，不采集**留言、点赞数、转发数**（多数会话里连阅读数也没有）。原因：微信把这几项放在只下发给微信客户端会话的凭证之后——实测 `show_comment=0`、文章 HTML 中
  `elected_comment` 出现 0 次、直接调 `mp/appmsg_comment` 返回「请在微信客户端打开链接」；换 UA、改写链接参数、甚至重放 `pass_ticket`/`appmsg_token` 都不改变结果。本项目**不伪装微信客户端**绕过该判定；更关键的是浏览器里"这篇文章没有
  评论"与"这次访问不被允许查看"完全无法区分，返回一张空表等于交出看着正常的假数据。因此数据源节点选中微信时不提供「采集内容=评论」，并给出**原因说明弹窗**（`explainWechatLimits()`）。评论采集请使用 知乎/微博/小红书。批量抓取在控制台
  **每篇只留一行**（成功：第 i/n 篇 + 标题 + 公众号；失败：第 i/n 篇没取到正文），微信的任何一条消息也不得承诺阅读/点赞/打赏这三个它取不到的数字。
- **微博"假登录墙"免疫**：微博搜索会先把浏览器闪到扫码页再弹回已登录结果流（站点设置的假象）；爬虫会等待页面进入终态后才判定登录墙，真掉线时照常明确报错，已采数据不受影响。
- **运行时浏览器设置**：chromedriver 路径、浏览器二进制、窗口尺寸、超时等可在设置面板修改，写入 `data/settings.json`，下次运行即生效，无需改代码重启。

## 第二采集方式：CatBus

本项目默认用 Selenium（本机浏览器）采集。数据源节点与评论节点按 **平台 × 引擎 × 功能** 组织：先选平台，再选引擎（Selenium / CatBus），功能列表随引擎变化。选 **CatBus** 时，采集由外部 CLI
`catbus-crawler-workflow` 以子进程完成，行仍走同一条落库、续跑、去重与水位链路，只是**换了一套登录态、一套限流桶、一套去重账本**。CatBus 是子进程（`services/ingest/catbus.py`、`crawlers/backends/catbus.py`），
它的单元格、行列与身份列都读自适配器自己的 `capabilities` 清单——**绝不复制进一张 Python 表**——每个失败都点名缺失的部分（没有 Node / 没有适配器 / Node 太旧 / 清单读不了 / 没有这个单元格 / 没有 CatBus 登录），
而不是答一张空表让节点结算 DONE。`backend`（`selenium`/`catbus`）按节点身份的一部分写进指纹（`selenium`/空被折叠掉），所以两个后端绝不共享去重账本、游标或水位范围。

### 让它真的能跑

1. 装 Node（CatBus 的 `engines`：`^22.22.2 || ^24.15.0 || >=26.0.0`）；
2. 装 CatBus（`npm i -g catbus-cli`，或用一份源码检出）；
3. 告诉本项目适配器在哪。**首选项是「设置」面板里的两栏**：「CatBus 适配器路径」可填 `…/crawler-workflow/cli.js` 或直接填一份 CatBus 目录（自动补上入口）；「CatBus 的 Node 程序」只接受程序本身
   （`node.exe` / `/usr/bin/node`），填成目录会被点名说明。两栏都留空 = 按本机系统查找。环境变量优先级：**面板 > 环境变量 > 系统候选表 > `PATH`**（`CATBUS_HOME`/`CIXI_CATBUS_CLI`/`CATBUS_CLI`，Node 同理
   `CIXI_NODE_BIN`/`NODE_BIN`）。存盘后立刻重新探测一次本机能力——缓存里那句「本机没有」不该把刚修好的选项继续压灰。
4. 在 CatBus 侧登录它自己的账号：`catbus <平台> auth login`（**不是**本项目的「打开浏览器登录」）。它的登录门按后端分别发问（`bilibili@work` 与 `bilibili@work#catbus` 是两个判定），绝不缓存成一份 Cookie 判决。

找不到 Node／找不到适配器／Node 过旧，**引擎选项**会列着但置灰并写明原因；某个功能 CatBus 不提供时，它仍留在功能列表里、置灰并带适配器自己的理由。运行前的校验会先拒绝不可运行的一对，不会让你为一个页面加载时就已经否决的组合付一次运行。
桌面安装包默认不打包 CatBus（要带 Node 运行时与百 MB 级模型），所以打包版里这个引擎是灰的——装好后依然可用，只是得自己装。CatBus 独有的平台（快手、TikTok、京东、淘宝、闲鱼）没有浏览器引擎，面板只列出 CatBus；独有功能（粉丝/关注列表、
热搜词、直播间、收藏夹、合集……）也只在 CatBus 引擎下出现。这些功能与参数全部读自适配器清单。

### 与浏览器后端的真实差异（都会打印，不静默）

| | Selenium | CatBus |
|---|---|---|
| 登录态 | `data/cookies/<平台>@<账号>.json` + Chrome Profile | CatBus 自己的 `~/.catbus/`（`catbus <平台> auth login`） |
| 续跑 | 页码/链接游标，只补没走到的 | 没有偏移量：重放同一张清单，由去重账本挡掉重复行 |
| 跨运行水位 | 边界在**请求之前**判定，旧条目不再请求 | 只界定「哪些行入库」，旧条目仍被请求一次（控制台会说明） |
| 账号字段 | 节点上的「登录账号」 | 「CatBus 账号」（留空 = CatBus 当前选中的那个） |
| 停止 | 结束浏览器进程树 | 结束适配器进程树（Windows/Linux 连子进程一起，macOS 无 `/proc` 只结束直接子进程） |
| 行 | 一行一个事务，边采边入库 | 同上：适配器产出一行就写一行，中途失败或停止都保住已经落库的行 |
| 模式专属的数据条件 | 全部由本项目实现 | **只接受适配器在清单里声明的参数**；填了它不消费且不是默认值的条件时**按名拒绝** |

**数据条件不再有「静默忽略」**：适配器在清单的 `params` 里声明每个功能消费哪些字段；节点上填了 `start_time`/`end_time`/`comment_preview`/`board` 等会改变采集范围、又不在这张清单里（且不等于默认值）的条件，运行前会得到一句点名拒绝，
而不是一张看起来执行过条件的表。`per_article_file` 那类**文件形态**的开关不受影响：分片与按篇写文件都由本项目的写出层负责，与用哪个后端无关。已适配范围由 **CatBus 自己的能力清单**决定（`catbus-crawler-workflow capabilities`），本项目不另立名单。
