# 数据采集（各平台）

> 返回总览见 [README.md](../README.md)。逐平台的选择器、翻页与字段来源见 [crawler_notes.md](crawler_notes.md)，平台边界、登录墙与风控规则见 [crawler_rules.md](crawler_rules.md)。

数据源节点先选平台，再选采集内容；评论节点则按链接所属平台路由。下表是当前矩阵，`GET /api/capabilities` 是同一份声明的线上版本。

## 平台与模式

| 平台 | 采集内容 | 登录 | 说明 |
|---|---|---|---|
| 知乎 | 关键词搜索 · 某作者的作品 · 热榜 · 评论 | 需要 | 搜索可展开全文；热榜整块固定 30 条，目标数填更大只会被告知榜就这么多 |
| 微博 | 关键词搜索（时间窗）· 某作者的作品 · 热榜 · 评论 | 热榜匿名 | 永远串行；搜索按站点头部链接深度翻页 |
| 小红书 | 关键词搜索 · 评论 | 需要 | 评论楼中楼逐条原生展开；链接被送回首页按失效处理 |
| 微信公众号 | 文章正文 | 匿名 | 只取正文，不提供评论、点赞、转发、阅读数 |
| 哔哩哔哩 | 关键词搜索 · 某作者的作品 · 热榜 · 评论 | 需要 | 热榜有热门榜（分页）与周排行榜（一次整表）；作者模式点“下一页”换屏 |
| 抖音 | 某作者的作品 · 热榜 · 评论 | 需要 | 没有关键词模式；作者模式在已加载页面打开预览遮罩，不逐条跳转 |
| 红果短剧 | 热榜（四个榜）· 评论 | 匿名 | 评论需 Windows 桌面播放器；四个榜各是一张表 |
| 中国知网 | 文献检索 | 需要 | Refworks 导出后解析成标准文献表，可直接接文献计量节点 |
| YouTube | 关键词搜索 · 某作者的作品 · 评论 | 需要 | 页内 innertube JSON，海外平台 |
| X（推特） | 关键词搜索 · 某作者的作品 · 评论 | 需要 | 虚拟列表，按保留行数与推文 id 集合判进度，海外平台 |

Instagram 只能保存登录 Cookie，不是数据源。快手、TikTok、京东、淘宝、闲鱼只在 CatBus 引擎下出现。

## 采集量、收尾与欠采

- 采集量由目标数决定；留空表示采完这份列表。收工信号只有站点给的事实：它自己的结束标记、它发布的固定榜量、它明说的空结果。
- “我们自己的循环说它没再长”不算结束。站点没自报到底的短表按欠采处理，节点失败或 partial，已采行保留，“继续”从断点续跑。
- 撞风控时节点报 `risk_blocked`：保留已采行、置运行失败，话术只让人退避后再继续，不要求重存 Cookie。
- 停止永远可用；停止后已入库的行与断点游标都保留。

## 字段

- 视频平台给出播放、点赞、投币、收藏、转发、弹幕、评论数、时长、分P、合集、作者、发布时间与文案；抖音没有播放数列。
- 作者粉丝数与获赞数只在页面发布时填写，读不到留空，不填 0。
- 热榜每个榜一张表，不混成带“榜单”列的宽表；红果的排名/评分/热度/收藏/点赞/集数/简介等来自页面自带的榜单载荷。
- 评论列按平台提供：评论ID（站点印出来时）、楼层、父楼层、子回复数、点赞数、评论时间、评论地区；哔哩哔哩另有用户等级与 UP 主态。

## 评论

- 评论引擎按 `core/refs.py` 的 `comment_platforms()` 路由八个平台：知乎、微博、小红书、哔哩哔哩、抖音、YouTube、X、红果短剧；链接必须属于所选平台，面板、预检、引擎与抓取四层一致拒收外站链接。
- `comment_limit` 为评论上限，0 表示整条 thread。`comment_start`/`comment_end` 是表格侧的时间范围筛选，按日历天、两端都含；只填一端或解析不了按名拒绝。
- `include_replies`（“爬楼中楼（子回复）”）默认开；关掉后只采主评论：不再点开“展开 N 条回复”，也不把站点随接口带回的子回复入表，父行“子回复数”仍是站点自己的计数。声明在真正有子回复可采的平台上——知乎、微博、小红书、哔哩哔哩、抖音、红果短剧；X 与 YouTube 的评论本身就是整张回复列表，不出现这个开关。它选择数据，因此进节点指纹。
- 小红书滚到站点自印的 `- THE END -` 才合法收尾，并对账站点自己的“共 N 条”；登录门、重定向回首页、链接失效分别具名上报。
- 红果评论按“平台 + 评论ID”认一行，输入可以是详情页链接或剧名；每页属于哪部剧只问播放器请求里的 `book_id`。

## 输入与输出

- 评论、微信文章这类链接表单可由上游表格逐行喂入：填上游列名后手填链接框不再参与，一格多链接自动拆开，重复链接只爬一次。不接受喂送的模式接了表格、或填了列名却没接线，都按名拒绝。
- 采集节点可设 `part_size`（每满 N 行落一个带编号分片）与 `part_timestamp`（分片名带本次创建时间），节点结束时合并为单个文件；LLM 处理节点可开“实时导出”，每批原子重写 `{节点}.live`。
- 输出节点可勾“文件名追加本次运行时间”；只有上游采集节点确实声明了起止时间时，才出现“追加采集时间范围”的选项。
- 文件名分隔用 `_to_` 而不是 `~`（NTFS 会把它当 8.3 短名）；导出格式为 CSV 或 JSON。

## 登录、Profile 与并发

- 一个登录 = 一个 `data/cookies/<平台>@<账号>.json` 与一个 `chrome_profile/<平台>/<账号>`；默认账号名为 `default`，空值与它等价。保存 Cookie 时会同时种进该账号的 Profile。
- 持久 Profile 默认开启；一个目录同时只开一个浏览器。红果短剧不建 Profile（四个榜对匿名浏览器直接开放）；知乎、微博、小红书、抖音、知网的矩阵标记为“建议用持久 Profile”。
- 真排队（`same_platform_queue`，默认关）让同平台一次只跑一条；关掉时按 `same_platform_stagger` 错峰。微博无论设置如何都串行，并行画布里有两条以上微博会先说明。
- 并行 + 同平台会先问一次：继续用 Profile（同平台串行）或本次不用 Profile（真并行，但每个都是全新设备）。
- 最大并发浏览器按窗口/无头分别取设置，串行不受此限。海外平台上画布时，开跑前按 `ask_overseas_network` 问一句外网是否已开。

## 中国知网

填关键词与目标篇数，爬虫逐页点一次“全选”（站点跨页累计），最后走“导出与分析 → 导出文献 → Refworks”。下载的 `CNKI-…txt` 交给与上传同一个 `services/biblio/importer` 解析成 `记录ID/题名/作者/作者单位/来源期刊/年份/卷/期/页码/关键词/摘要/参考文献/DOI/格式`。新设备需先在 Cookie 面板完成一次滑块验证并保存登录；单次最多选 500 篇，目标更大时自动分批。

## 红果短剧

- 四个榜：热播榜、真人剧热播榜、AI剧热播榜、漫剧热播榜（`hot_drama`/`hot_real_drama`/`hot_ai_drama`/`hot_comic_drama`），每榜 5 页、每页 20 条、排名跨页连续；匿名可采，不点、不滚、不逐条开详情。
- 评论模式不开 Selenium：带本地代理启动第三方桌面播放器，由播放器完成 App 协议签名，节点从 mitmproxy 明文响应收割 `comment/list` 与 `reply/list`。播放器须已登录；发现它已开着但没走本代理时具名拒绝。
- 每部剧按“采集集数”逐集走查，默认连子回复；某集没收满在节点结束时具名报错并保留已采行。依赖 `mitmproxy`/`uiautomation`（`requirements-optional.txt`），非 Windows 与 cloud 模式按名拒绝。

## 第二采集后端：CatBus

数据源与评论节点按平台 × 引擎 × 功能组织。选 CatBus 时采集由 `catbus-crawler-workflow` 子进程完成，行仍走同一条落库、续跑、去重与水位链路，但换一套登录态、限流桶与去重账本。`backend`（`selenium`/`catbus`）是节点身份的一部分，两个后端绝不共享账本或游标。

1. 装 Node（版本按 CatBus `engines` 清单核对）。
2. 装 `catbus-cli`（`npm i -g catbus-cli`）或准备一份源码检出。
3. 在设置里填“CatBus 适配器路径”和“CatBus 的 Node 程序”，或设 `CIXI_CATBUS_CLI`/`CATBUS_CLI`/`CATBUS_HOME` 与 `CIXI_NODE_BIN`/`NODE_BIN`；优先级为设置 > 环境变量 > 系统候选表 > `PATH`。
4. 用 `catbus <平台> auth login` 登录它自己的账号，与本项目的 Cookie 无关。

单元格、行列表与身份列都读自适配器自己的 `capabilities` 清单（`services/ingest/catbus.py`、`crawlers/backends/catbus.py`），不复制进 Python 表。找不到 Node、没有适配器、Node 过旧、清单读不了、没有这个单元格或没有 CatBus 登录，每次都点名缺失部分，引擎或模式置灰而不是运行后才失败。

| | Selenium | CatBus |
|---|---|---|
| 登录态 | `data/cookies/<平台>@<账号>.json` + Chrome Profile | `~/.catbus/` 自己的账号 |
| 续跑 | 页码/链接游标，只补没走到的 | 重放同一张清单，由去重账本挡重复行 |
| 跨运行水位 | 边界在请求之前判定，旧条目不再请求 | 只界定哪些行入库，旧条目仍会被请求一次 |
| 账号字段 | 节点上的“登录账号” | “CatBus 账号”，留空用 CatBus 当前选中项 |
| 停止 | 结束浏览器进程树 | 结束适配器进程树 |
| 数据条件 | 全部由本项目实现 | 只接受清单 `params` 声明的参数；填了不消费且非默认值的条件按名拒绝 |

文件形态的开关（分片、按篇写文件）由本项目的写出层负责，与后端无关。桌面安装包默认不带 CatBus；独有平台没有浏览器引擎，面板只列出 CatBus。
