## 五、画布模糊的真实原因（重要，别再走弯路）
不是配色问题，是 `#canvas-inner`（**10000×10000** 的容器）带了
`will-change: transform` → 被提升为 GPU 合成层后纹理尺寸超过显卡上限（约 16k px），
浏览器强制降采样，于是**整块画布永久发虚，100% 缩放也糊**。
修复：删掉 `will-change: transform`；`updateTransform()` 里对平移量 `Math.round` 取整
避免亚像素偏移。★ 已确认样式表里**没有** `filter: blur` / `backdrop-filter`。
注意：style.css 里残留一行解释性注释含 "will-change" 字样，grep 校验会误报。

## 十一、数据来源改为「预筛选 + 理由 + toast」（本轮）
需求原话：数据来源应当是"让用户选节点，然后载入该节点的数据"；不是所有节点都能选，
要提前筛选、给出不可选理由，点击弹 toast。

**改前逻辑**（三条链路）：
- 数据来源 = `<select id="studio-source">`，`_refreshSources()` **同步列出画布上全部节点**，
  `Object.keys(canvas.nodes)`，零筛选，标签 `标题 · 类型`。
- 载入数据 = `loadSelected()` → `_payloadFor(nodeId)` 拼 payload → `POST /api/studio/dataset`
  （limit 5000）→ 后端 `_resolve_dataframe` 读 `execution_state['results']` 或 `_datasets`
  → `postMessage` 把行/列交给 iframe（桥接走 TSV 注入 `#paste-data`）。
- 保存回流程 = `saveBack()` → `zenviz:snapshot` → 桥接 html2canvas 截 `#chart-frame`
  → `POST /api/studio/save-image` → 落盘 `data/exports/`，toast 报路径。
- 三个毛病：不可选的节点**看不出来**，点了才知道；后端 `_resolve_dataframe` KeyError 时会
  **偷偷 fallback** 到第一个有结果的节点（`fallback` 字段），于是"选了 A 出来 B"。

**现逻辑**：
- 新增 `POST /api/studio/sources`（+ `_probe_source`）：逐候选返回 `{available, rows, reason}`，
  reason 是稳定码 `no_upstream / no_result / stale_dataset / empty / error`。
  探测**故意做得便宜**：node 结果直接读 `execution_state['results'][id]` 的长度、上传集直接读
  `_datasets`，不为每个节点 materialize 一份 DataFrame 副本；只有 upload-backed tokenize 的

- `zenviz.js`：`_refreshSources` → async `refreshSources()`。**静态死路**（visualize/output 未连上游，

  全不可用则塌成一行 `studio.src.none` 并把 select 与两个按钮一起禁用。

## 十二、节点被删后设置面板必须立刻消失（本轮）
**根因**：`canvas.deleteNode(id)` 只做了四件事 —— 移除 DOM、`delete this.nodes[id]`、过滤
`connections`、清 `selectedNode` —— **完全没管 `canvas._settingsNodeId`**。于是 `#node-settings`
面板留在屏幕上，内部输入框/下拉仍绑着 `updateParam('已删除的id', …)`；`updateParam` 虽然有
`if (node)` 守卫（静默 no-op），但从用户视角就是"节点没了，设置页还在，改了还像是能改"。

**修法**（把"面板不能比它的节点活得久"这条规则集中到一处）：
- `canvas.js` 新增 `closeSettingsIfStale()`：`_settingsNodeId` 存在但 `this.nodes[...]` 已无 → `closeSettings()`。
- `deleteNode()`：`if (this._settingsNodeId === id) closeSettings();`（节点自带的 X 按钮、
  右键菜单删除、键盘 Delete 三条路径**都**汇到这一个函数，改一处即全覆盖）。
- `_restoreHistory()`（撤销/重做）：`restoreState()` 后调 `closeSettingsIfStale()` —— 撤销可能把
  面板正在编辑的节点删掉。
- `openSettings(nodeId)`：原来 `if (!node) return;` 会**保留**旧面板 → 改为 `canvas.closeSettingsIfStale()`。
  这同时兜住了 `setLang()` 里 `if (canvas._settingsNodeId) openSettings(...)` 拿着失效 id 重渲染的情况。
- `loadFromJSON()` / `newFile()`：整块画布换掉且 **id 会重排**（node-1, node-2 …），旧面板此刻指向的
  是另一个节点，所以**无条件** `if (canvas._settingsNodeId) closeSettings();`。
- 关键依赖：`closeSettings()` 定义在 **workflow.js**，但 canvas.js 本来就在 `editNode()` 里调用它
  （同页全局函数，无需 guard），继续沿用。

## 十三、设置面板/节点被"点击内部"关掉（本轮）
需求原话：节点编辑页里点击节点内部不要让它消失；节点内部有的还有子菜单，点子菜单也不能消失。

**定位过程（值得复用）**：先用 linkedom 解析 `index.html`，打印 `#workspace.contains(...)`
和各元素的祖先链 —— 结论：`#node-settings`、`#studio-overlay`、`#context-menu`、`#console-panel`
**都是 body 的直接子级**（只有 `#canvas-inner`、`#nodes-container` 在 `#workspace` 内）。
这一步很关键：它排除了 `canvas.js` 里 `#workspace` 的 mousedown 处理器
（`!target.closest('.node') && !target.closest('.node-port')` → `deselectNode()+closeSettings()`），
说明点面板内部并不会命中它。

**真正的两个凶手**（都是 `mousedown`，都在 document 级 / body 级）：
1. `app.js:966` 的"点击外部关设置面板"监听：只豁免了 `#node-settings` 和
   `.node-action-btn, [data-action="ctxEdit"]`。于是——
   - 点**被编辑的那个节点本身**（header 拖动、body、端口、右键菜单里的折叠/复制）→ 面板关闭；
     节点 body/端口本来**不做任何事**（只有 `.node-header` 的 mousedown 会 selectNode+拖动），
     所以"点节点内部"唯一的可见效果就是面板消失，用户感受极差。
   - 点面板里控件的**弹层**（`.cselect-menu` 下拉行、`.cand-menu` 候选词）→ 关闭。
     这两个弹层由 `custom-select.js` `document.body.appendChild` 渲染（与面板不构成祖孙关系），
     所以 `closest('#node-settings')` 判断不出来。★ 坑：**任何 append 到 body 的浮层都会
     被"点外部关闭"逻辑误判**。
2. 顺带修的兄弟 bug：`closeSettings()` 只摘 `.open`（面板靠 CSS 右移 + `pointer-events:none` 隐藏），
   控件弹层留在 body 里继续可点 —— 面板滑走后仍有下拉悬在画布上，还能改一个已经看不见的节点。

**改法**：
- `custom-select.js`：两个弹层都记 `menu._csSource = sel|input`（归属控件）；新增公开方法
  `CustomSelect.ownsPopup(node, container)` —— 命中 `.cselect-menu/.cand-menu` 且
  `container.contains(popup._csSource)` 才算"面板自己的弹层"。**按归属判断，不用硬编码类名集合**，
  这样 studio-bar 里的 `#studio-source` 下拉不会被误豁免。
- `app.js` 的守卫按序豁免：`#node-settings` → `.node-action-btn/ctxEdit` →
  `#<被编辑节点id>`（header/body/端口/动作按钮）→ `#context-menu` 且 `canvas._contextNode === 被编辑id`
  → `#studio-overlay, #data-preview-panel`（从面板里打开的全屏层，点它们背后的东西不该有反应）
  → `CustomSelect.ownsPopup(e.target, panel)`；都不是才 `closeSettings()`。
- `workflow.js` `closeSettings()` 末尾加 `if (window.CustomSelect) CustomSelect.close();`（防孤儿弹层）。
- 保留不变：点空白画布仍关闭（`canvas.js:104` + app.js 两处，语义一致）；节点上的 S 按钮
  `editNode()` 仍是**切换**语义（第二次点关掉）；`X` 按钮删除节点（上一轮已加"删节点即关面板"）。

## 十四、数据来源：节点独立标识 + 多选合并（本轮）

1. `_nodeLabel` = `标题 · 类型`，而 `canvas.addNode` 给每个新节点的 `title` 就是**类型英文名**

- `labelFor()` 对 multiple 返回计数（模板来自 `sel.dataset.multiLabel`，措辞仍由应用/i18n 提供）；

## 十六、"要点两下才展开/回收"的根因与修法（本轮）
**症状**：数据来源、合并两个自定义下拉，以及工坊镜像菜单（引擎/数据/样式/导出），偶发需要点两次。

**根因有两个，都不在下拉本身的开关逻辑里**：

1. **自定义下拉用的是 `click` 事件**。click 只在"按下和抬起落在同一个元素上"才触发，
   而这中间 DOM 会动：`.studio-bar` 是 `flex-wrap` 的会重排、弹层入场动画会位移、
   标签宽度会变。于是那次 click 被静默吞掉，看起来就是"点了没反应"。
   → 改成 **`mousedown` 开关**（mousedown 一定会到），并把配套的 `click` 只用来 `stopPropagation()`。
   ★ 但 mousedown 开关会引入一个**新的自伤**：菜单在按键抬起前就已经显示在光标下方，
   若抬起落在弹层上，click 的目标会变成"按下与抬起目标的最近公共祖先"= `<body>`，
   于是这次 click 会被当成"点到别处"→ 弹层刚开就自己关掉。
   → 用 `inst.armed` 标记"这一次 click 是打开它的那次按压产生的"，在 click 守卫里吞掉它；
   `document` 上用**捕获阶段**的 mousedown 清掉 armed（捕获先于 target，所以 trigger 在 target
   阶段 set 才是对的），这样"按了却没产生 click"也不会一直挂着。
2. **`window.addEventListener('scroll', closeAny, true)` 太狠**。捕获阶段监听全文档滚动，
   于是"按下时浏览器把获得焦点的控件滚进可视区"这个动作本身就产生一次 scroll →
   刚打开的弹层被立刻关掉 → 第二次点击（已经无需滚动）才留得住。
   另外 `paintActive()` 里的 `scrollIntoView` 也会误伤多选清单。
   → 改成 **重新定位而不是关闭**（`reanchor()`：anchor 还在视口就 `place()` 跟随，滚出视口才 close）。
   → 顺带：trigger 的 mousedown 里 `preventDefault()`，从源头不让焦点/滚动介入。
3. 附带：`.cselect-menu` / `.cand-menu` 的入场动画从 `dropIn`(translateY(-4px))
   换成新的 `fadeIn`（只动 opacity）——translateY 会让弹层在动画的 120ms 内压住自己的 trigger 1px，
   第一次点击会落在弹层上。
4. 附带：`refreshSources()` 原本先 `innerHTML=''` 再逐条 append，中间存在 options=0 的窗口，
   此时点开会被 `open()` 的 `if (!sel.options.length) return` 直接吞掉。
   → 改成先建好全部 `<option>` 再一次性换入（`textContent=''` + append）。
5. **工坊镜像菜单是另一套机制**：host 只发 openMenu/closeMenu，iframe 里用 `btn.click()` 去"toogle"。
   两边各存一份"哪个菜单开着"的状态，只要有一次不同步，toggle 就会朝反方向走——
   于是"点一下关"变成"点一下又开了"。`reportMenuState()` 还有一处 `|| document.querySelector('.dropdown')`
   的兜底：把**没打开的残留元素**报成"打开着"，正好制造这种不同步。
   → `zenviz-bridge.js` 里 open/close 全部改写成 **幂等**："确保处于目标状态，验证，然后强制回报真实状态"
   （`reportMenuState(true)` 绕过去重）；`reportMenuState` 只看 `.dropdown.open`；
   `closeStudioMenu` 只点"确实开着"的那个 chip，收尾时清掉 `submenu-open` 与 `.menu-btn.active`。
   ★ 还有个隐蔽 bug：`new MutationObserver(reportMenuState)` 会把 **mutations 数组当 `force` 参数**传进去
   （truthy）→ 每次 body 变动都强制 postMessage。必须包一层 `function(){ reportMenuState() }`。

### 多选拼接改成"整表摆放"（去掉对角稀疏）

用户反馈多选节点合并后是"**对角放置**"：两张列名不同的表按列名并集 concat，A 的行只在 A 的列有值、
B 的行只在 B 的列有值，非空值正好落在矩阵对角线上。要求二选一：整表放到下方（追加行）或整表放到右侧（追加列）。

- **模型换成"粘贴到同一张表"**，绝不按值匹配，结果永远是实心矩形：
  - `rows`（放到下方）：列名集合完全一致 → 按名 `pd.concat(ignore_index=True)`；
    否则**按列位置**堆叠（表头沿用第一张表的列名，后续表更宽时把多余列名补到表头尾部），
    短行补 `None`。
  - `side`（放到右侧）：各表 `reset_index(drop=True)` 后 `pd.concat(axis=1)`，
    重名列用 `_merge_unique_names()` 加序号后缀（`freq` → `freq_2`），因为前端按列名绑定 series。
- 模式值从 `concat`/`join` 改为 `rows`/`side`（后端对 `side|columns|right` 判为横向，
  其余一律纵向；旧客户端传 `join` 会落到纵向）。index.html、`chartStudio._mergeMode`、
  `setMergeMode()`、i18n（`studio.merge.rows` / `studio.merge.side`，中文"放到下方（追加行）/放到右侧（追加列）"）
  全部同步，`studio.merge.concat|join` 两条词条删除。
- 进程内验证（viacopy 到 $TEMP 的脚本 + venv python）：列名不同纵向 → 5×2 实心、
  第二张表的值落在第一张表表头下（不再对角）；横向 → 3×4；列名相同纵向 → 干净堆叠；
  同名横向 → `word_2/freq_2` 去重。`py_compile` 与 `node --check` 均 exit=0。
- **再次踩坑**：同一文件的两处 Edit 并行提交，`_mergeMode: 'concat' → 'rows'` 那次被覆盖丢失，
  只剩 `setMergeMode()` 落地；grep 复核时发现并串行补回。**同文件必须串行改，改完必须 grep 复核。**

### 弹出层跟随锚点的重排（rAF 采样）

工坊 `.studio-bar` 是 flex 行且靠 `.studio-spacer` 右对齐，**新增控件会把已有控件整体往左挤**：
勾第二个节点时 `#studio-merge-field` 由 `hidden` 变可见，数据来源那块随左移，
但已展开的下拉弹层仍停在旧坐标（弹层是 `position:fixed`，只按 `place()` 时的 rect 定位）。
scroll/resize 都没发生，所以 `reanchor()` 一次都不会被调到。

- `custom-select.js` 新增 `followAnchor()` + `startFollow()`：**弹层打开期间每帧 rAF 采样锚点
  `getBoundingClientRect()`，left/top/width/height 任一变化就 `reanchor()`**。
  关闭后（两个 open 引用都为空）下一帧自动停止，不在后台常驻。
  `place()` 只写 fixed 弹层自身的样式，不会反过来扰动锚点布局，所以循环会收敛不会抖动。
- 调用点：`open()` 末尾、候选列表 `show()` 里 `openCand = inst` 之后。
- 另外在 option 列表的 MutationObserver 里补了 `place(menu, trigger)`：重建后列表可能更宽
  （新节点的标签），原来只 `build()` 不重新定位，宽度会停在旧值。

### 外部点击要能关掉工坊下拉：iframe 是跨文档的

用户反馈点外部区域下拉不消失。根因：**工坊柱条下方的工作台是 iframe**，
而 iframe 里的点击只会派发给内层 document，**永远不会冒泡到宿主 document**，
所以 `custom-select.js` 里 `document.addEventListener('click')` 那条 dismissal 规则
以及 `armed` 的清理 mousedown 全都收不到 → 弹层留在屏幕上。
（同一文档内的点击路径本来是对的，问题只在 iframe 区域。）

- `watchFrame(frame)` / `watchFrames()`：对页面上每个 iframe 取 `contentDocument`
  （同源才行，`try/catch` 兜住跨域），在**内层文档**上挂捕获阶段 `mousedown` → `closeAny()`，
  Esc 同样。iframe 重新加载会换掉内层 document，所以在 frame 元素上挂一次 `load`
  把 `__csWatched` 重置后重新挂。
- `watchFrames()` 在 `startFollow()`（即每次弹层打开）时调一次，避免常驻轮询。
- 兜底：`window.addEventListener('blur', …)` —— 拿不到内层文档（跨域）或事件被吞时，
  焦点离开页面就说明按到外面了。用 `preventDefault()` 挡住 trigger 的 mousedown，
  所以点 trigger 自身不会触发 blur。

### 多选清单：勾选行不再穿"hover 样式"

`.cselect-option.selected` 与 `:hover` 共用 `var(--hover)` 背景 + ink 边框，而多选清单的弹层
不关、点击后行一直保持 `.selected` → 看起来像 hover 卡住。修法（style.css）：

- `.cselect-option.multi.selected` 改为透明背景/无边框/无下划线，只留勾选框 + 深文字
  ——勾本身就是选中指示。
- 键盘光标 `.active` 在 multi 下不再铺行背景（勾选框描 ink 边），否则取消勾选后
  `.active:not(.selected)` 又会把 hover 背景留在鼠标不在的行上。
- 两条 hover 覆盖规则保证 `:hover` 仍胜出（`.multi.selected` 特异度 4 会压过 `:hover` 的 2，
  必须显式写 `.multi.selected:hover { background: var(--hover) }`，否则勾选行连 hover 都没了）。
- 单选模式的 `.selected` 保持原样（菜单选完即关，不存在"卡住"）。

### 工坊图例：多图例时自动换行 / 换列（均衡分配）

工坊的图例**不是 ECharts 自带的**，而是 `zenviz.html` 里自绘的 overlay 图例
（`.layout-legend` / `.layout-legend-item`，由 `renderOverlay()` 生成）。
原样式是 `flex-wrap: nowrap; width: max-content; overflow-x: auto` —— 横排永远一行、
放不下就横向滚动；竖排永远一列、往下溢出。

- 新增 `fitLegendLayout(legend, host)`（在 `renderOverlay()` 里 `host.appendChild(legend)` 之后调用）：
  - 量 `host.clientWidth/Height`（**布局 px，不用 getBoundingClientRect**，避免 preview 缩放时和 CSS 百分比混算）
    减去 `24 + --layout-pad-*`，得到与 CSS `max-width` 同一个盒子；再扣掉图例自身 padding/border。
  - 横排：按平均项宽算出每行容量 → `perLine`，再用 `lines = ceil(N/perLine); perLine = ceil(N/lines)`
    均分；因为 grid 的 `max-content` 列宽取"该列最宽项"，还要迭代把 `perLine` 递减到**每行真的放得下**。
  - 竖排：按可用高度算每列容量 → 列数 → `perLine = ceil(N/cols)`；列数再用最大项宽夹一次，避免超出宽度。
  - 只有**真的需要换行**（`perLine >= 2 && perLine < total`）才加 `.legend-grid` 并写
    `display:grid` + `grid-auto-flow` + `grid-template-columns/rows`，否则保持原来紧凑的一行/一列。
  - `.stream` 类型的图例是绝对定位到各 band 上的，直接跳过。
- CSS 只加了一条 `.layout-legend.legend-grid { display: grid; align-items: center; justify-items: start }`。
- `resize` 时 `resizeChart()` 不会重新 `renderOverlay()`，所以额外挂了一个 resize 监听，
  在 `requestAnimationFrame` 里重跑一次 `fitLegendLayout`。
- 用 `node + vm.Script` 抽取内联 `<script>` 做语法校验（HTML 没法直接 `node --check`）：

## AI 面板初始状态 bug（夜间补丁）

- 现象：provider=本地 Ollama 时打开 AI 菜单，OpenRouter 专属行（模型/免费模型/Key/测试连接）仍然显示。
- 根因：`LLMSettings`/`AppSettings` 是 app.js 顶层 `const`，**不会挂到 window**；menu.js 里 `if (window.LLMSettings)` 守卫恒 false，`applyToPanel()`（含 toggleOpenRouterRows）从未执行，面板保持 HTML 原始全显状态。切一次 provider 才会"自愈"。
- 修复：app.js 末尾显式 `window.LLMSettings = LLMSettings; window.AppSettings = AppSettings;`。
- 经验：跨文件用 `window.X` 做存在性守卫时，声明侧必须显式导出；顶层 const/let 不进 window。

## 候选区要点好几下才出现（夜间补丁）

- 现象：点击带联想候选区的输入框（input[list] → .cand-menu），弹层有时要点好几下才留住。
- 根因：`focus` 在 mousedown 时打开弹层，随后这次点击的 click 冒泡到 document 的外点关闭守卫；
  守卫只豁免了弹层内部和 `.cselect-trigger`，没有豁免"候选区所属输入框本身"，于是弹层被
  打开它的同一次点击关掉（视觉上是闪一下）。click 只在按下/抬起落同一元素时才触发，
  所以鼠标稍微一挪弹层反而留住——"时好时坏"的来源。
- 修复：custom-select.js 外点守卫补第三条例外：`openCand && (e.target === openCand.input || openCand.input.contains(e.target))` → return。
- 经验：mousedown/focus 开弹层 + click 关的模式，必须把"开启者自己"从外点守卫里豁免，select 和 input 两条路径都要。
