# Runtime-only dependency set for the Windows onedir and macOS .app builds.
#
# One file, selected by environment markers: Windows takes the Edge WebView2 host and the newer
# onnxruntime; macOS takes the Cocoa host and a universal2 onnxruntime. Keeping two near-identical
# lists made a version bump a two-place edit and let the Mac list drift.
#
# This is intentionally NOT requirements.txt: the dev/test tools (ruff, pylint, pytest)
# and the optional multi-gigabyte stacks (torch, transformers, sentence-transformers,
# pyarrow, mitmproxy) are absent. The app already degrades without the optional stack and
# prints the method that actually ran; see requirements-optional.txt and AGENTS.md.
#
# onnxruntime + tokenizers ARE here, and they are what makes that degradation unnecessary:
# they run the fine-tuned BERT checkpoints from an exported ONNX graph, so the packaged app
# answers `bert` nodes instead of falling back to snownlp/ml. Together they cost tens of MB
# against torch's gigabytes, and `tokenizers` reads the trainer's own `tokenizer.json` --
# which is why transformers itself stays out. See analyzers/sentiment.py:bert_runtime().
#
# ASCII ONLY. pip decodes a requirements file with `locale.getpreferredencoding()` unless the
# file carries a UTF-8 BOM, so a Chinese comment here is a `UnicodeDecodeError: 'gbk' codec
# can't decode byte ...` and the dependency install dies before downloading anything. Measured
# on this machine when such a comment was added: the build stopped at "Build environment".
#
# Versions are the ones this checkout was measured against. Keep them pinned so two
# builders produce the same folder and the same size.

Flask==3.1.0
# app.py imports HTTPException and ProxyFix from werkzeug directly; a direct import is a
# declared dependency even when Flask also pulls it in.
werkzeug==3.1.8
flask-cors==6.0.5
requests==2.34.2
urllib3==2.7.0
# The self-updater verifies a signed feed with Ed25519 (services/update.py imports it lazily).
# Without it a packaged build that configures CIXI_UPDATE_PUBKEY answers "this install is
# missing the signature component" and can never update. The safest configuration was the
# only one that broke. Declared here so the build venv (and PyInstaller) actually contains it.
cryptography==44.0.3
selenium==4.45.0
pandas==3.0.3
numpy==2.4.6
matplotlib==3.11.0
openpyxl==3.1.5
ollama==0.6.2
joblib==1.5.3
jieba==0.42.1
scipy==1.17.1
scikit-learn==1.9.0
snownlp==0.12.3
networkx==3.6.1
# Windows has the 1.31 cp311 wheel. macOS 1.19.2 is the last universal2 wheel for Python 3.11 that
# supports macOS 11+; newer releases publish an arm64-only macOS wheel and would strand the Intel
# DMG. Both load the same exported ONNX graphs.
onnxruntime==1.31.0; sys_platform == "win32"
onnxruntime==1.19.2; sys_platform == "darwin"
tokenizers==0.22.2
# Web of Science sells an "Excel" download that is legacy OLE2 .xls; pandas opens that
# only through xlrd (openpyxl reads .xlsx), so the packaged app needs it to accept a file
# the vendor itself offers. Measured on a real WoS Excel export.
xlrd==2.0.2
# jieba imports pkg_resources when it is present; keeping it explicit avoids a
# warning-only dependency on whatever a bare venv happens to include.
setuptools==78.1.0
# The IANA zone database: Windows has no system zoneinfo directory, and a slim Linux image usually
# does not either. Declared explicitly on both packaged platforms so a resolver change cannot make
# a schedule or a timestamp silently depend on the host.
tzdata==2026.2
# Pillow generates the macOS .icns and is a matplotlib dependency; the tool imports PIL directly.
Pillow==12.3.0
# The desktop window: Edge WebView2 on Windows, Cocoa/WebKit on macOS. pywebview talks to WebView2
# through its .NET wrapper, which pythonnet loads; the WebView2 runtime itself ships with Windows
# 10/11 and is NOT bundled here. pythonnet 3.0.x is pinned because its Python.Runtime.dll loads on
# the .NET Framework every supported Windows already has. The markers keep the Windows stack off a
# macOS install and the Cocoa stack off Windows.
pywebview==6.2.1; sys_platform == "win32" or sys_platform == "darwin"
pythonnet==3.0.5; sys_platform == "win32"
# The tray icon (desktop/tray.py). Windows only: the macOS build posts notifications through the
# PyObjC stack the window already pulls in and, by convention, has no status-bar item (the Dock icon
# is the affordance). pystray talks to Shell_NotifyIcon through ctypes and needs Pillow, which the
# build already carries for matplotlib.
pystray==0.19.5; sys_platform == "win32"
