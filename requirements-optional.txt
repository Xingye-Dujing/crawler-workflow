# Optional, per-feature dependencies — nothing here is needed for a crawl, a cleaning
# pass, a keyword list or a SnowNLP polarity column. The topic model's DEFAULT method is now
# `embedding`, so a plain (untouched) topic step DOES want sentence-transformers from this file —
# it refuses BY NAME when absent and never falls back; LDA remains the no-dependency opt-in you
# select with 主题方法=lda, and saved canvases that meant LDA are pinned to it explicitly.
#
# They live in their own file rather than in requirements.txt because of SIZE and because
# of how the code treats them. `torch` is a multi-gigabyte download, and `sentiment.py`
# imports both packages inside a guard that PROBES for them first — a machine without them
# gets a working project whose `bert` mode refuses and names the missing package, rather
# than a broken install or a silent fallback to a different model.
#
# So this file exists to keep one rule honest: every package the code imports is declared
# somewhere it can be found, instead of being discovered by reading the source.
#
# Install (CUDA build — replace cu121 with the wheel matching your driver, or drop the
# --extra-index-url entirely for the CPU build):
#
#     .venv/Scripts/pip.exe install -r requirements-optional.txt \
#         --extra-index-url https://download.pytorch.org/whl/cu121
#
# Used by: the Process node's 情感极性 (sentiment) operation, mode `bert`.
# The model itself is a separate download named in the node — see the README's bert note.

torch
transformers

# ── Topic modeling: embedding is now the DEFAULT method ───────────────────────────
# `sentence-transformers` (with torch/transformers) is imported by product code —
# `services/data_analysis.py::_embed_vectors` — and is what EVERY topic step (主题模型 / 分阶段 /
# 距离图 / 显著词) uses on its default path, so an untouched canvas wants it installed. The step
# refuses BY NAME when it is absent and NEVER falls back to LDA (that would put one model's topics
# in a column another method claimed); LDA stays the no-dependency alternative you pick explicitly.
# The ml_train/scripts/topic_bakeoff.py comparison that justified the switch scored sklearn LDA
# against embeddings + KMeans (and BERTopic) on the same NPMI coherence — with a real small Chinese
# encoder the embedding path won on both corpora. `bertopic`/`umap-learn`/`hdbscan` are used ONLY by
# that offline script, not by the app (BERTopic was judged heavier for no gain and was not adopted).
# None of these are CI-installed.
sentence-transformers
bertopic
umap-learn
hdbscan
