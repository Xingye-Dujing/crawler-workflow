# 已保存画布的说明

`data/workflows/` 是**有意纳入版本管理**的：一张画布是创作物而不是运行残渣。但它按 **数据集 id** 引用上传的文件，
所以一份检出的画布只有在**同一份 `data/` 旁边**才跑得起来——下面的数字都来自本机 `data/exports/刘学州最终`。

## 两张刘学州画布必须成对同步

`刘学州-情感演化分析.json`（六份博文导出）与 `刘学州-评论-情感演化分析.json`（六份评论导出）**结构必须完全一致，只有
按语料而变的「措辞层」可以不同**。必须一致的是：节点 id / 类型 / 操作 / 连线，以及所有**方法参数**（阈值、扫描、
`phase_edges` 五段边界、`stage_topic_counts`、桑基/显著词等）。允许不同的（核对脚本会把它们归一）：
1. 上传节点指向的数据集不同；
2. 评论语料没有 `正文`/`发布时间` 两列 → 清洗节点（node-6 `text_column`）读 `评论内容`、提取日期与划分阶段
   （node-11/12 `column`）读 `评论时间`；
3. 标题里的「发帖量」在评论画布应作「评论量」（node-14/17）；
4. 评论画布的 `filename` 前缀带「评论」（`刘学州-评论-…`），否则两张画布跑会互相覆盖 `data/exports/`；
5. `annotations` 里的事件峰值是**各语料自己测出来的**（帖文爆发峰 3439、评论爆发峰 4615…），照抄就是编数。

改完一张跑这段核对（应打印 True，标题/文件名/标注/坐标都按上面的口径归一掉了）：

```python
import json, io

def norm(p):
    w = json.load(io.open(p, encoding='utf-8'))
    for n in w['nodes']:
        if n['type'] == 'upload':
            n['params'] = {'u': 1}          # the datasets differ by design
        pr = n['params']
        # the raw text/time columns legitimately differ per corpus:
        # 正文↔评论内容 (node-6 clean), 发布时间↔评论时间 (node-11 extract_time, node-12 bin_time)
        if n['type'] == 'process' and pr.get('operation') == 'clean':
            pr['text_column'] = 'TEXT'
        if n['type'] == 'analysis' and pr.get('operation') in ('extract_time', 'bin_time'):
            pr['column'] = 'TIME'
        # per-corpus prose (titles, export filenames, event peaks) legitimately differs:
        n['title'] = 'T'
        for key in ('title', 'filename', 'annotations'):
            if key in pr:
                pr[key] = 'P'
        n.pop('x', None); n.pop('y', None)  # where a node sits on the canvas is not content
    w.get('settings', {}).pop('view', None)
    w['name'] = 'X'
    return json.dumps(w, sort_keys=True, ensure_ascii=False)

from pathlib import Path

a = Path('data/workflows/刘学州-情感演化分析.json')
b = Path('data/workflows/刘学州-评论-情感演化分析.json')
print(norm(a) == norm(b))
```

（节点坐标不算差异：画布上的摆位是各人自己的事。）

### 图15 桑基现在依赖模型（这是有意的取舍）

`主题跨阶段流向` 填了 `flow_label_col=主题概括`，上游也从 分阶段 LDA 改成了 **主题概括** 节点：

（原始编号仍在 `source_topic`/`target_topic` 两列里，可追溯）。代价是**模型没起时这张图一起失败**——
概括节点按名拒绝，流向节点就没数据。宁可少一张图，也不要一张节点名谁也读不懂的图。
换数据时若暂时不想起模型，把这条连线改回 `node-19` 并清空 `flow_label_col` 即可。

### 词表口径

所有文本统计（LDA 特征词、显著词、共词网络、关键词节点、词云）共用 `backend/analyzers/stopwords.py`
那一份中文停用词表。它保守收录：语法词进表，域内实词（网暴/警方/律师/生父/校园/私信/微博/网友/问题）一律保留，
用例把这双向都钉住了。觉得某个词被误杀或被漏杀，改那一处列表就行。
